# Trio v0.1.4 개발 백로그

> 2026-09-17 범위 갱신: 이 문서의 macOS 항목은 **non-MVP / future scope**이며 현재 MVP 지원이나 Release Gate 요구가 아닙니다. Linux 범위는 변경하지 않습니다. [현재 플랫폼 정책](operations/mvp-platform-scope.md)을 우선합니다.
> 이전 시점의 실행 결과와 gate 상태는 역사적 기록이며 현재 후보 판정은 [최신 Release Gate 보고서](release/2026-09-17-mvp-release-gate.md)를 따릅니다.

> **계획 문서**
>
> 이 백로그는 v0.1.3 공개 릴리스 직후의 안정성·상용 운영·제품 가치를 기준으로 정리한 제안입니다. 각 항목은 구현 전 문제 정의, 사용자 영향, 보안·법률 검토, 테스트 범위를 다시 확정해야 합니다.

## 릴리스 목표

v0.1.4의 1차 목표는 새 기능 수를 늘리는 것보다 **신뢰할 수 있는 설치·업데이트·저장 경험**을 만드는 것입니다. 자동 번역과 배치 처리 같은 확장 기능은 데이터 안전성과 배포 신뢰성 기준을 충족한 뒤 단계적으로 진행합니다.

이번 주에 바로 시작할 P0·P1 작업의 책임 경계, 일자별 순서, PR 분할, 외부 의존성 및 검증 기준은 [이번 주 실행 계획](exec-plans/v0.1.4-week-1.md)에서 관리합니다.

P0 작업 이후 이번 주에 남은 P1-01~04의 실제 Windows 실증·revision fixture·브랜딩 준비 계획은 [P1 이번 주 잔여 실행 계획](operations/p1-week-remainder.md)에서 관리합니다. P1-02의 scenario·test seam·완료 기준은 [revision journal 실행 계획](operations/p1-02-revision-plan.md)에, public release와 private update delivery의 분리 설계는 [업데이트 제공 아키텍처](operations/update-delivery-architecture.md)에 상세히 기록합니다.

## 권장 실행 순서

1. **P0-01 ~ P0-04:** 배포 신뢰성, 상용 운영 책임, 무결성 기준을 먼저 확정합니다.
2. **P1-01 ~ P1-03:** 프로젝트 데이터가 안전하게 저장·복구·충돌 처리되는 기반을 완성합니다.
3. **P1-04:** 설치 후 인지 품질을 정비합니다.
4. **P2-01 ~ P2-04:** 자동화와 배치 생산성 기능을 작은 사용자 승인 단위로 출시합니다.

## v0.1.4 릴리스 게이트

- 전체 테스트·타입 검사·프로덕션 빌드가 통과해야 합니다.
- Windows·macOS·Linux 패키징과 스모크 테스트가 통과해야 합니다.
- 업데이트 전환 시험 결과와 알려진 제한을 Release 노트에 기록해야 합니다.
- 새 외부 데이터 전송 또는 분석 기능이 있으면 개인정보 처리 방침과 사용자 고지를 함께 갱신해야 합니다.
- 신규 사용자 생성 콘텐츠·고객 리뷰·평점은 실제 데이터가 없는 한 예시로도 추가하지 않습니다.
