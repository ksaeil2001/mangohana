# Trio v0.1.4 Stable Go/No-Go 기록

> 2026-09-17 범위 갱신: 이 문서의 macOS 항목은 **non-MVP / future scope**이며 현재 MVP 지원이나 Release Gate 요구가 아닙니다. Linux 범위는 변경하지 않습니다. [현재 플랫폼 정책](../operations/mvp-platform-scope.md)을 우선합니다.
> 이전 시점의 실행 결과와 gate 상태는 역사적 기록이며 현재 후보 판정은 [최신 Release Gate 보고서](2026-09-17-mvp-release-gate.md)를 따릅니다.

> **현재 결정: No-Go** — 이 기록은 후보를 공개하거나 tag를 실행했다는 기록이
> 아니다. 각 gate의 외부 증거를 고정하고 별도 execution approval을 받은 뒤에만
> 다음 단계를 수행한다.

## 판정 규칙

상태는 `PASS | FAIL | BLOCKED | NOT RUN`을 사용한다. `PASS (code-side)`는
자동화된 코드·설정 검증만 통과했다는 뜻이며, 실장비·서명·공증·법률·GitHub
설정·공개 delivery 결과를 대신하지 않는다. 하나라도 필수 gate가 `BLOCKED` 또는
미완료이면 stable은 No-Go다.

## Code-side closeout evidence (not live release evidence)

### Gate 4 — private preview candidate and tracked-tree integrity

The transition workflow consumes the exact inputs `preview_candidate_run_id`,
`preview_evidence_sha256`, and `release_tooling_sha`. The private candidate is
fixed to `0.1.4-preview.1` / `v0.1.4-preview.1`, and the artifact name is
`trio-preview-transition-candidate-<sourceSha>-<runId>`. The run must be the
exact successful `workflow_dispatch` candidate run; its head SHA, the artifact
binding, private evidence `sourceSha`, `release_tooling_sha`, and
`TRIO_APPROVED_RELEASE_TOOLING_SHA` Environment value must agree. The actual
run ID, artifact ID, source SHA, evidence digest, and Environment value are
**미정** because no live candidate run was executed.

The candidate evidence schema is `trio.transition-candidate-evidence.v1` and
contains exactly the three updater records `latest.yml`,
`Trio-Setup-0.1.4-preview.1.exe`, and
`Trio-Setup-0.1.4-preview.1.exe.blockmap`, plus their exact SHA-256/SHA-512 and
size values. Its JSON and lowercase SHA-256 sidecar are private artifacts.
Transition evidence additionally records `source-integrity-before.json`,
`tooling-integrity-before.json`, `source-integrity-after.json`, and
`tooling-integrity-after.json`. Each uses `trio.git-source-integrity.v1` with
`clean: true`; before/after head and tracked-tree SHA values must match, and
`transition.json` records the same bindings. This code-side contract does not
claim a signed installer, hosted-runner execution, or WU-01~08 physical result.

### Gate 6 — exact anonymous metadata, bytes, rollback, and provenance order

The Task 5B2 metadata guard is now represented by the executable promotion
contract. The release request must use exactly:

| Field | Required bytes/value |
| --- | --- |
| tag | `v0.1.4` (`tag_name`) |
| title | `Trio v0.1.4` (`name`) |
| body | byte-for-byte UTF-8 contents of `candidate-assets/RELEASE_NOTES.md` |
| draft at creation | `true` |
| prerelease | `false` |
| generated notes | `false` |
| anonymous check | `draft=false`, same tag/title/body/prerelease and every exact candidate asset byte |

The workflow first verifies the draft with the scoped App token, publishes the
single draft, then fetches anonymous metadata/HTML and downloads every exact
asset. Only after those checks succeed is `PROMOTION_OK=1` set and
`trio-release-published` dispatched with the fixed provenance payload. The
same-step EXIT trap returns a failed public Release to `draft=true`; if that
rollback fails, the run reports manual intervention. GitHub/public repository,
credentials, and live anonymous bytes have not been observed.

### Gate 7 — approved concept 2 and package verifier

Concept 2 was explicitly approved on 2026-08-23. The approved 1254x1254 RGBA
source SHA-256 is
`08276cdab69d6d2da74d3b46134af812b4b1f130b8ac9eee2316c8c154473a08`.
`package.json` points Windows to `build/icon.ico`, macOS to `build/icon.icns`,
and Linux to `build/icons`; `scripts/verify-brand-icons.mjs` checks the fixed
source, dimensions, representations, regular files and no symlinks. Physical
display and installed-package QA remains BLOCKED.

`candidate SHA`, `tag SHA`, `release evidence digest`가 하나라도 다르면 promotion을
중단한다. GitHub App token은 별도 운영 설정 후 public delivery 저장소의 Contents
write만 가져야 하며, 이 문서만으로 token·repo·environment를 만들지 않는다.

## 실행 금지와 승인 경계

- 별도 실행 승인을 받기 전에는 tag, public Release, promotion, repository,
  GitHub App, environment, issue 또는 외부 메시지를 만들지 않는다.
- source repository와 public delivery repository를 섞지 않는다. source archive,
  `builder-debug.yml`, signing 원본 log, credential, PFX/PEM/key/token, 실제
  프로젝트 파일은 public asset allowlist에 들어갈 수 없다.
- macOS는 Developer ID hardened runtime·notarization·stapling, Windows는
  timestamped SHA-256 Authenticode가 모두 검증될 때만 stable 후보가 된다.
- Linux는 v0.1.4에서 updater disabled와 AppImage digest·SBOM·provenance를
  확인한 수동 다운로드만 허용한다.
- `appId=com.local.character-dialogue-translation-editor`와 `.ctp` schema,
  migration, `DialogueLine.userTranslation`과 render-ready authority는
  변경하지 않는다.

## Corrective release와 rollback

문제 수정은 더 높은 버전(예: `0.1.5`)의 새 candidate로만 진행하며 동일한
버전의 public asset이나 tag를 덮어쓰지 않는다. rollback owner는 **김세일**이다.
promotion 후 문제가 확인되면 공개 안내와 함께 higher version corrective release를
준비하고, 동일 버전의 byte를 조용히 교체하지 않는다. release evidence에는
rollback 시각·영향 asset·재현 절차·후속 version을 sanitized 값으로 남긴다.

## 최종 결정

현재는 **No-Go / v0.1.4 stable 배포 보류**다. 모든 Gate 1~9의 evidence가
독립적으로 기록되고 release owner가 별도 실행 승인을 한 뒤에만 이 표의 상태를
갱신한다.
