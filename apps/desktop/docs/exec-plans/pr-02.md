### 2-3. 서명

서명 신뢰 영역을 분리한다.

1. Authenticode:
   - Sidecar EXE/DLL/PYD, Electron EXE, Installer를 공개 신뢰 Code Signing 신원으로 서명한다.
   - SHA-256 digest와 RFC 3161 SHA-256 timestamp를 사용한다.
   - 개인키는 HSM, 하드웨어 토큰 또는 CA의 Cloud Signing에 보관한다.
   - 자체서명 인증서와 일반 GitHub Secret의 exportable PFX는 제품 Release에 사용하지 않는다.
2. Manifest Signing:
   - Sidecar와 Resource Manifest는 전용 RSA-3072/SHA-256 X.509 키로 Detached CMS를 만든다.
   - 공개 인증서 DER와 SHA-256 certificate thumbprint를 ASAR 신뢰 설정에 포함한다.
   - Runtime은 `current`와 `next` 최대 두 개의 thumbprint만 허용한다.
   - Manifest 원문은 UTF-8, BOM 없음, LF, 결정론적 key/array 순서를 사용한다.
   - 인증서 체인의 공개 신뢰 여부 대신 pinned thumbprint와 정확한 CMS 서명을 검증한다.

Publisher는 미정이다. 따라서 인증서 공급자, 비용, Subject, timestamp URL, HSM/Cloud API, CI 인증 방법은 승인된 값이 아니며 PR 2-B 시작 Gate에 남긴다.

## 4. 보안 경계

```text
Signed app.asar
├─ Resource Lock
├─ 허용 Publisher thumbprint(current/next)
└─ 검증 코드
        │
        ├─ 설치본 resources/pipeline
        │    ├─ sidecar-integrity-manifest.json
        │    ├─ sidecar-integrity-manifest.p7s
        │    └─ signed PE + payload
        │
        ├─ bundled Font Pack
        │    ├─ resource-manifest.json
        │    ├─ resource-manifest.p7s
        │    ├─ OTF
        │    └─ OFL
        │
        └─ userData/pipeline-resources/{resourceId}/{version}
             └─ 검증 완료 후 원자 승격된 Download Pack
```

신뢰 규칙:

1. Renderer가 경로, Lock, Manifest, thumbprint, 설치 상태를 결정하지 않는다.
2. Main만 ASAR의 Lock을 읽고 Resource Manager를 호출한다.
3. 검증 전 Archive와 해제 파일은 `.partial/{transactionId}` 밖으로 나가지 않는다.
4. Manifest/P7S 제외 파일을 빼고 Tree의 모든 파일이 Manifest에 정확히 한 번 있어야 한다.
5. Manifest에 없는 파일, Manifest에만 있는 파일, 중복 경로, 대소문자 충돌을 모두 거부한다.
6. Windows absolute path, drive prefix, UNC, `..`, ADS `:`, trailing dot/space, NUL, reserved device name을 거부한다.
7. symlink, junction, reparse point, encrypted ZIP, unsupported compression을 거부한다.
8. Archive entry 수, 개별 크기, 총 압축 해제 크기, 압축률, download byte 수, redirect 수, timeout에 상한을 둔다.
9. CMS는 정확한 Manifest bytes, SHA-256 계열 digest, 단일 허용 signer, pinned SHA-256 thumbprint를 만족해야 한다.
10. 기존 유효 Pack은 새 Pack 검증과 rename이 끝날 때까지 유지한다.
11. 검증 실패 시 기존 Pack과 Lock을 변경하지 않고 임시 경로만 정리한다.
12. Main이 검증한 절대 경로만 이후 PR의 Sidecar에 전달한다.

테이블 기반 실패 테스트에 최소한 다음을 포함한다.

- `../`, `..\`, absolute `/`, `C:\`, `C:relative`, UNC
- 빈 segment, `.`, `..`
- `/`와 `\` 혼용
- NUL과 control character
- ADS colon
- trailing dot/space
- `CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`
- exact duplicate와 case-insensitive duplicate
- Manifest 자기 제외 파일의 다른 대소문자

검증기는 허용된 `/` 구분 상대 경로 하나로만 정규화하고 원래 입력이 canonical form과 다르면 거부한다.

### Task A3 — CMS verifier

1. test publisher 공개 인증서와 정상 Detached CMS fixture를 추가한다.
2. 정확한 Manifest bytes만 성공하는 테스트를 작성한다.
3. payload 한 byte 변조, signature 변조, 허용되지 않은 signer, SHA-1, signer 0/2개를 거부한다.
4. 인증서 thumbprint는 SHA-256 uppercase hex로 정규화하되 입력 길이와 문자를 엄격히 검증한다.
5. 허용 signer는 `current`와 선택적 `next` 두 개를 넘지 못하게 한다.
6. 인증서 subject 문자열만 같고 thumbprint가 다른 서명을 거부한다.

### Task A4 — Sidecar Tree verifier

1. Manifest와 P7S 두 파일만 Tree hash 대상에서 제외한다.
2. 모든 다른 regular file의 relative path, byte size, SHA-256을 streaming 계산한다.
3. Tree 파일 수와 Manifest 파일 수가 정확히 같아야 한다.
4. 누락, 미등록, 중복, case collision, hash mismatch, size mismatch를 독립 테스트한다.
5. symlink와 reparse point를 파일로 따라가지 않고 거부한다.
6. Runtime 검증 entry point는 CMS 검증 성공 뒤에만 Tree를 읽는다.

### Task A5 — Resource Archive

1. yauzl의 lazy entry 방식으로 Archive 중앙 디렉터리를 검사한다.
2. entry path를 A2 validator에 통과시킨다.
3. directory와 regular file만 허용한다.
4. encrypted entry, symlink metadata, unsupported compression method를 거부한다.
5. entry count, individual uncompressed bytes, total uncompressed bytes, compression ratio 상한을 코드 상수와 테스트에 고정한다.
6. Manifest와 P7S를 먼저 메모리 제한 안에서 읽어 CMS/shape를 검증한 뒤 나머지 entry를 extract한다.
7. 추출 중 실제 bytes가 declared size를 초과하면 즉시 실패한다.

상한 값은 테스트와 사용자 영향 설명을 PR 본문에 기록하며, 모델 실측이 필요한 확대는 PR 6 승인 대상으로 남긴다.

### Task A6 — HTTPS Downloader

1. `https:`만 허용하고 URL credential, fragment를 거부한다.
2. redirect 횟수를 제한하고 매 redirect에서 다시 HTTPS 정책을 적용한다.
3. connect/response timeout과 최대 download byte를 적용한다.
4. `Content-Length` 초과와 streaming 실제 byte 초과를 모두 거부한다.
5. destination은 Resource Manager가 만든 `.partial/{transactionId}` 아래 파일 handle만 받는다.
6. 테스트는 network에 의존하지 않고 mocked fetch/response stream을 사용한다.

### Task A7 — 원자 설치

```text
Lock entry 선택
→ Archive/Manifest/P7S를 .partial/{transactionId}에 저장
→ CMS·schema·licenseFiles 검증
→ 제한된 extract
→ 모든 file hash/size와 미등록 파일 0 검증
→ compatiblePipelineVersions 검증
→ 최종 resourceId/version 경로가 없을 때 same-volume rename
→ 최종 경로 재검증
→ 성공 후 partial 정리
```

- 기존 같은 version이 유효하면 idempotent success로 처리한다.
- 기존 같은 version이 손상되면 자동 덮어쓰지 않고 `RESOURCE_CORRUPT`를 반환한다.
- 다른 기존 version은 삭제하지 않는다.
- 실패 주입 지점마다 기존 Pack이 유지되는 테스트를 둔다.
- cleanup은 transaction UUID가 확인된 자기 `.partial` 경로만 대상으로 한다.

### Task A8 — Resource Preflight

1. ASAR에서 주입받은 immutable Lock object만 입력으로 받는다.
2. 역할별 bundled/download, version, pipeline compatibility, manifest hash를 확인한다.
3. pack root가 `userData/pipeline-resources/{resourceId}/{version}` 또는 승인된 bundled root와 정확히 일치하는지 확인한다.
4. 성공한 절대 경로만 `ResourceBindingV1`에 필요한 내부 결과로 반환한다.
5. 오류를 `RESOURCE_MISSING`, `RESOURCE_CORRUPT`, `RESOURCE_INCOMPATIBLE`로 안정적으로 분류한다.
6. 실제 Font Load와 Model Open은 PR 2-B/PR 6의 platform probe가 성공해야 최종 success가 되도록 probe interface를 필수 주입한다.

PR 3 Protocol 타입이나 Sidecar spawn은 만들지 않는다.
