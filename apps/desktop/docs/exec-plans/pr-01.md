## 8. PR 1 실행 계약

### 목표

Container v1 외부 형식을 유지하면서 내부 Project v2, 전체 Persisted Snapshot, Pending Mutation Journal, 결정론적 Replay, Revision 충돌 판정, Main 소유 Project Session, project-only atomic replace, Save/Save As/Rekey, Secret v1 key upgrade, 단일 인스턴스를 구현한다.

이번 작업에서는 PR 1만 구현한다.

- PR 1-B 이후 코드를 작성하지 않는다.
- Pending Page Import Journal, 다중 Asset Save Transaction, Sidecar, Protocol, Manifest, Pipeline Worker, 자동 OCR/번역/식자를 구현하지 않는다.
- 미래 PR용 Stub은 PR 1 Gate 테스트에 필요한 내부 `MainProjectPatch` 적용 seam 외에는 만들지 않는다.

### 변경 금지 사항

- 외부 `.ctp` Container v1의 `format/schemaVersion/encrypted/kdf/salt/iv/authTag/payload` 형식을 바꾸지 않는다.
- 기존 v1 Project를 제자리 변경하지 않는다.
- 사용자 Pending Mutation을 Pipeline/Main Patch 저장에 섞지 않는다.
- 일부 사용자 필드만 복제한 부분 Snapshot을 만들지 않는다.
- Pipeline/Main Patch가 User/Manual DialogueLine을 삭제하게 하지 않는다.
- Renderer에 `security`, password, container key, artifact master key를 반환하지 않는다.
- Save As로 secret/plain 보호 모드를 바꾸지 않는다.
- `rekeyProject()` 외 경로에서 비밀번호를 교체하지 않는다.
- 기존 TXT, 이미지 선택, 이미지 표시, OCR, OpenAI/Gemini 수동 인페인팅 기능을 삭제하거나 의미를 바꾸지 않는다.
- PR 1-B의 Prepared/Pending 분리, content-addressed image asset, 다중 Asset Journal을 선행 구현하지 않는다.
- Sidecar·Electron Fuse·서명·Resource Pack·NDJSON·Manifest 파일을 만들지 않는다.
- 패키지 추가, lock 파일 변경, 배포 설정 변경을 하지 않는다.

### 구현 계약

1. `StoredProjectFileV1`은 외부 wrapper로 유지하고 payload의 `schemaVersion`만 1 또는 2로 판별한다.
2. v1 load는 새 v2 객체를 생성하며 모든 legacy DialogueLine에 `origin: { kind: "manual" }`을 부여하고 빈 `processing`을 추가한다.
3. Secret v1 open은 artifact key upgrade 필요 상태로 Session을 만들며, key가 project-only atomic replace로 영속화되기 전 Pipeline 시작 가능 상태를 만들지 않는다.
4. Session은 `persistedProjectSnapshot`, `liveProject`, `pendingUserMutations`, `revision`, `persistedRevision`, `revisionJournal`, `dirty`, 보호 키 상태를 Main에서만 보유한다.
5. 사용자 변경은 `projectSessionId + baseRevision + ProjectMutation`만 받는다.
6. Main이 ID, order, default, changed path를 정규화한 뒤 Journal에 넣고 persisted snapshot부터 전체 Journal을 재생한다.
7. stale revision은 revision journal의 경로가 겹치지 않을 때만 최신 revision에 적용한다. 겹치거나 journal 범위를 벗어나면 최신 DTO를 포함한 `REVISION_CONFLICT`를 반환한다.
8. PR 1 테스트용 Main patch seam은 persisted snapshot clone에만 적용하고 디스크 저장 성공 후 Pending Journal을 다시 재생한다. 외부 Pipeline IPC나 가짜 Worker는 만들지 않는다.
9. Replay 실패 시 저장된 Main patch는 유지하고 Session을 `needs_recovery`로 바꾸며 Pending Mutation을 임의 삭제하지 않는다.
10. 사용자 Save는 Pending Mutation을 Candidate에 전부 적용하고 성공 후에만 Journal을 비운다.
11. project-only replace는 candidate 작성, 재열기 검증, backup 이동, 최종 rename, 최종 재검증, 성공 후 backup 삭제 순서를 지킨다.
12. 실패 시 기존 유효 `.ctp`를 보존하거나 `.bak`에서 복원한다. 추측으로 파일을 삭제하지 않는다.
13. Save As는 현재 Session의 보호 모드와 key를 유지한다. Rekey는 Container key만 교체하고 artifact master key를 유지한다.
14. Session 종료 시 password/key Buffer와 임시 token을 정리한다.
15. `app.requestSingleInstanceLock()` 실패 인스턴스는 창을 만들지 않고 종료한다. `second-instance`는 기존 창 restore/focus만 수행한다.
16. 기존 이미지 import와 수동 인페인팅은 PR 1-B/4-B 전까지 기존 Provider·파일 동작을 유지한다. PR 1 Session 전환에 필요한 최소 adapter만 허용한다.
