# Workspace 재설계 진단

## 사용자 캡처에서 확인한 실패

| 증상 | 근본 원인 | 재설계 원칙 |
|---|---|---|
| 상단에 기능과 상태가 겹치고 읽기 어려움 | 파일·페이지·업데이트·환경·테마·설정 제어가 하나의 도구 줄에 병렬 배치됨 | 항상 보이는 상단에는 프로젝트명·저장·핵심 페이지 이동만 남기고, 환경·업데이트·테마·내보내기는 설정 또는 보조 메뉴로 이동 |
| 만화 이미지가 중앙에서 매우 작음 | Canvas는 넓지만 페이지 이미지의 읽기 흐름을 우선하는 별도 보기와 화면 상태가 분리되어 있음 | 페이지를 처음 열면 Fit 보기를 명확하게 적용하고, 필요 시 Width Fit을 우선 행동으로 제공 |
| Inspector가 이미지 작업, 환경 경고, 현재 작업, 문맥을 세로로 모두 쌓음 | 선택된 대사와 무관한 상태 패널까지 항상 같은 열에 렌더링됨 | 대사가 선택되지 않았을 때는 얇은 작업 안내만 표시하고, 선택됐을 때만 번역 편집 Inspector를 열어 세부 정보는 접이식 처리 |
| 하단 검수 영역이 Canvas를 침범하고 내용이 잘림 | 결과 drawer가 열린 채 페이지를 차지하며 내부 내용의 높이와 footer grid가 충돌 | 기본은 34px 단일 행으로 접고, 사용자가 열 때만 제한된 높이의 drawer를 사용. 한 번에 한 종류의 검수 정보만 표시 |
| 오류와 업데이트 안내가 작업 화면 위를 가림 | 상태 알림이 상단 도구와 분리되지 않은 floating surface로 노출됨 | 실패 알림은 우측 상단의 작고 닫을 수 있는 toast로 축소하고, 해결 행동은 Settings/환경 준비 화면으로 연결 |

## 실제 구현 목표

1. **Canvas 우선:** 화면 가로·세로 여유의 대부분을 만화 이미지에 배정한다.
2. **선택 기반 Inspector:** 선택한 말풍선이 없으면 편집 패널이 기본적으로 접힌다.
3. **한 줄짜리 검수 Drawer:** 하단은 상태 요약만 보이며, 상세는 사용자가 명시적으로 연다.
4. **단순한 상단 Command Bar:** 핵심 파일 행동과 페이지 이동만 노출한다.
5. **Electron 42 호환:** Renderer는 표준 CSS·React 상태만 사용하고, Electron 42.2.0 lockfile을 유지한다.

## 확정된 화면 구조

| 영역 | 기본 상태 | 사용자가 여는 경우 | 보존 기능 |
|---|---|---|---|
| 상단 Command Bar | 프로젝트명, 저장 상태, 새로 만들기·열기·저장, 이전/다음 페이지 | 설정 메뉴 | 다른 이름 저장, TXT 내보내기, 테마, 환경 준비, 업데이트 |
| 좌측 페이지 Rail | 열린 상태, 페이지·문맥·설정 탐색 | 토글로 접기 | 페이지 이동, 이미지 추가, 등장인물·용어 |
| 중앙 Canvas | 화면의 주 영역, Fit 보기 | Width Fit·확대·오버레이·이미지 결과 선택 | OCR, 결과 비교, 인페인팅, 이미지 레이어 |
| 우측 Inspector | 대사 미선택 시 접힘 | 말풍선 선택 또는 Inspector 토글 | 원문·번역·화자 편집, AI 제안, 상태 확인 |
| 하단 Review Drawer | 34px 요약 행으로 접힘 | 사용자가 직접 열기 | 대사 목록, OCR 이슈, 오류, 결과 확인 |

이 구조는 사용자가 만화 페이지를 볼 때 보조 패널이 캔버스를 침범하지 않도록 하고, 텍스트를 편집할 때에만 Inspector를 적극적으로 노출한다.

## 시각 검토 메모

개발 서버의 새 프로젝트 시작 화면에서 다크 톤과 간결한 정보 계층은 정상적으로 로드되었다. 다만 브라우저 검토 환경에는 사용자의 실제 저장 프로젝트와 만화 이미지가 없으므로, Workspace의 최종 검토 기준은 사용자가 제공한 2048×1160 캡처의 문제점으로 삼았다. 구현에서는 해당 해상도에서 Canvas 우선 상태일 때 Inspector와 Review Drawer가 화면 폭·높이를 차지하지 않도록 CSS grid를 재구성했다.
