| ID | 결정 또는 입력 | 현재 상태 | 필요한 책임자 | 사용자에게 필요한 응답 | 차단하는 작업 |
| --- | --- | --- | --- | --- | --- |
| EXT-01 | Windows 코드 서명 방식 | **결정됨 — 클라우드 서명 우선, credential 없음** | 개인 개발자 김세일 | 공급자·비용·계정·secret 보관 체계 확정 | P0-01 stable Windows 서명 |

## 4. 이번 주 요청 패킷

### A. 사용자가 메시지로 확정할 수 있는 비밀이 아닌 정보

아래 항목은 비밀값이 아니므로 이 대화에서 알려줄 수 있다. 아직 정해지지 않았다면 “미정”으로 답해도 된다.

| 응답 항목 | 예시 형식 |
| --- | --- |
| Windows 서명 방식 | `클라우드 서명 검토 중` 또는 `PFX 인증서 사용` |
| Apple Developer 준비 상태 | `계정 있음 / Team ID 확인 중` 또는 `미보유` |
| stable 배포 정책 | `서명 없으면 stable 태그 차단` 또는 `preview만 허용` |
| 운영 주체·관할 | `법인명 / 국가 또는 지역` 또는 `미정` |
| 연락 채널 | 개인정보 문의 이메일, 일반 지원 이메일, 보안 신고 채널 또는 `미정` |
| 지원 수준 | 커뮤니티 지원, 영업일 기준 응답 목표, 유료 SLA 여부 |
| 브랜드 | 아이콘 원본 보유 여부, 제품 표기명, Linux category 후보 |
| Windows QA | 검증 가능한 Windows 10/11 장비 또는 VM 보유 여부 |

### B. 절대로 대화나 Git에 보내면 안 되는 정보

다음 정보는 채팅·README·Issue·커밋·릴리스 노트에 보내지 않는다. 확정 후에는 GitHub Actions Secrets 또는 조직의 비밀 관리 체계에 직접 설정한다.

| 금지 정보 | 안전한 보관 위치 |
| --- | --- |
| PFX 파일, private key, 인증서 비밀번호 | 승인된 secret store 또는 GitHub Actions Secrets |
| Apple 앱 전용 비밀번호, API private key, notarization token | 승인된 secret store 또는 GitHub Actions Secrets |
| 실제 사용자 API 키·원고·개인정보 | 사용자 소유 환경 또는 승인된 보안 저장소 |

## 5. Day 1 종료 판정

Day 1은 기준선 명령이 모두 통과했고, EXT-01부터 EXT-09가 각각 **확정**, **담당자 배정**, 또는 **차단됨** 중 하나로 상태가 기록되면 종료한다. 외부 입력이 없더라도 다음 개발을 멈추지는 않는다. 다만 서명되지 않은 stable Release를 게시하거나, 법률 초안을 최종 정책처럼 표시하거나, 승인되지 않은 브랜드 자산을 패키지에 포함해서는 안 된다.

## 6. 확정된 배포 정책

1. Windows stable Release는 유효한 코드 서명 credential과 서명 검증이 없으면 생성하거나 게시하지 않는다.
2. 서명되지 않은 빌드는 stable 채널에 올리지 않고 preview/dev 채널에서만 허용한다.
3. Windows는 v0.1.4의 실제 업데이트 전환과 설치·제거·파일 잠금·single-instance·저장·복구 QA의 우선 플랫폼이다.
4. macOS 정식 서명·공증·자동 업데이트와 Linux 업데이트 QA는 Apple 계정 준비와 후속 QA 계획이 확정될 때까지 stable 범위에서 제외한다.
5. 개인정보·일반 지원·보안 신고 연락처는 미정 상태를 유지한다. 임의 연락처를 문서나 Release에 추가하지 않으며, 확정 전에는 유료 판매·조직 배포 blocker로 유지한다.

구체적인 workflow gate와 Windows 전환 QA 절차는 [Release Signing Gate](release-signing.md) 및 [Windows 업데이트 전환 QA 체크리스트](windows-update-transition-qa.md)에서 관리한다.
