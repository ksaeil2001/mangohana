# Image-First Project Start Design

## 목적

애플리케이션의 첫 행동을 TXT 불러오기에서 이미지 불러오기로 전환한다. 사용자는 페이지 이미지를 먼저 선택하고 프로젝트 저장 위치를 정한 뒤 즉시 이미지 중심 OCR 작업 화면으로 진입한다.

현재 `새 프로젝트`는 빈 상태를 다시 초기화할 뿐 화면에 보이는 변화를 만들지 않는다. 또한 빈 작업 공간이 대사 수만으로 결정되어, 이미지가 있어도 대사가 없으면 시작 화면으로 분류될 수 있다. 이번 변경은 이 두 문제를 함께 해결한다.

## 범위

- 시작 화면의 주요 CTA를 `이미지 불러오기`로 변경한다.
- `새 프로젝트`와 시작 화면의 주요 CTA가 동일한 이미지 프로젝트 생성 흐름을 실행하게 한다.
- 이미지 선택 후 프로젝트 저장 위치를 선택하고, 저장된 프로젝트에 이미지를 등록한다.
- 이미지가 하나 이상 있으면 대사가 없어도 작업 화면을 표시한다.
- 처리 진행, 취소, 성공 및 실패 상태를 화면에 보이게 표시한다.
- TXT 불러오기는 보조 시작 방법으로 유지한다.
- 기존 프로젝트 열기, 저장, 내보내기, OCR, 번역 검토 및 인페인팅 동작은 유지한다.

다음 항목은 범위에 포함하지 않는다.

- 프로젝트 파일 형식 변경
- 신규 IPC 계약 추가
- 임시 프로젝트 폴더 도입
- 시크릿 프로젝트의 이미지 지원
- OCR 또는 인페인팅 제공자 변경
- 패키지 추가 및 대규모 리팩터링

## 선택한 접근 방식

기존 renderer API를 조합하는 전용 이미지 프로젝트 시작 흐름을 사용한다.

1. 이미지 파일을 선택한다.
2. 프로젝트 저장 위치를 선택한다.
3. 빈 프로젝트 파일을 저장한다.
4. 선택한 이미지를 프로젝트 자산 폴더로 복사한다.
5. 성공한 이미지 메타데이터를 프로젝트에 반영한다.
6. 완성된 프로젝트를 다시 저장한다.
7. 첫 번째 이미지가 표시된 작업 화면으로 이동한다.

이 접근은 기존 `choosePageImageFiles`, `chooseSaveFile`, `saveProject`, `importPageImages` 계약과 프로젝트 자산 구조를 재사용한다. 전체 순서를 `App.tsx`에 직접 쌓지 않고, 의존성을 주입받는 전용 흐름 모듈로 분리한다. 해당 모듈은 UI 상태를 직접 변경하지 않고 판별 가능한 결과를 반환하며, `App.tsx`가 그 결과를 화면 상태에 반영한다.

## 사용자 흐름

### 최초 시작

```text
시작 화면
→ 이미지 불러오기
→ 이미지 파일 선택
→ 프로젝트 저장 위치 선택
→ 프로젝트 생성 및 이미지 복사
→ 첫 번째 페이지 이미지 표시
→ 말풍선 OCR 강조
```

### 작업 중 새 프로젝트

저장하지 않은 변경이 있으면 기존 확인 대화상자를 먼저 표시한다. 사용자가 변경 폐기를 거부하면 아무 작업도 하지 않는다. 변경 폐기를 승인하더라도 이미지 선택과 저장 위치 선택이 모두 완료되고 최초 프로젝트 저장이 성공하기 전까지 현재 작업 상태를 교체하지 않는다.

### TXT로 시작

시작 화면의 `TXT로 시작` 보조 버튼은 기존 TXT 파일 선택 흐름을 실행한다. TXT를 성공적으로 불러오면 기존과 동일하게 번역 검토 작업 화면으로 진입한다.

## 시작 화면 설계

시작 화면은 하나의 주요 행동과 두 개의 보조 행동만 제공한다.

- 주요 CTA: `이미지 불러오기`
- 보조 행동: `기존 프로젝트 열기`
- 보조 행동: `TXT로 시작`

기존 `빈 프로젝트 저장` 버튼은 제거한다. `새 프로젝트`라는 별도 보조 버튼을 시작 화면에 중복 배치하지 않는다. 작업 화면의 상단 `새 프로젝트` 버튼은 이미지 프로젝트 생성 흐름을 실행한다.

기본 문구는 다음 의미를 전달한다.

```text
이미지로 번역 프로젝트 시작
페이지 이미지를 선택하면 프로젝트 저장 위치를 정한 뒤 OCR 작업 화면으로 이동합니다.
```

`Ctrl+Enter`는 시작 화면에서 `이미지 불러오기`를 실행한다. 이미지가 등록된 후에는 기존 주요 행동 결정 규칙에 따라 `말풍선 OCR`을 실행한다.

## 상태 모델

빈 작업 공간은 대사와 이미지가 모두 없는 상태로 정의한다.

```ts
isEmptyWorkspace = dialogueLines.length === 0 && pageImages.length === 0;
```

`getWorkspacePresentation`은 `lineCount`와 함께 `imageCount`를 입력받는다.

| 대사 | 이미지 | 표시 화면 |
| --- | --- | --- |
| 0개 | 0개 | 시작 화면 |
| 1개 이상 | 0개 | 번역 작업 화면 |
| 0개 | 1개 이상 | 이미지/OCR 작업 화면 |
| 1개 이상 | 1개 이상 | 이미지 중심 작업 화면 |

저장된 빈 프로젝트도 시작 화면으로 표시한다. 이미지가 있는 프로젝트는 OCR 결과가 아직 없어도 작업 화면과 페이지 제어를 유지한다.

## 이미지 프로젝트 생성 모듈

전용 모듈은 다음 의존성을 입력받는다.

- 이미지 선택 함수
- 저장 경로 선택 함수
- 프로젝트 저장 함수
- 이미지 가져오기 함수
- 새 빈 프로젝트 생성 함수 또는 프로젝트 값

반환 결과는 최소한 다음 상태를 구분한다.

- `success`: 프로젝트 경로, 완성 프로젝트, 성공 이미지 수
- `partial`: 프로젝트 경로, 성공 이미지, 실패 정보
- `canceled-image-selection`
- `canceled-save-selection`
- `save-failed`
- `import-failed`

예외 메시지와 원본 파일 경로를 UI에 과도하게 노출하지 않는다. 실패 결과에는 사용자에게 보여줄 안전한 요약과 실패 개수를 포함한다.

## 데이터 일관성

- 이미지 선택을 취소하면 저장 위치 대화상자를 열지 않는다.
- 저장 위치 선택을 취소하면 프로젝트 파일과 자산을 생성하지 않는다.
- 최초 빈 프로젝트 저장에 실패하면 이미지 복사를 시작하지 않는다.
- 이미지 가져오기가 일부 성공하면 성공한 이미지만 프로젝트에 반영하고 다시 저장한다.
- 이미지가 전부 실패하면 저장된 빈 프로젝트는 유지하되 시작 화면에 머물고 재시도 안내를 표시한다.
- 최종 프로젝트 저장에 실패하면 가져온 자산을 임의로 삭제하지 않는다. 프로젝트가 복구 가능한 상태임을 알리고 다시 저장할 수 있게 한다.
- 여러 이미지는 선택 순서대로 1페이지부터 연결한다.

## 진행 상태와 중복 실행 방지

이미지 프로젝트 생성 중에는 동일 흐름을 다시 시작할 수 없게 한다. 주요 CTA에 `aria-busy`와 비활성 상태를 적용한다.

화면에 보이는 상태 영역은 다음 상태를 표현한다.

- `이미지 선택 중`
- `프로젝트 저장 위치 선택 중`
- `프로젝트 만드는 중`
- `이미지 불러오는 중`
- `이미지 N개를 불러왔습니다`
- `N개 중 M개를 불러오지 못했습니다`
- 저장 또는 이미지 가져오기 실패와 재시도 안내

접근성용 live region은 유지하되 일반 사용자에게도 같은 결과가 보이게 한다.

## 컴포넌트 책임

### `WorkspaceStartPanel.tsx`

- 이미지 불러오기를 유일한 주요 CTA로 표시한다.
- 기존 프로젝트 열기와 TXT로 시작을 보조 행동으로 표시한다.
- 진행 상태와 가시적인 결과 메시지를 표시한다.
- 파일 선택과 저장 로직은 소유하지 않는다.

### `workspacePresentation.ts`

- 대사 수와 이미지 수를 이용해 빈 작업 공간을 계산한다.
- 렌더링 조건만 반환하고 파일 작업은 수행하지 않는다.

### 이미지 프로젝트 시작 흐름 모듈

- 기존 renderer API 호출 순서를 조율한다.
- 취소, 부분 성공 및 실패를 판별 가능한 결과로 반환한다.
- React 상태나 DOM에 의존하지 않는다.

### `App.tsx`

- 미저장 변경 확인을 수행한다.
- 흐름 모듈을 실행하고 진행 상태를 갱신한다.
- 성공 결과를 프로젝트, 경로, 현재 페이지, dirty 상태에 반영한다.
- 성공 후 첫 페이지와 이미지 작업 모드를 선택한다.

## 오류 및 취소 처리

- 이미지 선택 취소: 현재 프로젝트 유지, `이미지 불러오기를 취소했습니다.` 표시
- 저장 위치 선택 취소: 현재 프로젝트 유지, `프로젝트 만들기를 취소했습니다.` 표시
- 최초 저장 실패: 현재 프로젝트 유지, 오류 요약과 재시도 제공
- 전체 이미지 실패: 새 빈 프로젝트 경로는 유지, 시작 화면에서 이미지 불러오기 재시도 가능
- 일부 이미지 실패: 성공한 이미지가 있는 작업 화면으로 이동하고 실패 개수를 표시
- 최종 저장 실패: 가져온 프로젝트 상태를 dirty로 유지하고 저장 재시도 안내

## 테스트 전략

### 단위 테스트

- 대사와 이미지가 모두 0개일 때만 빈 작업 공간이다.
- 이미지만 있는 프로젝트는 작업 화면 표시 조건을 반환한다.
- 이미지 선택 취소 시 후속 API를 호출하지 않는다.
- 저장 위치 선택 취소 시 저장 및 이미지 가져오기를 호출하지 않는다.
- 최초 저장 실패 시 이미지 가져오기를 호출하지 않는다.
- 성공 시 API 호출 순서와 페이지 매핑이 올바르다.
- 일부 성공 및 전체 실패 결과가 구분된다.

### renderer 통합 테스트

- 시작 화면의 주요 CTA가 이미지 불러오기다.
- `새 프로젝트`와 시작 CTA가 동일한 흐름을 실행한다.
- `Ctrl+Enter`가 시작 화면의 이미지 불러오기를 실행한다.
- 성공 후 첫 이미지와 이미지/OCR 작업 화면이 표시된다.
- 이미지가 있고 대사가 없어도 시작 화면으로 돌아가지 않는다.
- 처리 중 중복 클릭이 차단된다.
- 취소 시 기존 프로젝트가 그대로 유지된다.
- 가시적인 진행 및 오류 메시지가 표시된다.
- TXT로 시작과 기존 프로젝트 열기가 계속 작동한다.

### 회귀 검증

- 전체 renderer 및 main 테스트
- IPC smoke 테스트
- storage smoke 테스트
- 타입 검사
- 프로덕션 빌드
- 실제 Electron에서 이미지 선택, 저장 위치 선택, 이미지 표시, OCR 주요 CTA 전환 수동 확인

## 완료 기준

- 사용자는 첫 화면에서 설명 없이 이미지 불러오기를 주요 시작 행동으로 인식할 수 있다.
- `새 프로젝트`를 누르면 이미지 선택 흐름이 시작되어 즉각적인 반응이 보인다.
- 이미지 선택과 저장 위치 선택 후 첫 이미지가 작업 화면에 표시된다.
- 대사가 0개여도 이미지가 있으면 작업 화면이 유지된다.
- 취소 또는 실패가 기존 작업을 예기치 않게 지우지 않는다.
- TXT 기반 작업과 기존 저장 형식이 회귀하지 않는다.
