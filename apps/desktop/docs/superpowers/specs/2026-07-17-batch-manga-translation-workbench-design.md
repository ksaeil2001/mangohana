# 다중 페이지 만화 번역 워크벤치 설계

## 목표

Windows 데스크톱 앱을 단일 페이지 OCR 편집기처럼 보이는 화면에서, 만화 한 작품의 여러 페이지를 한 번에 준비하고 번역하는 이미지 중심 워크벤치로 재구성한다.

사용자는 다음 두 방식 중 하나를 선택한다.

- 빠른 번역: 모든 페이지를 자동으로 OCR, 번역, 합성하고 실패한 페이지만 마지막에 검토한다.
- 정밀 번역: 작품 전체 텍스트와 장면을 먼저 분석하고 등장인물·화자를 연결한 뒤 전체 문맥으로 번역·합성한다.

어떤 단계에서도 페이지 이미지가 주 작업 대상이다. 이미지는 기본적으로 잘리지 않은 전체 페이지로 표시하고, 모든 보조 패널과 텍스트 레이어는 접거나 숨길 수 있어야 한다.

## 현재 상태와 문제

현재 파일 선택 IPC는 이미 여러 이미지 선택을 지원하며 선택 순서대로 페이지 번호를 부여한다. 그러나 시작 화면의 `이미지 불러오기` CTA와 페이지 단위 작업 문구가 단일 이미지 도구처럼 보여 이 기능이 드러나지 않는다.

현재 주요 문제는 다음과 같다.

- 작품 전체를 준비하는 단계 없이 파일 선택과 저장 대화상자가 연속으로 나타난다.
- 빠른 번역과 정밀 번역의 목적과 처리 방식이 구분되지 않는다.
- `작업·페이지·문맥·설정` 레일이 현재 단계와 무관하게 보이며 화면을 복잡하게 만든다.
- 페이지 목록, OCR 결과, 상세 작업 패널이 이미지 표시 공간과 경쟁한다.
- OCR 검토 모달이 이미지와 작업 문맥을 가린다.
- 전체 작품의 진행률, 실패 페이지, 중단 후 재개 상태를 표현할 모델이 없다.

## 범위 분리

이 기능은 하나의 거대한 구현으로 진행하지 않는다. 다음 하위 프로젝트를 순서대로 설계·구현한다.

1. 프로젝트 홈과 다중 이미지 준비 화면
2. 접이식 이미지 중심 작업 공간
3. 빠른 번역 작업 큐
4. 정밀 번역 분석·대본·번역 파이프라인
5. 번역문 이미지 합성과 결과 내보내기
6. 저장 형식 확장, 중단 후 재개, 실패 복구

각 하위 프로젝트는 독립된 구현 계획과 검토 단위를 가진다. UI 셸을 먼저 완성한 뒤 실제 자동 번역 파이프라인을 연결한다.

## 범위 밖

- 스마트폰 전용 UI
- 협업, 사용자 계정, 클라우드 동기화
- 원본 이미지 덮어쓰기
- AI가 생성한 결과를 검토 불가능한 단일 합성 이미지로만 저장
- 페이지 성공 때마다 빠른 번역을 강제로 멈추는 흐름
- 기존 프로젝트를 새 형식으로 일괄 변환하는 별도 마이그레이션 도구

## 고정 설계 원칙

구현 중 다음 원칙을 임의로 변경하지 않는다.

1. 기본 화면에서 현재 페이지 전체가 잘리지 않고 보여야 한다.
2. 페이지 목록, 작업 패널, 하단 결과 패널은 각각 접을 수 있어야 한다.
3. 집중 모드에서 이미지 외의 작업 UI를 한 번에 숨길 수 있어야 한다.
4. 패널을 접고 펼쳐도 이미지 비율이 유지돼야 한다.
5. 빠른 번역은 성공 페이지마다 멈추지 않는다.
6. 한 페이지 실패가 다른 페이지 처리를 중단하지 않는다.
7. 정밀 번역은 작품 전체 OCR과 화자 연결 후 최종 번역을 시작한다.
8. 원본 이미지를 덮어쓰지 않는다.
9. 검토 UI가 전체 이미지를 가리는 중앙 모달이 되어서는 안 된다.
10. 접힌 오류와 검토 필요 항목도 개수 배지로 존재를 알려야 한다.
11. 프로젝트 홈에서 TXT, OCR, 문맥, 설정이 서로 주 행동으로 경쟁하지 않는다.
12. 승인된 화면 구조를 구현 편의 때문에 다른 구조로 바꾸지 않는다.

## 정보 구조

제품은 다음 5개 핵심 화면으로 구성한다.

1. 프로젝트 홈
2. 프로젝트 준비
3. 번역 작업
4. 문제·결과 검토
5. 완료 및 내보내기

상태 전환은 다음과 같다.

```text
프로젝트 홈
  -> 새 번역 프로젝트
  -> 이미지 준비 및 모드 선택
  -> 프로젝트 저장 위치 선택
  -> 빠른 번역 또는 정밀 번역 작업
  -> 문제 항목 검토
  -> 완료 및 내보내기
```

기존 프로젝트 열기는 저장된 작업 단계에서 직접 재개한다.

## 화면 1: 프로젝트 홈

앱 실행 시 파일 대화상자를 자동으로 열지 않는다.

```text
Manga Translator

[새 번역 프로젝트]

최근 프로젝트
- 작품 A · 18페이지 · 정밀 번역 · 62%
- 작품 B · 12페이지 · 빠른 번역 · 완료

우측 상단: 기존 프로젝트 열기 · 설정
```

프로젝트 홈에는 다음만 표시한다.

- 새 번역 프로젝트
- 기존 프로젝트 열기
- 최근 프로젝트 목록
- 설정

TXT 불러오기는 `기존 대본 가져오기` 보조 메뉴로 이동한다. OCR, 문맥, 저장 버튼은 홈에 표시하지 않는다.

최근 프로젝트는 프로젝트 경로, 제목, 페이지 수, 번역 모드, 진행률, 마지막 접근 시각만 앱별 사용자 설정에 저장한다. API 키나 OCR·번역 내용은 최근 프로젝트 목록에 복제하지 않는다.

## 화면 2: 프로젝트 준비

사용자가 만화 전체 페이지를 확인한 뒤 번역을 시작하는 화면이다.

```text
새 번역 프로젝트                                      18페이지

[01] [02] [03] [04] [05] ...
순서 변경 · 삭제 · 이미지 추가

빠른 번역
전 페이지 자동 OCR · 번역 · 합성

정밀 번역
전체 OCR · 화자 연결 · 문맥 번역 · 합성

                              [18페이지 정밀 번역 시작]
```

### 이미지 준비 기능

- 파일 선택창에서 여러 JPG, JPEG, PNG, WEBP 선택
- 탐색기에서 여러 파일 드래그 앤 드롭
- 선택한 이미지 전체를 썸네일 격자로 표시
- 자연 숫자 정렬: `1, 2, 10` 순서 보장
- 드래그로 페이지 순서 변경
- 선택한 페이지 삭제
- 이미지 추가 선택
- 동일 파일 또는 동일 해시 중복 경고
- 전체 페이지 수 표시
- 파일을 읽지 못한 항목은 다른 항목과 분리해 오류 표시

이미지를 선택한 직후 저장 대화상자를 열지 않는다. 사용자가 페이지 순서와 번역 모드를 확인하고 `N페이지 [모드] 번역 시작`을 누른 뒤 저장 위치를 한 번 선택한다.

### 번역 모드 선택

두 모드는 동일한 프로젝트와 이미지 순서를 사용한다.

- 빠른 번역 카드: 전 페이지 자동 처리, 실패 페이지 마지막 검토, 빠른 결과
- 정밀 번역 카드: 작품 전체 분석, 화자·문맥 일관성, 두 개의 문제 중심 검토 지점

Gemini API 키가 구성되지 않았다면 번역 시작 직전에 설정 패널을 열고, 키가 준비될 때까지 시작 CTA만 비활성화한다. 이미지 준비와 순서 편집은 계속 가능하다.

## 화면 3: 번역 작업 공간

### 기본 구조

```text
┌──────────────────────────────────────────────────────────────┐
│ 작품명   07 / 18   정밀 번역 · 화자 연결 72%       집중 모드 │
├────┬───────────────────────────────────────────────┬─────────┤
│ ◀  │                                               │ ▶       │
│페이지│             전체 페이지 이미지              │ 작업    │
│목록 │          기본: 화면 맞춤 · 무자르기           │ 패널    │
│    │                                               │         │
├────┴───────────────────────────────────────────────┴─────────┤
│ ▲ 진행 상태 · OCR 18/18 · 화자 확인 4개 · 실패 1개           │
└──────────────────────────────────────────────────────────────┘
```

### 상단 바

번역 중에는 다음만 상시 표시한다.

- 작품명
- 현재 페이지 / 전체 페이지
- 번역 모드와 현재 단계
- 전체 진행률
- 집중 모드
- 더보기 메뉴

저장, 다른 이름, 내보내기, 프로젝트 설정, API 키 설정은 더보기 또는 설정 화면으로 이동한다.

### 제거할 고정 레일

현재 `작업·페이지·문맥·설정` 레일을 제거한다.

- 작업: 중앙 화면 자체이므로 메뉴가 필요 없다.
- 페이지: 접이식 페이지 필름스트립으로 대체한다.
- 문맥: 정밀 번역의 등장인물·화자 단계 안으로 이동한다.
- 설정: 상단 설정 메뉴로 이동한다.

## 이미지 표시 규칙

### 기본 표시

기본값은 `화면 맞춤`이다.

- 원본 비율 유지
- 이미지의 어느 부분도 잘리지 않음
- 가로·세로 남는 공간은 어두운 중립 배경으로 처리
- 패널 크기 변경 시 남은 공간에 맞춰 즉시 재계산
- 이미지 업스케일로 원본보다 흐려지는 것을 피함
- 페이지 이동 후에도 사용자가 선택한 표시 방식을 유지

### 보기 옵션

- 화면 맞춤: 전체 페이지 표시, 기본값
- 100%: 원본 픽셀 크기
- 폭 맞춤: 가로폭 기준, 세로 스크롤 허용
- 확대·축소
- 확대 상태에서 드래그 이동
- 원본 위치로 재설정

폭 맞춤은 이미지를 자르지 않지만 세로가 화면을 넘을 수 있으므로 기본값으로 사용하지 않는다.

### 이미지 레이어

```text
보기: [원본] [OCR 박스] [원문] [번역문] [완성 미리보기]
```

각 레이어는 독립적으로 표시하거나 숨긴다.

- 원본: 아무 보조 표시가 없는 원본 이미지
- OCR 박스: 검출된 텍스트 영역과 읽기 순서
- 원문: 추출한 원문 표시
- 번역문: 번역 결과 표시
- 완성 미리보기: 원문 제거와 번역문 합성 결과

`Esc`는 열린 작업 패널과 보조 레이어를 닫고 원본 전체 페이지 보기로 돌아간다. 진행 중인 백그라운드 작업은 중단하지 않는다.

## 접이식 패널 시스템

### 독립 패널

- 왼쪽 페이지 필름스트립
- 오른쪽 작업 인스펙터
- 하단 결과·진행 도크

각 패널은 독립적으로 접고 펼친다. 접힌 패널은 사라지는 대신 화면 가장자리에 얇은 탭과 상태 배지를 남긴다.

### 집중 모드

집중 모드는 좌·우·하단 패널을 한 번에 접고 상단 바를 최소화한다. 작업 큐는 계속 실행된다. 사용자가 집중 모드를 해제하면 이전 패널 상태를 복원한다.

### 패널 내부 아코디언

오른쪽 작업 패널의 다음 섹션도 독립적으로 접는다.

- OCR 원문
- 번역문
- 등장인물·화자
- 작품·장면 문맥
- 번역 근거와 후보
- 합성 설정
- 경고와 실패

오류 섹션이 접혀 있어도 `경고 1`, `확인 필요 4`처럼 개수를 표시한다.

### 패널 상태 기억

패널의 열림·접힘, 이미지 보기 방식, 집중 모드 직전 상태는 앱별 UI 설정으로 저장한다. OCR·번역 데이터와 분리하며 다른 프로젝트의 콘텐츠를 저장하지 않는다.

## 빠른 번역

### 사용자 목표

모든 페이지를 자동으로 처리하고 실패하거나 검토가 필요한 페이지만 마지막에 확인한다.

### 처리 흐름

```text
페이지 순서 확인
  -> 페이지 OCR
  -> 즉시 번역
  -> 원문 제거
  -> 번역문 배치
  -> 결과 저장
  -> 다음 페이지
  -> 실패·검토 필요 페이지만 마지막 검토
```

페이지 작업은 안정성을 위한 제한된 작업 큐로 실행하며 결과 순서는 페이지 순서를 유지한다. 공급자 과부하를 키우는 무제한 병렬 요청은 사용하지 않는다.

### 누적 문맥

빠른 번역은 작품 전체 화자 분석을 먼저 수행하지 않는다. 대신 앞에서 확정된 다음 정보를 뒤 페이지에 전달한다.

- 인물 이름
- 고유명사
- 호칭
- 반복 표현
- 이미 확정된 번역 용어

### 진행 화면

작업 시작 시 모든 보조 패널은 접혀 있고 하단에 얇은 진행 표시줄만 남는다.

- 현재 페이지와 처리 단계
- 완료 / 전체 페이지
- 실패 개수
- 일시 중지·재개
- 상세 진행 목록 펼치기

사용자가 다른 페이지를 보는 동안 작업은 계속된다.

### 실패 처리

- 한 페이지 실패가 다음 페이지를 막지 않는다.
- 자동 재시도 예산이 끝난 페이지는 실패 큐로 이동한다.
- 전체 작업이 끝난 뒤 실패·검토 필요 페이지만 자동으로 목록화한다.
- 사용자는 개별 페이지 또는 선택한 실패 페이지를 재실행한다.
- 성공 페이지는 재실행하지 않는다.

## 정밀 번역

### 사용자 목표

작품 전체의 등장인물, 관계, 말투, 장면 흐름을 먼저 이해한 뒤 일관된 번역과 이미지 합성을 만든다.

### 처리 흐름

```text
전체 페이지 OCR
  -> 텍스트·장면·읽기 순서 분류
  -> 등장인물·화자 연결
  -> 중간 대본 생성
  -> 작품 전체 문맥 분석
  -> 최종 번역
  -> 원문 제거·번역문 배치
  -> 문제 항목 검토
```

### 전체 OCR 산출물

모든 텍스트 항목은 다음 정보를 가진다.

- 페이지 번호
- 장면 번호
- 읽기 순서
- 텍스트 유형
- 원문
- 정규화된 말풍선 위치
- 화자 후보
- OCR 신뢰도
- 주변 장면 설명
- 번역 포함 여부
- 검토 상태

말풍선·내레이션은 기본 번역 대상이다. 효과음, 장식 문자, 배경 잡문자는 별도 분류하며 기본 제외하되 사용자가 포함할 수 있다.

### 등장인물·화자 연결

AI는 모든 페이지의 인물과 대사를 비교해 다음을 구성한다.

- 등장인물 이름과 별칭
- 등장 페이지
- 인물 관계
- 말투와 호칭
- 연결된 대사 수
- 화자 후보와 근거
- 확인 필요 대사

신뢰도가 높은 연결은 자동 적용한다. 애매한 항목만 확인 필요 큐에 넣는다.

### 중간 대본

번역 전 다음 구조의 대본을 프로젝트 내부에 저장하고 TXT로 내보낼 수 있다.

```text
[PAGE 03] [SCENE 02]

01 | 미사키
원문: 今日はどうしたの？
상황: 교실에서 유키를 바라보며 질문
위치: 오른쪽 상단 말풍선

02 | 유키
원문: 別に……
상황: 시선을 피하며 짧게 대답
위치: 왼쪽 하단 말풍선
```

대본에는 페이지, 장면, 읽기 순서, 화자, 원문, 상황, 말풍선 위치, OCR 신뢰도, 검토 상태를 포함한다.

### 전체 문맥 번역

최종 번역 요청은 현재 대사와 함께 다음 문맥을 사용한다.

- 작품 전체 등장인물 목록과 관계
- 인물별 말투와 호칭
- 고유명사와 용어집
- 앞뒤 장면
- 현재 페이지 이미지
- 현재 말풍선 위치
- 앞 페이지에서 확정된 번역
- 같은 장면의 다른 대사

번역 결과는 번역문, 선택 이유, 말투 적용 근거, 다른 후보, 애매한 부분, 검토 필요 여부를 가진다. 상세 근거는 기본 접힘 상태로 표시한다.

### 정밀 번역 검토 지점

모든 페이지를 강제로 하나씩 승인하게 하지 않는다. 다음 두 문제 중심 검토 지점만 사용한다.

1. OCR·화자 연결의 확인 필요 항목
2. 최종 합성의 텍스트 넘침, 낮은 신뢰도, 배치 실패 항목

문제가 없는 항목은 자동으로 다음 단계로 넘어간다.

## 화면 4: 문제·결과 검토

검토는 이미지가 보이는 워크벤치 안에서 수행한다.

### OCR 검토

- 하단: OCR 항목 목록
- 오른쪽: 선택 항목 원문·유형·신뢰도
- 이미지: 선택한 bbox 강조

### 화자 검토

- 하단: 확인이 필요한 대사 목록
- 오른쪽: 등장인물 후보와 연결 근거
- 이미지: 해당 대사의 페이지와 위치

### 번역 검토

- 하단: 원문·번역문 목록
- 오른쪽: 번역 근거와 다른 후보
- 이미지: 원본·번역문 레이어 전환

### 합성 검토

- 이미지: 원본과 완성본 비교
- 오른쪽: 글자 크기, 정렬, 줄바꿈
- 하단: 넘침과 배치 실패 목록

기존 중앙 OCR 검토 모달은 새 패널 검토가 안정화될 때까지만 롤백 경로로 유지하고, 기본 흐름에서는 표시하지 않는다.

## 번역문 이미지 합성

최종 번역이 확정된 항목은 다음 순서로 합성한다.

1. 원문 영역을 별도 결과 자산에서 제거
2. 말풍선과 주변 그림 보존
3. 번역문 길이에 맞춘 글자 크기 계산
4. 원문의 세로·가로 쓰기 방향 참고
5. 중앙 정렬과 줄바꿈
6. 말풍선 밖 넘침 검사
7. 원본, 제거본, 완성본을 각각 저장

합성 과정은 원본 파일을 수정하지 않는다. 검토를 위해 언제든 원본과 완성본을 전환한다.

## 화면 5: 완료 및 내보내기

```text
정밀 번역 완료

완료 페이지       17 / 18
검토 필요          1
실패               0

[완성 만화 보기]
[문제 항목 검토]
[번역 이미지 내보내기]
[대본 TXT 내보내기]
[프로젝트 폴더 열기]
```

### 결과물

- 페이지 순서대로 정렬된 번역 완료 이미지
- 페이지·장면·화자·원문·번역문이 포함된 TXT 대본
- 원본 이미지 자산
- 중간 OCR·화자·번역 결과
- 실패 및 검토 필요 보고서

## 자동 저장과 중단 후 재개

각 페이지와 단계가 끝날 때 프로젝트를 자동 저장한다.

- 이미지 준비 완료
- OCR 페이지 완료
- 화자 연결 배치 완료
- 번역 페이지 완료
- 합성 페이지 완료
- 사용자 검토 변경

앱을 다시 열면 마지막으로 완료된 안정된 단계에서 재개한다. 실행 중이던 원격 요청 자체를 복원하지 않고 해당 페이지·단계를 대기 상태로 돌려 안전하게 다시 실행한다.

## 공통 오류 처리

- Gemini 429·503은 기존 지수 백오프 정책 사용
- 필수 단계 최대 3회, 선택적 Crop 단계 최대 2회 정책 유지
- 최종 실패 시 수동 재실행 유지
- Crop ReOCR 실패 시 기존 OCR 유지
- 한 페이지 실패가 전체 작업을 중단하지 않음
- 파일 읽기 실패는 이미지 준비 화면에서 분리 표시
- 자동 저장 실패 시 작업 큐를 일시 중지하고 사용자에게 저장 복구를 요구
- 원본, OCR 결과, 번역, 합성 결과를 독립 자산으로 보존
- 사용자 오류 메시지에 API 키, 전체 내부 경로, 공급자 요청 본문을 노출하지 않음

## 시각 방향

- 이미지 무대: 짙은 남청색 또는 차콜
- 패널: 따뜻한 아이보리 또는 밝은 중립 회색
- 경계: 얇은 기능적 선 한 개
- 강조색: 현재 페이지, 주요 CTA, 검토 필요 항목에만 사용
- 접힌 패널: 화면 가장자리의 좁은 탭과 상태 배지
- 카드: 모드 선택과 완료 요약처럼 실제 그룹이 필요한 곳에만 사용
- 모서리: 계층화된 작은 반경, 모든 요소를 둥근 카드로 만들지 않음
- 모션: 150~200ms의 기능적 패널 전환
- 패널 전환 시 이미지가 남은 공간 중앙으로 부드럽게 재배치
- 진행 숫자와 배지는 고정 정렬해 값 변경 시 화면이 흔들리지 않게 함

## 저장 모델 요구사항

프로젝트 파일에는 기존 데이터와 함께 다음 선택적 상태가 필요하다.

- 번역 모드: 빠른 / 정밀
- 전체 작업 단계와 진행률
- 페이지별 OCR·화자·번역·합성 단계
- 페이지별 대기·진행·완료·검토 필요·실패 상태
- OCR 텍스트와 장면·읽기 순서
- 등장인물·관계·화자 연결
- 중간 대본
- 번역 결과와 근거
- 실패 종류와 재시도 가능 여부
- 원본·제거본·완성본 자산 경로
- 마지막 안정 저장 시각

새 필드는 선택적으로 추가한다. 기존 프로젝트에 필드가 없으면 현재 수동 편집 프로젝트로 정상 로드하고, 사용자가 새 자동 번역 모드를 시작할 때만 새 작업 상태를 생성한다. 기존 파일을 열기 위해 별도 파괴적 마이그레이션을 요구하지 않는다.

저장 형식 변경은 별도 설계·계획 단계에서 구체 타입, 버전, 검증, 하위 호환 테스트를 확정한 뒤 구현한다.

## 테스트 전략

### 프로젝트 준비

- 여러 이미지가 한 프로젝트에 추가된다.
- 자연 숫자 순서가 유지된다.
- 순서 변경, 삭제, 추가가 페이지 번호에 반영된다.
- 중복과 읽기 실패가 정상 이미지와 분리된다.
- 저장 대화상자는 시작 CTA 전에는 열리지 않는다.

### 이미지 중심 작업 공간

- 기본 이미지가 `contain` 규칙으로 잘리지 않는다.
- 좌·우·하단 패널을 독립적으로 접고 펼친다.
- 집중 모드가 이전 패널 상태를 복원한다.
- 패널 전환 후에도 이미지 표시 방식이 유지된다.
- `Esc`가 작업을 취소하지 않고 원본 집중 보기로 돌아간다.

### 빠른 번역

- 성공 페이지 후 자동으로 다음 페이지를 처리한다.
- 한 페이지 실패 후에도 후속 페이지가 실행된다.
- 실패 페이지만 재실행한다.
- 자동 저장 후 앱 재시작 시 완료 페이지를 반복 처리하지 않는다.
- 완료 요약의 성공·검토·실패 수가 정확하다.

### 정밀 번역

- 최종 번역보다 전체 OCR과 화자 연결이 먼저 완료된다.
- 대본에 페이지·장면·순서·화자·원문·위치가 포함된다.
- 신뢰도 높은 화자는 자동 연결되고 애매한 항목만 검토 큐에 들어간다.
- 번역 요청에 작품 문맥과 현재 페이지 정보가 포함된다.
- 문제 없는 항목은 강제 승인 없이 다음 단계로 이동한다.

### 합성과 보안

- 원본 파일이 변경되지 않는다.
- 원본, 제거본, 완성본 경로가 분리된다.
- 텍스트 넘침이 검토 필요 상태가 된다.
- API 키와 공급자 요청 본문이 프로젝트·오류·로그에 저장되지 않는다.

### 최종 검증

- 타입 검사
- 전체 테스트
- 프로덕션 빌드
- Electron에서 10~20페이지 프로젝트 준비
- 빠른 번역의 전 페이지 자동 진행과 실패 격리
- 정밀 번역의 전체 OCR 선행과 문제 중심 검토
- 패널 전체 접기와 이미지 무자르기
- 앱 종료 후 작업 재개
- 결과 이미지와 TXT 대본 내보내기

## 완료 조건

- 사용자가 첫 화면에서 이 앱이 만화 전체를 번역하는 도구임을 이해한다.
- 여러 이미지를 한 번에 추가하고 번역 전 순서를 확인·수정한다.
- 빠른 번역은 전 페이지를 자동 처리하고 실패 페이지만 마지막에 보여준다.
- 정밀 번역은 전체 OCR과 화자 연결 후 전체 문맥으로 번역한다.
- 현재 페이지 이미지는 기본 상태에서 전부 보이며 잘리지 않는다.
- 모든 보조 패널과 텍스트 레이어를 접거나 숨길 수 있다.
- 집중 모드에서 이미지가 화면의 실질적인 대부분을 차지한다.
- OCR·화자·번역·합성 검토 중에도 이미지가 계속 보인다.
- 한 페이지 실패가 전체 작업을 멈추지 않는다.
- 원본은 보존되고 중단 후 마지막 안정 단계에서 재개된다.
- 번역 이미지, 중간 대본, 실패 보고서를 내보낼 수 있다.
- 기존 프로젝트는 파괴적 변환 없이 열린다.
