# Trio Image-first Workbench Redesign

> **제품**: Trio — Manga Translation Workbench  
> **범위**: Electron 렌더러의 UI·UX·시각 시스템 전면 재설계  
> **보존 원칙**: 현행 프로젝트 스키마, IPC 계약, 파일 보호, API 키 처리, OCR·화자·번역·인페인팅의 핵심 동작은 변경하지 않는다.

## 1. 설계 결론

Trio는 자동 번역 결과를 소비하는 대시보드가 아니라, **만화 페이지 위에서 AI 제안을 사람이 검증·수정·확정하는 전문 작업대**다. 따라서 새 UI의 중심 객체는 대사 테이블이 아니라 현재 페이지 이미지와 그 위의 선택된 말풍선이다. 사용자는 어느 순간에도 현재 페이지, 선택한 영역, 수정 중인 정보, 다음 가능한 행동을 잃지 않아야 한다.

자동 만화 번역 도구는 감지·OCR·번역·클린업·식자를 넓게 지원하지만, 실제 사용자 대화에는 모델 조합의 복잡성, 느린 고품질 OCR, 좁은 말풍선에서의 텍스트 겹침, 문맥을 가진 수동 번역의 필요가 반복적으로 나타난다.[1] [2] 따라서 Trio는 지원하지 않는 자동 일괄 번역이나 정확도 지표를 만들어내지 않는다. 대신 현재 구현된 사람 검수 흐름을 더 빠르고 명확하게 만든다.

## 4. 선택 방향: Inkline Production Bench

### 4.1 디자인 운동과 제품 감정

선택한 방향은 **에디토리얼 프로덕션 벤치**다. 고전적인 출판·편집 작업대의 명료한 정보 위계와 현대 이미지 편집기의 직접 조작을 결합한다. 화면은 차분하고 도구적이며, 사용자의 만화 페이지가 제품보다 앞에 놓인다. 커다란 카드, 유리 질감, 그라데이션, 마케팅형 통계와 장식은 사용하지 않는다.

### 4.2 핵심 원칙

| 원칙 | 구현 규칙 |
| --- | --- |
| **페이지가 주인공이다** | 이미지 스테이지는 유효 작업 공간의 최대 영역을 차지한다. 패널은 열려도 이미지를 덮지 않고, 좁은 창에서는 먼저 접힌다. |
| **선택이 편집을 결정한다** | 선택 없음·대사 선택·OCR 후보 선택·인페인팅·식자 모드마다 오른쪽 인스펙터와 캔버스 근처 행동을 바꾼다. |
| **예외만 줄 세운다** | 정상 항목을 모두 읽게 하지 않는다. 실제 경고, 검토 상태, 누락 화자, 미완료 번역에만 이슈 큐 진입을 제공한다. |
| **사용자 확정이 최종값이다** | AI 결과는 제안/검토 필요 상태로 표현한다. 명시적 확정 전에는 완료처럼 보이지 않는다. |
| **항상 돌아갈 수 있다** | 인페인팅·OCR 검토·집중 모드·비교 모드에는 취소 또는 이미지 보기로 복귀하는 보이는 경로와 안전한 단축키를 둔다. |

### 4.3 시각 언어

라이트 테마는 텍스트 검수의 기본 표면으로 사용한다. `#F4F4F1`의 중성 작업면, `#FFFFFF`의 편집 패널, `#171A20`의 잉크 텍스트, `#2F62C9`의 선택·주 동작, `#C44832`의 주의·미확정, `#287B62`의 확정 상태를 사용한다. 이미지 스테이지는 테마와 무관하게 `#17191D` 차콜로 유지해 밝은 만화 이미지와 오버레이의 대비를 안정화한다.

다크 테마는 단순 반전이 아니라 야간·뷰어 작업에 맞는 동등한 정보 위계를 제공한다. 밝은 텍스트 판독이 많아지는 OCR·번역 입력 표면은 무채색 짙은 회색으로, 스테이지 외곽은 한 단계 더 어두운 차콜로 두어 이미지 가장자리가 사라지지 않게 한다. 정상 시력 사용자에게 세부 텍스트 판독은 일반적으로 라이트 모드가 유리하므로 라이트를 기본으로 제공하되, 장시간 사용하는 앱에서는 테마 선택을 제공해야 한다는 UX 근거를 따른다.[3]

| 토큰군 | 라이트 | 다크 | 사용처 |
| --- | --- | --- | --- |
| `--app-surface` | `#F4F4F1` | `#202329` | 앱 배경과 빈 영역 |
| `--panel-surface` | `#FFFFFF` | `#292D34` | 드로어·인스펙터·큐 |
| `--canvas-surface` | `#17191D` | `#121417` | 이미지 스테이지 |
| `--ink` | `#171A20` | `#F1F3F5` | 본문·라벨 |
| `--muted-ink` | `#69717D` | `#AAB2BD` | 보조 정보 |
| `--action` | `#2F62C9` | `#7DA5FF` | 기본 행동·선택 |
| `--review` | `#C44832` | `#FF8F76` | 검토 필요·오류 |
| `--confirmed` | `#287B62` | `#5FC79F` | 명시적 확정 |
| `--rule` | `#D7D9DD` | `#434951` | 경계선·표 형식 구분 |

서체는 외부 의존성을 추가하지 않고 현재 Windows 친화적 조합을 유지한다. UI와 한국어 본문은 `Pretendard, Noto Sans KR, Malgun Gothic, sans-serif`를, 숫자·페이지·단축키·진단 정보는 `Cascadia Mono, Consolas, monospace`를 사용한다. 제목은 16–20px의 중간 이상 굵기만 사용하며, 큰 히어로 제목은 사용하지 않는다. 모서리는 2–6px로 제한하고, 그림자는 모달·떠 있는 캔버스 도구의 깊이를 나타낼 때만 짧고 약하게 사용한다.

## 6. 핵심 워크플로

### 6.1 페이지에서 수정까지

사용자는 페이지 네비게이터 또는 단축키로 페이지를 이동한다. 이미지 위 오버레이 또는 하단 대사 큐에서 말풍선을 선택하면 해당 영역이 명확한 테두리와 순서표로 강조되고, 오른쪽 인스펙터가 그 대사의 OCR·화자·번역·메모·상태를 연다. 인스펙터의 다음 행동은 현재 상태에 맞춰 OCR 검토, 화자 선택, 번역 확정 또는 다음 검토 항목 이동으로 바뀐다.

### 6.2 OCR 검토와 화자 검토

OCR 실행 후 현재 페이지는 계속 보인다. 하단 큐는 `OCR 후보`로 전환해 후보 목록·그룹·경고를 압축해 보이고, 선택한 후보만 오른쪽 인스펙터에서 원문·화자 후보·메모를 편집한다. `적용`은 명시적이며, 취소는 대사를 새로 만들지 않는다. 이 흐름은 이미지 클릭으로 편집기를 여는 만화 번역 도구의 장점을 가져오되, Trio의 실제 화자·읽기 순서·검토 상태를 보존한다.[2]

### 6.3 문제 큐

`문제 라인`은 미확정 상태, 실제 경고, 낮은 신뢰도 경고, 필요한데 누락된 화자, 번역문 미입력 등 코드에서 파생 가능한 항목만 보여 준다. 항목을 고르면 페이지 이동, 영역 중앙 정렬, 선택, 해당 인스펙터 전환이 한 번에 일어난다. 정상 항목의 인위적 품질 점수나 진행률을 표시하지 않는다.

### 6.4 비교·인페인팅·식자

원본·인페인팅·번역 결과는 같은 viewport 변환을 공유한다. 기본은 단일 보기이며, 결과가 있을 때에만 좌우 분할, 리빌, 투명도 비교를 선택하게 한다. 인페인팅은 이미지 단계의 모드로 열리고, 마스크·브러시·지우개는 캔버스 가까이에, 프롬프트·공급자·실행·실패 메시지는 인스펙터에 둔다. 실패 시 마스크를 유지하며, 성공해도 원본을 덮어쓰지 않는 기존 자산 정책을 계속 지킨다.

| 1024px 미만 | 열람·페이지 이동·OCR·저장·텍스트 수정은 가능하게 둔다. | 인페인팅 마스크·식자 박스 직접 조작은 창 확대를 안내하며 제한한다. |

## 8. 상호작용 및 단축키 규칙

Photoshop의 문맥형 작업 바는 선택에 따라 캔버스 위의 관련 행동만 보여 패널 전환을 줄이고 캔버스 집중을 유지한다.[4] Trio는 그 원리를 복사하되, 떠 있는 도구가 이미지를 가리거나 위치를 계속 바꾸지 않게 한다.

| 입력 | 동작 | 보호 규칙 |
| --- | --- | --- |
| `Space` | 현재 페이지의 OCR 실행 또는 활성 OCR 검토 열기 | 텍스트 입력·선택·콘텐츠 편집 영역에서는 동작하지 않는다. |
| `Esc` | 현재 OCR/인페인팅/집중 보기에서 이전 안정 상태로 복귀 | 편집 중 텍스트를 지우거나 미확정 후보를 자동 적용하지 않는다. |
| `←` / `→` | 이전/다음 페이지 | 텍스트 필드·선택 상자에서는 이동을 가로채지 않는다. |
| `Ctrl+Enter` | 현재 인스펙터의 명시적 다음 행동 | 버튼의 기존 비활성 조건을 따른다. |
| `\` 누르고 있기 | 원본 임시 비교 | 포커스가 편집 컨트롤일 때 비활성화하고, 창 포커스 상실 시 즉시 원복한다. |

## 9. 구현 경계와 수용 기준

이번 UI 변경은 새 자동 번역 모드, 새 파일 입력 형식, 백그라운드 처리 큐, 임의의 완료 지표를 추가하지 않는다. README가 밝히듯 `fast`와 `precise`는 현재 저장되는 모드이며 자동 파이프라인은 아직 구현 전이므로, 프로젝트 설정과 홈에 이를 완성 기능처럼 표시하지 않는다.

구현이 완료되었다고 판단하려면 다음이 모두 충족되어야 한다.

| 범주 | 수용 기준 |
| --- | --- |
| 이미지 우선 | 첫 워크스페이스 화면에서 이미지 스테이지가 지배적이며, 1366×768에서도 보조 패널 때문에 과도하게 축소되지 않는다. |
| 선택 문맥 | 이미지 또는 큐의 항목 선택이 해당 영역 강조와 적합한 인스펙터를 함께 갱신한다. |
| 검토 | OCR·화자·번역·인페인팅·식자 흐름에서 원래 핸들러와 데이터 계약이 유지된다. |
| 회귀 | 새 프로젝트, 열기, 최근 프로젝트, 이미지 가져오기, OCR, OCR 적용, 번역 편집, 저장, TXT 입출력, 인페인팅, 설정, 환경 준비가 기존 테스트와 수동 확인에서 유지된다. |
| 접근성 | 키보드 포커스와 선택 상태가 보이고, 전역 단축키가 텍스트 입력을 방해하지 않으며, 상태는 색상 하나에만 의존하지 않는다. |
| 테마 | 라이트·다크 모두에서 텍스트·선택·경고·오버레이 대비가 보존되고, 이미지 스테이지가 안정적인 중성 배경을 유지한다. |
