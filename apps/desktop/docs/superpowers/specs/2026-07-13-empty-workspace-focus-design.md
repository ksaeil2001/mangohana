# Empty Workspace Focus Design

## 목적

대사가 없는 상태에서는 시작 행동만 보여주고, 대사를 불러온 뒤에는 현재 번역 단계에서 가장 중요한 다음 행동 하나만 강조한다. 저장, OCR, 이미지 연결, 내보내기의 기존 동작과 데이터 구조는 변경하지 않는다.

## 범위

이번 변경은 Windows 데스크톱 UI의 표시 정책과 시각적 위계만 다룬다.

- 빈 상태의 상단 페이지 제어와 하단 작업 패널을 숨긴다.
- 중앙 시작 안내와 오른쪽 시작 안내를 하나의 시작 패널로 통합한다.
- TXT 불러오기 후 작업 단계별 주요 행동을 하나만 강조한다.
- 모바일 전용 레이아웃, 저장 스키마, IPC, OCR 또는 인페인팅 API는 변경하지 않는다.

## 상태 정의

빈 상태의 유일한 기준은 `lineCount === 0`이다. 프로젝트가 저장됐는지, 파일 경로가 있는지, 새 프로젝트인지와 관계없이 대사가 0개면 빈 상태다.

```ts
type WorkspacePresentation = {
  isEmptyWorkspace: boolean;
  showStartPanel: boolean;
  showWorkspaceChrome: boolean;
  showPageControls: boolean;
  showBottomPanel: boolean;
  showInspector: boolean;
  showSave: boolean;
  showSaveAs: boolean;
  showExport: boolean;
  saveLabel: "새 프로젝트" | "저장 필요" | "변경 있음" | "저장됨";
};
```

`getWorkspacePresentation`이 이 값을 계산하며 `App.tsx`는 같은 조건을 다시 만들지 않는다.

## 빈 상태 화면

### 표시하는 요소

- 앱 이름과 최소 프로젝트 상태
- 중앙 `WorkspaceStartPanel`
- 주요 행동 `TXT 불러오기`
- 보조 행동 `새 프로젝트`, `기존 프로젝트 열기`, `빈 프로젝트 저장`
- TXT를 불러오면 첫 번째 미완료 대사부터 검토할 수 있다는 한 줄 설명

### 숨기는 요소

- 이전 페이지, 페이지 번호, 다음 페이지
- 왼쪽 작업 레일과 작업 서랍
- 오른쪽 `시작 준비` 검사 영역
- 하단 `대사`, `OCR 후보`, `문제 라인` 패널
- 이미지, OCR, 인페인팅 작업 흐름

### 문구

```text
TXT 불러오기 → 번역 검토 → 내보내기
번역할 TXT 파일을 불러오세요
TXT를 불러오면 첫 번째 미완료 대사부터 바로 검토할 수 있습니다.
```

오른쪽 패널의 기존 시작 설명은 삭제하고 위 문구로 통합한다. 같은 의미의 문장을 다른 영역에서 반복하지 않는다.

## 작업 상태 화면

대사가 한 개 이상이면 시작 패널은 사라지고 기존 작업 셸이 나타난다. 각 단계에서 시각적으로 강조되는 주요 행동은 하나다.

| 상태 | 주요 행동 | 보조 행동 |
| --- | --- | --- |
| 선택된 대사 없음 | 첫 미완료 대사 선택 | 전체 대사 보기 |
| 번역 수정 중 | 완료하고 다음 대사 | 상태 변경, 이동, 삭제, 저장 |
| 다른 페이지에 미완료 대사 존재 | 남은 대사로 이동 | 프로젝트 검토 |
| 모든 대사 완료 | 번역 내보내기 | 프로젝트 검토, 저장 |
| OCR 실패 | OCR 다시 실행 | 오류 닫기 또는 작업 복귀 |

저장은 데이터 손실 방지를 위해 계속 접근 가능하지만 현재 번역 행동과 같은 시각적 강도로 표시하지 않는다. 저장 필요 여부는 상태 배지와 보조 버튼으로 전달한다.

## 컴포넌트 책임

### `workspacePresentation.ts`

- `lineCount`를 기준으로 빈 상태를 계산한다.
- 상단, 레일, 검사 영역, 하단 패널 표시 여부를 반환한다.
- UI 문구나 React 노드를 반환하지 않는다.

### `App.tsx`

- 표시 모델을 한 번 계산한다.
- 페이지 제어, 작업 셸, 검사 영역, 하단 패널을 표시 모델에 따라 렌더링한다.
- TXT 불러오기, 저장, OCR, 번역, 내보내기의 기존 핸들러를 그대로 전달한다.

### `WorkspaceStartPanel.tsx`

- 빈 상태에서 필요한 설명과 행동을 한 영역에 제공한다.
- 불러오기 진행 중 중복 클릭을 막고 `aria-busy`를 유지한다.
- 보조 행동을 주요 CTA보다 약하게 표시한다.

### `FocusDeckShell.tsx`

- 작업 상태에서만 레일과 워크플로를 표시한다.
- 빈 상태를 위한 중복 검사 패널을 만들지 않는다.

### `StageEditor.tsx`

- 현재 `stage`, 오류, 선택 대사와 남은 작업 상태를 기준으로 주요 행동을 결정한다.
- 현재 단계의 주요 CTA 하나만 `.primary-button`으로 표시한다.
- 저장과 검토 같은 보조 행동은 `.secondary-button`을 사용한다.

## 상태 전환

```text
lineCount = 0
  -> TXT 불러오기 성공
  -> lineCount > 0
  -> 작업 셸 표시
  -> 첫 미완료 대사 자동 선택
  -> 완료하고 다음 대사
  -> 남은 대사로 이동 또는 번역 내보내기
```

TXT 불러오기가 취소되거나 빈 파일이면 `lineCount`는 0으로 유지되고 시작 패널도 유지된다. 오류 메시지는 시작 패널 가까이에 표시하며 페이지 제어나 빈 작업 패널을 다시 나타내지 않는다.

모든 대사를 삭제해 `lineCount`가 0이 되면 즉시 빈 상태로 돌아간다. 현재 페이지, 저장 경로, 프로젝트 메타데이터는 유지한다.

## 오류 및 접근성

- TXT 불러오는 동안 주요 버튼을 비활성화하고 진행 상태를 읽을 수 있게 한다.
- 빈 TXT와 불러오기 실패는 원인과 재시도 행동을 제공한다.
- 숨긴 영역은 CSS로만 가리지 않고 DOM에서 제거해 키보드 포커스가 들어가지 않게 한다.
- 작업 상태의 주요 CTA에는 명확한 접근 가능한 이름을 유지한다.
- `Ctrl+Enter`는 텍스트 편집을 방해하지 않는 기존 조건을 유지한다.

## 테스트 전략

### 표시 모델 단위 테스트

- 저장 경로가 있어도 `lineCount === 0`이면 빈 상태다.
- 저장 경로가 없어도 `lineCount > 0`이면 작업 상태다.
- 빈 상태에서 페이지 제어, 검사 영역, 하단 패널 표시 값이 모두 `false`다.
- 대사가 있으면 작업 영역 표시 값이 `true`다.

### 렌더러 통합 테스트

- 최초 화면에서 TXT CTA는 보이지만 페이지 제어, 레일, 오른쪽 안내, 하단 패널은 보이지 않는다.
- 저장된 빈 프로젝트에서도 같은 결과가 나온다.
- TXT 불러오기 성공 후 작업 셸과 첫 미완료 대사가 나타난다.
- 빈 TXT 또는 취소 후 시작 화면이 유지된다.
- 마지막 대사 삭제 후 빈 상태로 돌아간다.
- 번역 수정 단계에서 강조된 주요 CTA는 `완료하고 다음 대사` 하나다.
- 전체 완료 단계에서 강조된 주요 CTA는 `번역 내보내기` 하나다.

### 시각 검증

- 1280×720과 1440×900에서 시작 카드가 자연스럽게 중앙 정렬된다.
- 빈 화면에 하단 패널 잔여 공간이나 잘린 안내 문구가 없다.
- 작업 화면에서 주요 CTA가 동시에 두 개 이상 경쟁하지 않는다.
- 가로 스크롤과 콘솔 오류가 없다.

## 수용 기준

1. `lineCount === 0`인 모든 상태에서 페이지 제어, 작업 레일, 오른쪽 검사 영역, 하단 작업 패널이 렌더링되지 않는다.
2. 빈 상태의 시작 설명은 `WorkspaceStartPanel` 한곳에만 존재한다.
3. TXT 불러오기 성공 직후 기존 작업 셸이 나타나고 첫 미완료 대사가 자동 선택된다.
4. 작업 단계별 주요 CTA는 시각적으로 하나만 강조된다.
5. 기존 TXT 불러오기, 저장, OCR, 인페인팅, 번역 수정, 내보내기 동작은 변경되지 않는다.
6. `npm run typecheck`, `npm test`, `npm run build`가 통과한다.
7. 1280×720과 1440×900에서 잘림, 겹침, 불필요한 가로 스크롤이 없다.

## 제외 범위

- 모바일 또는 태블릿 전용 UI 개선
- 프로젝트 파일 형식과 저장 정책 변경
- 새로운 패키지 추가
- OCR 및 인페인팅 동작 변경
- 최근 프로젝트 목록이나 파일 드래그 앤 드롭 추가
- 작업 패널의 대규모 구조 개편
