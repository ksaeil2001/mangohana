# Gemini API 키 암호화 저장 설계

## 목표

사용자가 Gemini API 키를 한 번 입력하면 앱을 다시 실행해도 재입력하지 않도록 한다. 키는 Electron 메인 프로세스에서만 취급하고 Windows 사용자 계정에 묶인 암호화를 사용한다. 암호화를 사용할 수 없거나 복호화에 실패하면 평문 저장으로 우회하지 않는다.

## 범위

- Electron `safeStorage`로 API 키를 암호화한다.
- 암호문은 Electron의 앱별 `userData` 아래 전용 설정 경로에 저장한다.
- 앱 시작 시 암호문을 복호화해 현재 런타임의 `process.env.GEMINI_API_KEY`에 적용한다.
- 설정 화면에서 저장 상태, 저장 방식, 재입력 필요 여부를 사용자에게 알린다.
- 사용자가 `키 삭제`를 누르면 저장된 암호문과 현재 런타임 키를 제거한다.
- 기존 OCR 및 Gemini 호출부가 `process.env.GEMINI_API_KEY`를 읽는 동작은 유지한다.

다음 항목은 범위 밖이다.

- 클라우드 동기화 또는 여러 Windows 계정 간 키 공유
- 프로젝트 파일에 API 키 또는 암호문 포함
- 키 자체를 렌더러로 다시 보내거나 화면에 재표시
- 새 패키지 또는 네이티브 의존성 추가

## 사용자 동작

### 최초 저장

1. 사용자가 설정 화면의 비밀번호 입력란에 키를 입력한다.
2. 렌더러는 기존 IPC를 통해 키를 메인 프로세스에 전달한다.
3. 메인 프로세스는 키 형식을 검증하고 즉시 현재 세션에 적용한다.
4. `safeStorage`가 사용 가능하면 키를 암호화해 저장한다.
5. 성공 시 입력란을 비우고 `Gemini API 키 암호화 저장됨`을 표시한다.

### 앱 재실행

1. `app.whenReady()` 이후 키 저장소를 초기화한다.
2. 이미 비어 있지 않은 `GEMINI_API_KEY` 환경변수가 있으면 그 값을 우선 사용한다. 환경변수 값은 자동으로 디스크에 저장하지 않는다.
3. 환경변수가 없으면 저장된 암호문을 읽고 복호화한다.
4. 복호화에 성공하면 그 실행에 한해 `process.env.GEMINI_API_KEY`에 적용한다.
5. 렌더러에는 키가 아니라 상태 정보만 전달한다.

### 삭제

1. 저장된 암호문 삭제를 먼저 시도한다.
2. 삭제가 성공하거나 저장 파일이 이미 없으면 현재 런타임 키를 제거한다.
3. 파일 삭제가 실패하면 키가 삭제됐다고 표시하지 않고 오류를 반환하며 현재 구성 상태를 유지한다. 사용자는 삭제를 다시 시도할 수 있다.
4. 외부 환경변수로 제공된 키는 앱이 원본 환경을 수정할 수 없으므로, 상태 문구로 환경변수 사용 중임을 명확히 알린다.

## 아키텍처

### 메인 전용 저장소

`src/main/geminiApiKeyStore.ts`를 추가한다. 이 모듈만 Electron `safeStorage`와 키 저장 파일을 다룬다.

- 저장 위치: `app.getPath('userData')` 아래 API 키 전용 설정 하위 경로
- 저장 내용: `safeStorage.encryptString()`이 반환한 암호문만 저장
- 복호화: `safeStorage.decryptString()`을 메인 프로세스에서만 호출
- 쓰기: 임시 파일에 암호문을 쓴 뒤 같은 디렉터리에서 교체하여 중간 쓰기 실패로 파일이 손상될 가능성을 줄임
- 금지: 평문 파일, `localStorage`, 프로젝트 JSON, 렌더러 상태, 로그에 키 저장

저장소는 파일 시스템과 암호화 기능을 주입받도록 만들어 단위 테스트가 실제 Windows 자격 증명이나 실제 사용자 설정 디렉터리를 건드리지 않게 한다.

### 초기화 순서

`electron/main.ts`에서 `app.whenReady()` 이후 저장소를 생성하고 초기 복원을 완료한 다음 IPC를 등록하고 창을 연다. 이 순서로 첫 OCR 요청 전에 런타임 키가 준비되도록 한다.

환경변수 우선순위는 다음과 같다.

1. 앱 시작 시 외부에서 전달된 `GEMINI_API_KEY`
2. 암호화 저장소에서 복원한 키
3. 현재 세션에서만 입력한 키
4. 구성되지 않음

외부 환경변수는 저장소에 복사하지 않는다.

### IPC 경계

기존 `getGeminiApiKeyStatus`, `setGeminiApiKey`, `clearGeminiApiKey` IPC를 유지하되 저장소 의존성을 주입한다. 키 값은 설정 요청에서 메인 방향으로만 이동한다. 상태 응답은 다음 의미만 포함한다.

```ts
type GeminiApiKeyStatus = {
  configured: boolean;
  source: 'none' | 'environment' | 'encrypted' | 'session';
  persistence: 'encrypted' | 'session-only' | 'unavailable';
  requiresReentry: boolean;
};
```

- `source`는 현재 실행에서 어떤 키를 쓰는지 나타낸다.
- `persistence`는 재실행 후 복원 가능 여부를 나타낸다.
- `requiresReentry`는 손상된 저장 데이터 등으로 사용자가 다시 입력해야 하는지를 나타낸다.
- 키 원문, 암호문, 저장 경로는 응답이나 오류에 포함하지 않는다.

## 실패 처리

### 암호화를 사용할 수 없음

`safeStorage.isEncryptionAvailable()`이 `false`이면 평문 저장을 하지 않는다. 입력한 키는 현재 세션에서만 사용하고 `암호화 저장을 사용할 수 없어 이번 실행에서만 사용됩니다`를 표시한다. 상태는 `source: 'session'`, `persistence: 'unavailable'`이다.

### 저장 실패

암호화 또는 파일 쓰기가 실패해도 이미 검증된 키는 현재 세션에서 사용할 수 있다. 저장 성공으로 표시하지 않고 세션 전용 경고를 보여 준다. 오류에는 키, 암호문, 전체 저장 경로를 노출하지 않는다.

### 복호화 실패 또는 손상된 파일

저장된 키를 적용하지 않는다. 손상된 암호문은 이후 매 실행마다 같은 오류가 반복되지 않도록 제거를 시도하고, 상태를 `configured: false`, `requiresReentry: true`로 반환한다. 정리 실패 여부는 내부 원인을 노출하지 않는 일반화된 재입력 안내에 포함한다.

### 삭제 실패

암호문 삭제에 실패하면 성공 상태로 전환하지 않는다. 현재 런타임 키와 구성 상태를 유지하고 `저장된 키를 삭제하지 못했습니다. 다시 시도해 주세요`를 표시한다.

## UI 문구

- 암호화 저장 성공: `Gemini API 키 암호화 저장됨`
- 환경변수 우선 사용: `환경변수의 Gemini API 키 사용 중`
- 세션 전용: `암호화 저장을 사용할 수 없어 이번 실행에서만 사용됩니다`
- 재입력 필요: `저장된 키를 복원하지 못했습니다. Gemini API 키를 다시 입력해 주세요`
- 삭제 실패: `저장된 키를 삭제하지 못했습니다. 다시 시도해 주세요`

비밀번호 입력란은 저장 요청 후 항상 비우며, 저장된 키를 다시 채우거나 일부 문자열로 표시하지 않는다.

## 보안 기준

- 렌더러는 저장된 키를 읽을 수 없다.
- 키와 암호문을 콘솔, 오류 메시지, 테스트 스냅샷에 기록하지 않는다.
- 평문 폴백은 없다.
- Windows에서는 Electron `safeStorage`가 사용하는 OS 보호 기능에 암호화를 맡긴다.
- 저장 파일만 다른 PC나 Windows 사용자 계정으로 복사해도 키를 복호화할 수 있다는 보장은 없다.
- 저장 기능은 로컬 사용자 계정의 보안을 보완하지만, 이미 해당 Windows 세션을 완전히 장악한 공격자로부터 실행 중인 키까지 보호하는 수단은 아니다.

## 테스트 계획

### 저장소 단위 테스트

- 파일에 기록된 데이터에 평문 API 키가 포함되지 않는다.
- 암호화 저장 후 새 저장소 인스턴스에서 키를 복원한다.
- 암호화 미지원 시 파일을 만들지 않고 세션 전용 결과를 반환한다.
- 손상된 암호문을 적용하지 않고 재입력 상태를 반환한다.
- 저장 파일 삭제 후 다음 초기화에서 키가 복원되지 않는다.
- 파일 삭제 실패 시 성공 결과를 반환하지 않는다.

### 메인 및 IPC 테스트

- 외부 환경변수가 암호화 저장 키보다 우선한다.
- 외부 환경변수는 자동 저장되지 않는다.
- 저장 성공, 세션 전용, 환경변수, 재입력 상태가 정확히 반환된다.
- 상태 및 오류 응답에 API 키나 암호문이 포함되지 않는다.
- 기존 키 유효성 검사와 OCR 호출 경로가 유지된다.

### 렌더러 테스트

- 상태별 안내 문구가 정확히 표시된다.
- 저장 요청 후 입력값이 비워진다.
- 저장된 키가 입력란에 다시 표시되지 않는다.
- 삭제 실패 시 구성됨 상태를 거짓으로 해제하지 않는다.

### 최종 검증

- 타입 검사, 전체 테스트, 빌드를 실행한다.
- Electron 앱을 재시작해 암호화 저장 키가 복원되는지 확인한다.
- 키 삭제 후 다시 시작했을 때 복원되지 않는지 확인한다.
- 가능한 경우 외부 환경변수 우선 동작과 암호화 미지원 모의 테스트를 확인한다.

## 변경 예상 파일

- `src/main/geminiApiKeyStore.ts`: 암호화 저장소 신규 추가
- `electron/main.ts`: 앱 준비 후 저장소 초기화 및 IPC 주입
- `src/main/ipcHandlers.ts`: 저장·삭제·상태 IPC를 저장소와 연결
- `src/renderer/electronApi.ts`: 상태 타입 확장
- `src/renderer/components/ProjectActionsPanel.tsx`: 저장 상태와 실패 안내 반영
- 관련 main, integration, renderer 테스트: 보안 및 복원 시나리오 추가

새 패키지, 데이터베이스, 프로젝트 파일 형식 변경은 필요하지 않다.

## 완료 조건

- 한 번 암호화 저장한 키가 같은 Windows 사용자 계정의 다음 앱 실행에서 자동 복원된다.
- 평문 키가 디스크, 렌더러 저장소, IPC 상태 응답, 로그에 남지 않는다.
- 환경변수 우선순위가 유지되고 환경변수 값은 자동 저장되지 않는다.
- 암호화 미지원, 손상, 저장 실패, 삭제 실패가 거짓 성공 없이 사용자에게 안내된다.
- 사용자는 언제든 `키 삭제`로 저장된 키를 제거할 수 있다.
- 기존 Gemini OCR 기능과 세션 키 입력 기능이 계속 작동한다.
