# 망고하나 전면 재설계 구현 계획

> 승인된 설계에 따라 현재 작업 트리에서 구현한다. 기존 사용자 변경을 보존하고 커밋·배포는 하지 않는다.

**목표:** 기존 Trio 기능과 프로젝트 데이터를 유지하면서 실제 Electron 앱의 이름, 화면, 조작 흐름을 망고하나로 교체한다.

**구조:** 기존 Main의 세션·저장·복구·검증과 Renderer의 작업 핸들러를 유지하고, 확인 상태와 명시적 편집 상태를 분리한다. 배경 정리의 사용자 확인은 기술적 QA 결과와 별도로 현재 자산에 연결한다.

**기술:** Electron, React, TypeScript, 기존 CSS와 Vitest. 새 의존성은 추가하지 않는다.

**승인된 설계:** `artifacts/mangohana-design-20261029/README.md` 및 사용자가 제공한 첨부 문서.

## 공통 조건

- 원본 이미지, 기존 `.ctp`·sidecar, 암호화, 복구 후보, 세션 소유권 및 비동기 결과 검증을 보존한다.
- 페이지·대상 선택과 처리 상태 변경만으로 편집기나 상세가 열리지 않는다. 패널을 닫아도 초안을 폐기하거나 확정하지 않는다.
- 사용자 확인, AI 제안, 기술적 QA, 저장, 출력은 각각 구분한다. 기존 출력 검사와 실패 처리를 약화하지 않는다.
- 좁은 창에서도 이미지 전체와 주요 행동을 유지하고 키보드·포커스·IME를 보존한다. 테스트 데이터와 실제 제공자 결과를 구분한다.
- 현재 dirty 파일과 생성물, 설정, 자격 증명, 사용자 프로젝트를 덮어쓰지 않는다. 배포 이름·업데이트 경로는 별도 호환성 검증 없이 바꾸지 않는다.

## 검토할 실패 조건

- 프로젝트를 바꾸거나 늦은 처리 결과가 도착해도 이전 세션의 선택·결과·초안이 새 프로젝트에 반영되지 않는다.
- OCR 미적용 초안과 번역 사용자 수정이 도구 닫기, 대상 이동, 재실행 및 저장·재열기에서 조용히 소실되지 않는다.
- 확인한 배경 결과가 바뀌면 A→B→A를 포함해 사용자 확인을 무효화하고, 원본 출력과 기존 QA 차단을 보존한다.
- AI 제안만 확인된 대사는 사용자 명시 채택과 출력 준비를 구분하고 기존 사용자 번역을 덮어쓰지 않는다.
- 이미지 표시 면적·종횡비·키보드 접근을 실제 창 크기에서 검증하며, 부분 출력이나 제공자 미실행을 성공으로 표시하지 않는다.

## 작업 3: 배경 정리 결과의 사용자 확인

**수정 대상:** `src/shared/projectTypes.ts`, `projectValidation.ts`, `inpainting.ts`, 처리 결과·출력 계약, `src/main/projectSessions.ts`, `projectReplay.ts`, `ipcHandlers.ts`, `projectImageExport.ts`, preload/renderer API 및 해당 테스트.

- [ ] 선택적 `userReviewedCleanedAssetId`를 현재 cleaned 자산과 연결하고, 세션 소유권·기대 revision·자산 무결성을 Main에서 검증하는 명시적 확인 경로를 만든다.
- [ ] 클릭 시 session·page·asset·revision을 고정한다. 확인은 일반 pending mutation에 넣지 않고 Main의 세션 작업과 원자적 저장으로 기록하며, 기존 미저장 편집은 보존한다.
- [ ] 새 결과 채택·되돌리기 등 자산 변경의 모든 경로에서 확인을 무효화한다. 기존 파일의 필드 부재는 유효한 미확인 상태로 취급한다.
- [ ] 실제 로드된 cleaned 자산의 identity를 확인하고, 원본 대체·실패·늦은 로드나 비교 결과 로드 실패는 확인을 허용하지 않는다.
- [ ] cleaned 직접 출력과 cleaned를 쓰는 식자 출력 각각에서 기존 QA, 현재 자산의 사용자 확인, 안전한 경로 및 실제 파일 해시를 확인한다. 폴더 선택 후 현재 상태를 재검증하고 원본 출력과 페이지별 부분 실패를 유지한다.
- [ ] 일반·암호화 `.ctp`, 청크, 저장·재열기·복구, 이전 파일, A→B→A, 오래된 revision 및 다른 세션, 부분 출력 실패를 격리된 데이터로 검증한다.
