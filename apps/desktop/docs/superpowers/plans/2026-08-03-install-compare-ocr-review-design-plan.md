# Trio 설치·비교·OCR 예외 검토 디자인 계획

> 작성일: 2026-08-03
> 상태: `TRIO-UI-12`까지 완료
> 제품 코드 변경: 환경 준비 상태 계약·화면·승인된 IPC 구현 완료
> 연결 계획: `2026-08-03-carrot-local-model-integration-plan.md`

## 1. 한 문장 정의

> 반디뷰처럼 이미지를 크게 보고 빠르게 넘길 수 있으면서, 필요한 순간에만 전문 편집 도구가 나타나는 사람 검수 중심의 만화 번역 작업대.

이번 계획은 Trio 전체 기능을 다시 늘어놓는 문서가 아니다. Carrot 계열 로컬 처리 기능을 도입할 때 새로 필요해지는 **설치·모델 관리**, **원본·결과 비교**, **OCR 예외 검수** 세 표면이 위 정의를 훼손하지 않도록 정보 구조와 상호작용 계약을 확정한다.

## 2. 검토 범위와 비범위

### 포함

- 최초 환경 준비와 이후 모델·실행 파일 상태 관리
- 구성요소별 다운로드·검증·설치·복구·업데이트 상태
- 원본, 인페인팅, 번역 미리보기의 즉시 비교
- 단일 보기, 좌우 분할, 드래그 비교선, 투명도 비교, 누르는 동안 원본 보기
- OCR 예외 큐에서 이미지 위치와 편집기로 한 번에 이동
- 원문 OCR 영역과 한국어 식자 영역의 시각적·상태적 분리
- AI 제안, 사용자 수정, 사용자 확정의 소유권 표시
- Windows 데스크톱 크기별 패널 축소와 키보드·포커스 접근성

### 포함하지 않음

- 제품 코드 구현
- 모델, 런타임 또는 패키지 실제 다운로드
- 패키지 추가와 잠금 파일 변경
- 프로젝트 저장 스키마, IPC, 인증·보안, 배포 설정 변경
- 스마트폰용 정밀 편집 UI
- Carrot UI의 색상·레이아웃 복제
- OCR·번역·인페인팅 알고리즘 자체의 품질 변경

## 3. 현재 시스템 감사

### 재사용 가능한 기반

- `FocusDeckShell`은 좌측 페이지, 우측 편집기, 하단 결과 패널을 각각 접을 수 있고 집중 모드를 지원한다.
- `ResizableWorkspace`는 중앙 캔버스를 우선하고 오른쪽 편집기 너비를 조절한다.
- `PageImagePanel`에는 확대·축소·이동·맞춤·실제 크기 조작이 이미 있다.
- `imageViewport` 상태에는 원본·OCR·원문·번역·최종 레이어 개념이 일부 존재한다.
- `IssueLinePanel`과 OCR 검토 패널은 문제 목록과 후보 편집의 출발점으로 재사용할 수 있다.
- 현재 전역 단축키는 텍스트 입력 중에는 작동하지 않도록 방어하고 있다.

### 계획에서 해결해야 하는 간극

1. `ToolDrawer`는 배경을 덮고 작업 영역을 비활성화하므로 이미지 중심의 기본 도구 표면으로 부적합하다.
2. 원본·OCR 외 비교 레이어는 상태 이름만 있고 실제 보기와 조작은 연결되지 않았다.
3. 현재 OCR 강조는 단일 OCR 상자 중심이며 말풍선 외곽, 안전 영역, 한국어 식자 상자, 보존 요소를 구분하지 못한다.
4. 문제 목록 선택이 페이지 이동, 영역 중앙 정렬, 편집기 전환까지 원자적으로 수행되지 않는다.
5. AI 제안과 사용자 확정의 시각 상태 및 재실행 보호 계약이 부족하다.
6. 기존 문서의 모바일 레이아웃과 밝은 보조 패널 방향은 Windows 전문 작업대라는 최신 결정과 충돌한다.
7. 설치 화면의 위치·밀도·오류 복구 상태가 기존 디자인 문서에 정의되어 있지 않다.

### 검토 전 점수

**6/10.** 이미지 중심 셸과 뷰어 조작의 기초는 있으나, 이번 세 표면의 정보 구조·상태·직접 조작·접근성 계약이 구현 가능한 수준으로 닫히지 않았다.

### 6.2 공간 우선순위

1. 이미지 스테이지는 남은 공간을 모두 차지한다.
2. 상단 명령 바는 한 줄, 높이 36~44px 범위의 조밀한 도구 모음으로 유지한다.
3. 좌측 페이지 패널은 기본 176~224px, 접힌 상태는 28~36px 가장자리 버튼만 남긴다.
4. 오른쪽 편집기는 기본 360~420px, 조절 범위 320~520px를 유지한다.
5. 하단 문제 큐는 기본 160~220px이며 접히면 한 줄 상태 표시만 남긴다.
6. 패널을 모두 숨기면 상단 바를 제외한 영역 대부분이 이미지가 된다.
7. 팝업은 파일 선택, 파괴적 확인, OS 권한처럼 작업 중단이 필요한 경우에만 허용한다.

### 6.3 크기별 정책

| 유효 너비 | 정책 |
|---|---|
| 1440px 이상 | 페이지 + 이미지 + 편집기 + 하단 큐 동시 사용 가능 |
| 1200~1439px | 페이지 목록을 먼저 축소하고 이미지·편집기·하단 큐 유지 |
| 1024~1199px | 보조 패널 하나만 열고 나머지는 가장자리 상태 버튼으로 축소 |
| 1024px 미만 | 이미지 열람은 허용하되 정밀 편집 시작 시 창 확대 안내 |

세로 공간이 부족할 때는 하단 큐를 먼저 한 줄로 접는다. 이미지 스테이지의 최소 조작 영역보다 보조 패널을 우선하지 않는다.

### 7.2 행 정보 계약

각 행은 다음 정보만 한 줄에 우선 표시한다.

- 표시 이름과 용도
- 현재 상태와 단계별 진행률
- 설치된 버전 또는 설치 예정 compatibility set
- 내려받을 용량과 설치 후 예상 용량
- 현재 가능한 한 개의 주 작업
- 세부 정보 메뉴: 공식 출처, 라이선스, SHA 검증, 설치 경로, 진단 코드

큰 설명 카드, 마케팅 문구, 장식용 일러스트, 그라데이션은 사용하지 않는다.

### 7.3 상태 모델

| 상태 | 기본 표시 | 가능한 작업 | 작업대 영향 |
|---|---|---|---|
| `checking` | 환경 확인 중 | 취소하지 않음, 세부 상태 | 이미지 열람 가능 |
| `queued` | 다운로드 대기 | 순서 변경, 제외 불가인 필수 표시 | 준비된 기능만 사용 |
| `downloading` | 진행률·속도·잔여량 | 일시정지 | 준비된 기능만 사용 |
| `paused` | 일시정지됨 | 계속, 취소 | 부분 파일 보존 |
| `verifying` | 서명·SHA 검증 중 | 세부 정보 | 해당 기능 비활성 |
| `installing` | 압축 해제·등록 중 | 안전한 경우만 취소 | 해당 기능 비활성 |
| `ready` | 준비됨 | 업데이트 확인, 설치 위치 열기 | 기능 활성 |
| `update-available` | 업데이트 가능 | 지금 업데이트, 나중에 | 기존 버전 사용 가능 |
| `repairable` | 복구 필요 | 이어받기, 다시 검증, 재설치 | 다른 기능은 유지 |
| `blocked` | 사용 불가 | 원인별 해결 작업 | 해당 기능만 차단 |

### 7.4 점진적 진입 규칙

- 기본 런타임과 이미지 열람이 준비되면 `작업대 먼저 열기`를 활성화한다.
- OCR이 준비되지 않았으면 OCR 버튼을 숨기지 않고 `설치 중 68%` 상태로 비활성화한다.
- 번역 또는 인페인팅만 실패해도 다른 준비된 기능을 차단하지 않는다.
- 작업대 상단의 상태 표시는 가장 심각한 한 상태만 보여주고, 펼치면 구성요소별 상태를 보여준다.
- 업데이트는 기존 정상 버전을 유지한 채 staging에서 검증하고 원자적으로 전환한다.
- 모델 제거·저장소 이동처럼 파괴 가능성이 있는 작업은 별도 확인과 영향 범위를 표시한다.

### 7.5 설치 오류 문구

오류 문구는 `실패했습니다`로 끝내지 않는다.

```text
PaddleOCR 설치 파일의 SHA-256이 카탈로그 값과 다릅니다.
손상된 임시 파일은 격리되었으며 기존 설치는 유지됩니다.
[다시 다운로드] [공식 출처 보기] [진단 코드 복사]
```

로그에는 이미지 내용, OCR 원문, 번역문, 사용자 경로 전체를 기록하지 않는다.

## 8. 원본·결과 비교 화면

### 8.1 단일 캔버스 계약

원본, 인페인팅, 번역 레이어는 같은 페이지 좌표계와 하나의 viewport transform을 공유한다.

```ts
type ResultLayer = "original" | "inpainted" | "translated";
type ComparisonMode = "single" | "split" | "reveal" | "opacity";
```

레이어 또는 비교 방식을 바꿔도 다음 상태를 바꾸지 않는다.

- 확대율
- 이미지 이동 위치
- 현재 페이지
- 선택된 대사·문제·오버레이
- 오른쪽 편집기와 하단 큐 상태
- 분할선의 이미지 좌표 기준 위치

### 8.2 조작 표면

```text
[원본] [인페인팅] [번역]    [비교 ▾]    100%   맞춤
                                  ├ 단일 보기
                                  ├ 좌우 분할
                                  ├ 드래그 비교선
                                  └ 투명도
```

- `single`: 선택한 한 레이어를 전체 표시한다.
- `split`: 원본과 선택 결과를 같은 transform으로 좌우에 표시한다.
- `reveal`: 하나의 이미지 위에서 비교선을 드래그해 원본과 결과 경계를 바꾼다.
- `opacity`: 결과 레이어의 투명도를 조절해 원본과 겹쳐 본다.
- `Backslash` 키를 누르고 있는 동안 원본을 표시하고 놓으면 직전 상태로 돌아간다.
- 텍스트 입력, 숫자 입력, 콤보박스, contenteditable에 포커스가 있으면 비교 단축키가 작동하지 않는다.
- 키를 놓는 이벤트를 창이 잃어도 원본 고정 상태가 남지 않도록 `blur`에서 복구한다.

### 8.3 사용 가능 상태

| 조건 | 표시 |
|---|---|
| 결과 없음 | 레이어 버튼 유지, `아직 생성되지 않음` 설명, 생성 작업으로 연결 |
| 처리 중 | 기존 레이어를 계속 표시하고 상태 배지만 갱신 |
| 최신 결과 | 정상 선택 가능 |
| 원본 변경 후 오래된 결과 | `이전 원본 기준` 경고, 기본 적용 금지 |
| 부분 실패 | 성공한 영역은 표시, 실패 영역은 문제 오버레이로 이동 가능 |
| 렌더링 실패 | 원본 자동 복귀, 확대·이동 상태 유지, 재시도 제공 |

### 8.4 비교 모드 접근성

- 활성 레이어와 비교 방식은 버튼의 선택 상태, 텍스트, 아이콘을 함께 사용한다.
- 비교선은 마우스 드래그뿐 아니라 키보드 화살표로도 이동할 수 있다.
- 투명도 값은 숫자로 읽히며 5% 단위 키보드 조절을 제공한다.
- 분할 화면에서도 두 이미지에 같은 페이지 설명과 레이어 이름을 제공한다.
- 빠른 깜박임 애니메이션을 사용하지 않는다.

### 9.2 문제 선택의 원자적 동작

문제 행을 클릭하거나 다음 문제 명령을 실행하면 아래 동작을 하나의 전환으로 처리한다.

1. 해당 페이지로 이동한다.
2. 페이지 이미지와 연결된 레이어를 준비한다.
3. 문제 영역이 패널에 가리지 않는 캔버스 안전 영역 중앙에 오도록 이동한다.
4. 문제의 실제 크기를 볼 수 있는 최대 확대율까지 맞추되 사용자가 더 크게 확대한 상태는 임의로 축소하지 않는다.
5. 관련 OCR·식자·인페인팅 오버레이를 선택한다.
6. 오른쪽 편집기가 고정되지 않았으면 문제 종류에 필요한 섹션을 연다.
7. 고정되었으면 현재 편집기를 유지하고 `필요한 편집기 열기` 안내를 표시한다.
8. 목록에서 현재 행과 전체 순번을 갱신한다.
9. 수정 가능한 첫 필드가 아니라 편집기 제목에 먼저 포커스를 보내 화면 낭독 사용자가 문맥을 들은 뒤 입력으로 이동할 수 있게 한다.

페이지 이동이나 결과 로딩이 실패하면 이전 선택과 viewport를 유지하고 실패 원인을 하단 행 안에서 표시한다.

### 9.3 문제 분류와 편집기 연결

| 텍스트 누락 의심 | OCR | OCR 후보, 주변 텍스트 영역 |
| OCR 신뢰도 낮음 | OCR | 원문 OCR 상자 |
| 텍스트 유형 불확실 | 유형 | 원문 OCR, 컨테이너 |
| 화자 불확실 | 화자 | 원문 OCR, 화자 연결선 |
| 읽기 순서 불확실 | 순서 | 번호·방향 연결선 |
| 직역 의심 | 번역 | 원문 OCR, 한국어 식자 |
| 공간 초과 | 식자 | 안전 영역, 한국어 식자 |

### 9.4 원문 분석과 최종 식자 분리

말풍선이 있는 경우:

```text
OCR region       원문을 어디서 읽었는지
container        말풍선의 전체 외곽과 꼬리·테두리
safe area        한국어가 들어갈 수 있는 내부 공간
preserve region  기호·효과음·그림 등 지워서는 안 되는 요소
typeset box      실제 한국어 가로쓰기 편집 영역
```

말풍선이 없는 경우:

- 원문 텍스트 범위는 출발점일 뿐 최종 상자로 재사용하지 않는다.
- 주변 확장 가능 영역과 얼굴·중요 그림 충돌 금지 영역을 함께 표시한다.
- 한국어 길이에 맞는 새 식자 상자를 만들고 사용자가 이동·크기·회전을 수정한다.

### 9.5 한국어 식자 규칙의 화면 표현

- 원문 세로쓰기 방향과 OCR 열 순서를 작은 방향 표시로 보여준다.
- 한국어 식자는 기본 가로쓰기이며 줄은 위에서 아래로 진행한다.
- 자동 줄바꿈의 의미 단위·어절 단위를 미리보기와 함께 보여준다.
- 조사 단독 행, 지나치게 불균형한 줄, 최소 글자 크기 위반을 문제로 표시한다.
- 자동 맞춤이 최소 글자 크기 아래로 내려가면 더 줄이지 않고 공간 초과로 전환한다.
- 텍스트 박스 핸들로 이동, 폭·높이, 회전, 글자 크기, 행간, Stroke를 직접 수정한다.

## 10. 오버레이 디자인 시스템

색상은 앱 크롬의 장식이 아니라 분석 정보를 구분하는 제한된 의미 색으로만 사용한다.

| 레이어 | 선·채움 | 라벨 | 선택 상태 |
|---|---|---|---|
| 원문 OCR | 짧은 점선, 무채색에 가까운 청록 | `OCR` | 선명한 청록 + 모서리 표식 |
| 말풍선 외곽 | 가는 실선 | `말풍선` | 두께 증가, 꼬리 연결점 표시 |
| 내부 안전 영역 | 안쪽 점선 | `안전 영역` | 간격 유지, 반투명 내부 표시 |
| 한국어 식자 | 실선 + 조절 핸들 | `식자` | 주 강조색 + 핸들 |
| 인페인팅 마스크 | 반투명 채움 | `마스크` | 브러시 경계 표시 |
| 보존 요소 | 사선 무늬 | `보존` | 대비 증가, 잠금 표식 |
| 문제 | 외곽 경고선 | 문제 종류 | 선택 문제만 지속 표시 |

### 혼잡도 제어

1. 기본은 현재 선택과 관련된 레이어만 선명하게 표시한다.
2. 비관련 레이어는 낮은 대비로 낮추거나 숨긴다.
3. 확대율이 낮아 라벨이 겹치면 라벨 대신 작은 기호를 표시한다.
4. 선택 항목은 색상뿐 아니라 선 두께·핸들·라벨로 식별한다.
5. `모든 오버레이 숨기기`는 분석 데이터를 삭제하지 않고 보기만 끈다.
6. 비교 모드에서도 오버레이는 같은 이미지 좌표에 유지하며 원본 보기 중에는 필요에 따라 일시적으로 흐리게 한다.

## 11. AI 제안과 사용자 소유권

### 상태

| 상태 | 의미 | 재실행 정책 | 표시 |
|---|---|---|---|
| `ai-proposed` | AI가 제안했고 사용자가 수정하지 않음 | 새 제안으로 갱신 가능 | `AI 제안` + 신뢰도 |
| `user-edited` | 자동 저장된 사용자 초안 | 사용자 값 보호, 새 AI 결과는 비교 후보 | `사용자 수정` |
| `user-confirmed` | 사용자가 명시적으로 확정 | AI가 덮어쓰지 못함 | 잠금 표식 + `사용자 확정` |
| `stale-confirmed` | 원본 변경으로 검토 필요 | 값은 유지, 재확정 요구 | `원본 변경 후 재검토` |

신뢰도는 정답처럼 한 숫자만 크게 표시하지 않는다. 상위 후보와 근접 후보를 함께 보여준다.

```text
텍스트 유형
생각 47%   독백 41%   대사 12%
사용자 확인 필요
```

사용자 수정은 입력 즉시 초안으로 저장한다. `확정하고 다음`을 눌러야 확정 잠금과 다음 문제 이동이 함께 실행된다. 보류는 수정 초안을 유지하고 확정하지 않은 채 다음 문제로 이동한다.

## 12. 오른쪽 편집기의 문맥 전환과 고정

- 기본 상태에서는 선택한 대상과 문제 종류를 따라 필요한 섹션으로 자동 전환한다.
- 사용자가 핀을 켜면 현재 편집기를 유지한다.
- 고정 중 필요한 도구가 다르면 이미지 이동과 문제 선택은 수행하되 상단에 비차단 안내를 표시한다.
- 고정 상태는 프로젝트가 아니라 현재 작업 세션 UI 선호로 저장한다.
- 아무 대상도 선택하지 않았을 때는 기능 목록 대신 `이미지 또는 문제를 선택하세요`와 현재 단계의 한 가지 다음 행동만 보여준다.

```text
📌 번역 편집기 고정됨
선택한 문제에는 OCR 편집기가 필요합니다.  [OCR 열기]
```

## 13. 복원과 지속성

앱 재실행 시 다음 UI 상태를 복원한다.

- 마지막 프로젝트와 현재 페이지
- 선택된 대사 또는 문제 ID
- 확대율과 이미지 이동 위치
- 활성 결과 레이어와 비교 방식·비교선·투명도
- 좌·우·하단 패널 열림 상태와 오른쪽 패널 너비
- 오른쪽 편집기 고정 상태
- 자동 저장된 사용자 수정 초안

복원 데이터가 현재 프로젝트 revision과 맞지 않으면 선택과 viewport만 안전하게 초기화하고 프로젝트 내용은 변경하지 않는다. 앱이 충돌한 뒤에는 `복원됨`을 한 번만 알리며 별도 모달을 띄우지 않는다.

## 14. 키보드와 포커스 계약

현재 존재하는 `Space = OCR 실행`, `←/→ = 페이지`, `↑/↓ = 선택 이동`, `Escape = 패널 닫기`, `Ctrl+Enter = 주 작업`의 의미는 구현 전 충돌 테스트에서 보존한다.

추가 비교 계약:

- `Backslash` 누름/놓음: 누르는 동안 원본, 놓으면 이전 비교 상태
- 비교선 포커스 + `←/→`: 비교선 이동
- 투명도 슬라이더 + `←/→`: 5% 단위 조절

공통 규칙:

- 입력 필드, 셀렉트, contenteditable 안에서는 전역 뷰어 단축키를 실행하지 않는다.
- 키보드 이동 뒤 포커스 링을 숨기지 않는다.
- 패널을 닫으면 포커스를 패널을 연 버튼 또는 이미지 스테이지로 되돌린다.
- 문제 이동 시 새 문맥을 알린 후 편집 필드로 이동할 수 있게 한다.
- 동일한 기능을 포인터와 키보드 양쪽에서 수행할 수 있다.
- OS 고대비 모드에서도 선택·오류·확정 상태가 색상 하나로 사라지지 않아야 한다.

## 15. 시각 언어

- 전체 작업 공간은 어두운 중립색을 사용하고 만화 흰색 페이지와 충분히 분리한다.
- 보조 패널도 어두운 계열 또는 낮은 대비 중립색으로 연결해 캔버스 주변에 밝은 큰 덩어리를 만들지 않는다.
- 경계선은 1px 중심, 모서리 반경은 2~4px 중심으로 제한한다.
- 주 강조색은 현재 선택과 주 작업에만 사용한다.
- 오류색은 실제 조치가 필요한 상태에만 사용하고 장식용 배지에 남용하지 않는다.
- 제목은 도구 모음 수준의 크기를 유지하고 영웅형 제목을 사용하지 않는다.
- 큰 카드, 과도한 여백, 글래스모피즘, 그라데이션, 떠다니는 마케팅형 CTA를 금지한다.
- v1에서는 새 글꼴 패키지를 추가하지 않고 현재 Windows 친화적 UI 글꼴 체계를 유지한다.

## 16. 빈 상태·로딩·오류 상태

| 표면 | 빈 상태 | 로딩 상태 | 오류 상태 |
|---|---|---|---|
| 환경 준비 | 구성요소 검사 시작 | 행별 진행 + 전체 진행 | 실패한 행만 복구, 정상 행 유지 |
| 비교 | 결과가 아직 없음 | 기존 레이어 유지 + 처리 표시 | 원본 복귀 + transform 유지 |
| 문제 큐 | `현재 필터에 문제가 없습니다` | 기존 목록 유지 + 갱신 표시 | 해당 소스만 재시도 |
| OCR 편집기 | 선택 없음, 다음 행동 한 개 | 선택 유지 + 읽기 전용 | 초안 보존 + 오류 원인 |
| 이미지 | 프로젝트 이미지 없음 | 이전 페이지를 임의 표시하지 않음 | 다시 연결, 경로 정보 최소화 |

로딩 스피너만 표시하지 않는다. 어떤 구성요소가 무엇을 하고 있는지 짧은 동사로 표시한다. 실패 시 사용자가 수정한 초안이나 마스크를 버리지 않는다.

## 17. 구현 단계

### UI-00 — 기준선과 상태 계약

목표: 현재 동작을 보존하는 테스트를 먼저 고정한다.

- 현재 셸, 전역 단축키, 이미지 transform, OCR 적용, 인페인팅 적용 테스트를 확인한다.
- `ResultLayer`, `ComparisonMode`, 오버레이 종류, AI 소유권 상태의 UI 계약을 shared 또는 renderer 경계에 정의한다.
- 패키지 추가 없이 구현 가능한지 확인한다.
- 기존 `ToolDrawer`와 OCR 모달은 즉시 삭제하지 않고 새 진입점이 안정화될 때까지 호환 경로로 둔다.

완료 조건:

- 기존 테스트가 통과하고 새 상태 reducer 테스트가 먼저 실패한다.
- 기존 스키마·IPC 변경이 필요하면 구현을 멈추고 별도 승인을 받는다.

### UI-01 — 환경 준비 화면

목표: 카드 없는 구성요소 상태 목록과 별도 환경 준비 진입점을 만든다.

- 별도 route/state로 환경 준비 화면을 추가한다.
- 구성요소 행, 전체 진행, 저장 위치, 복구 세부 정보를 분리한다.

완료 조건:

- `checking`부터 `blocked`까지 각 상태가 테스트된다.
- 화면에 큰 기능 카드나 이미지 작업대를 덮는 설치 모달이 없다.

### UI-02 — 작업대 런타임 상태와 점진적 기능 활성화

목표: 작업대에서 환경 상태를 작게 확인하고 준비된 기능만 안전하게 사용한다.

- 작업대 상단에 작은 런타임 상태 컨트롤을 연결한다.
- 설치 중에도 이미지 열람과 이미 준비된 기능은 계속 사용할 수 있게 한다.
- 사용할 수 없는 기능에는 현재 원인을 설명하는 disabled reason을 제공한다.

완료 조건:

- 한 구성요소 실패가 다른 준비된 기능을 차단하지 않는다.
- 비활성 기능마다 사용자가 다음 행동을 알 수 있는 이유가 표시된다.
- 런타임 상태 컨트롤에서 환경 준비 화면으로 이동하고 같은 작업대로 돌아올 수 있다.

### UI-03 — 비교 레이어와 transform 동기화

목표: 결과 전환이 이미지 위치를 바꾸지 않게 한다.

- `PageImagePanel`의 단일 viewport transform을 모든 결과 레이어가 공유한다.
- 결과 없음, 처리 중, stale, 부분 실패 상태를 추가한다.
- 페이지 전환과 결과 전환의 상태 보존 테스트를 작성한다.
- 수동 인페인팅 결과는 원본 `pageImages`를 교체하지 않고 기존 processing 저장 계약의
  `ProcessingRunRecord`, `DerivedImageAsset`, `approvedCleanedAssetId`로 기록한다.
- 세션 경로는 processing 결과를 즉시 커밋하고 반환된 최신 revision을 renderer가 채택한다.
  비세션 경로는 같은 processing 구조를 프로젝트에 반영하고 기존 저장 흐름으로 영구화한다.
- 이 연결에는 저장 스키마나 새 IPC 채널을 추가하지 않는다.
- provider가 반환한 편집 이미지는 원본 페이지와 동일한 종횡비인지 검증하고 원본 캔버스
  크기의 PNG로 정규화한 뒤 processing asset으로 기록한다.
- 새로 연결했지만 아직 저장하지 않은 페이지는 저장 전까지 OCR·인페인팅을 차단한다.
  renderer의 비활성 이유와 Main의 processing gate가 같은 계약을 적용한다.
- 같은 세션에서 늦게 도착한 processing 결과는 현재 revision 이상일 때만 프로젝트 snapshot을
  채택하며, 페이지·선택·viewport·활성 결과 레이어 문맥은 바꾸지 않는다.
- 승인 결과는 현재 `PageImage`와 asset·run·role 연결이 모두 일치할 때만 표시하며, 각 레이어는
  자신의 run `sourceSha256`로 stale 여부를 판정한다. 손상되거나 오래된 연결은 원본으로
  fallback하되 viewport와 선택을 유지한다.
- stale·processing·부분 실패가 겹치면 주 상태와 별도로 각 사실을 보존하고, 번역 결과가 아직
  없어도 활성 pipeline run이 있으면 처리 중 문맥을 표시한다.
- 현재 페이지 OCR·인페인팅 중에는 이미지 재연결을 차단하고, Main은 processing patch를 실제로
  저장하는 세션 큐 안에서 원본 ID·SHA와 page·run·asset·approval 연결을 다시 검증한다.
- OCR·인페인팅 provider 호출 전에 저장 원본 bytes의 SHA-256을 확인한다. 세션 processing
  커밋이 실패하면 해당 요청이 새로 만든 결과 asset만 정리하며 기존 파일은 건드리지 않는다.
- 다른 폴더로 Save As할 때는 최종 프로젝트가 참조하는 기존 `pageImages`와
  `processing.assets`를 같은 `storedRelativePath`로 복사한다. source와 staging의 hash·크기를
  검증하고, target 충돌은 동일 내용만 재사용하며 프로젝트 파일 교체 전 승격·정리를 끝낸다.
  실패 시 이번 실행의 신규 자산만 rollback하고 기존 프로젝트·자산·세션 문맥을 유지한다.
- foreground 인페인팅 완료의 자동 레이어 전환보다 처리 중 사용자가 확인한 결과 레이어 의도를
  우선한다. 동일 레이어 재클릭과 다른 레이어 왕복도 사용자 revision으로 기록하며, stale 결과는
  결과 graph만 유지하고 활성 레이어·viewport·OCR·선택·편집 문맥을 바꾸지 않는다.

완료 조건:

- 원본/인페인팅/번역 전환 전후 transform이 동일하다.
- 렌더링 오류 시 원본으로 돌아가도 transform과 선택이 유지된다.

### UI-04 — 비교 조작

목표: 단일·분할·비교선·투명도·누르는 동안 원본을 같은 캔버스에서 제공한다.

- 상단 조밀한 비교 컨트롤을 추가한다.
- 분할선과 투명도를 키보드로 조절할 수 있게 한다.
- `Backslash` keydown/keyup/blur 복구를 테스트한다.

완료 조건:

- 별도 창 없이 모든 비교가 가능하다.
- 비교 중 페이지·선택·오버레이가 사라지지 않는다.
- 입력 중 전역 비교 단축키가 작동하지 않는다.

### UI-05 — 의미 오버레이

목표: 원문 분석 영역과 출력 영역을 의미별로 구분해 표시한다.

- OCR, 말풍선, 안전 영역, 식자, 마스크, 보존 요소, 문제 오버레이를 렌더링한다.
- 현재 선택 중심의 혼잡도 제어와 범례·빠른 보기 토글을 추가한다.

완료 조건:

- 색상을 제거한 상태에서도 선·라벨·무늬로 영역을 구분할 수 있다.
- 말풍선 없음과 있음의 컨테이너 규칙이 각각 테스트된다.

### UI-06 — 식자 상자 직접 조작

목표: 한국어 식자 영역을 OCR 분석 영역과 분리해 이미지 위에서 편집한다.

- 한국어 식자 상자를 별도 객체로 생성하고 OCR 분석 영역과 독립적으로 유지한다.
- 식자 상자의 이동·크기·회전 핸들을 이미지 좌표계에 연결한다.
- 확대·축소·이동 뒤에도 식자 상자와 핸들의 정렬을 유지한다.

완료 조건:

- 세로 OCR 상자를 한국어 식자 상자로 그대로 사용하는 경로가 없다.
- 가로쓰기 기본값과 말풍선 안전 영역 제약이 테스트된다.
- 직접 조작 전후에도 원본 이미지 좌표가 보존된다.

### UI-07 — 문제 큐 오케스트레이션

목표: 문제 선택 한 번으로 페이지·캔버스·오버레이·편집기를 동기화한다.

- 문제 종류와 편집기·오버레이 매핑을 데이터로 정의한다.
- 패널을 제외한 캔버스 안전 영역에 문제를 중앙 정렬한다.
- 이동 실패 시 이전 선택을 보존한다.

완료 조건:

- 모든 문제 분류가 올바른 편집기와 오버레이로 이동한다.
- 하단 패널을 접었다 다시 열어도 현재 문제를 유지한다.
- 페이지 로드 실패가 다른 문제의 상태를 훼손하지 않는다.

### UI-08 — 문맥 편집기 자동 전환과 고정

목표: 문제 문맥에 맞는 편집기를 자동으로 열면서 사용자 고정 상태를 존중한다.

- 오른쪽 편집기 자동 전환과 고정 상태를 추가한다.

완료 조건:

- 고정 상태에서는 편집기가 강제로 바뀌지 않는다.
- 고정을 해제하면 현재 문제에 맞는 편집기로 다시 동기화된다.
- 문제 이동 실패 시 현재 편집기와 고정 상태가 유지된다.

### UI-09 — AI 제안과 사용자 확정 보호

목표: AI 제안 속도를 유지하면서 사용자 수정과 확정값의 소유권을 보호한다.

- `AI 제안`, `사용자 수정`, `사용자 확정`, `재검토 필요` 상태를 표시한다.
- 자동 저장 초안과 `확정하고 다음`, `보류` 흐름을 연결한다.

완료 조건:

- 사용자 확정값은 AI 재실행에서 덮어쓰이지 않는다.
- 실패·페이지 전환·앱 재시작 뒤에도 사용자 수정 초안이 남는다.

### UI-10 — 세션 복원

목표: 앱을 열자마자 마지막 이미지 작업 문맥으로 돌아온다.

- 프로젝트·페이지·viewport·비교·패널·선택·고정 상태를 복원한다.

완료 조건:

- 정상 종료와 충돌 복구 모두 유효한 초안을 복원한다.
- 손상되거나 오래된 세션 상태는 안전한 기본값으로 복구된다.

### UI-11 — 적응형 축소와 키보드·고대비 접근성

목표: 지원 너비와 Windows 접근성 설정에서 이미지 중심 작업 흐름을 유지한다.

- 1440, 1200, 1024 경계에서 패널 축소 정책을 적용한다.
- 1024px 미만 정밀 편집 안내와 이미지 열람 지속을 구현한다.
- 키보드 이동, 포커스 순서, 고대비 모드에서 주요 상태를 확인한다.

완료 조건:

- 어떤 지원 너비에서도 패널이 이미지 위를 무단으로 덮지 않는다.
- 주 작업 버튼이 잘리거나 키보드 포커스가 화면 밖으로 이동하지 않는다.
- 색상 없이도 선택·상태·오류·오버레이 의미를 구분할 수 있다.

### UI-12 — Windows/Electron 시각 회귀와 패키지 smoke

목표: 브라우저 모형이 아니라 실제 Windows 전문 프로그램으로 검증한다.

- 1440×900, 1280×720, 1024×640에서 스크린샷을 비교한다.
- Windows 배율 100%, 125%, 150%를 확인한다.
- 마우스, 키보드, 화면 낭독 순서와 패키지 실행 흐름을 확인한다.
- 설치 진행 중, 비교 중, OCR 예외, 오류 복구 화면을 캡처한다.

완료 조건:

- 이미지가 모든 지원 크기에서 가장 큰 단일 작업 영역이다.
- 전체 화면과 집중 보기에서 패널을 모두 숨길 수 있다.
- 콘솔 오류, React 경고, Electron 포커스 누수, 키 stuck 상태가 없다.

## 21. 최종 수용 기준

1. 평상시 화면에서 만화 이미지가 가장 큰 단일 영역이다.
2. 좌측·우측·하단 패널을 각각 또는 모두 숨길 수 있다.
3. 설치는 별도 환경 준비 화면에서 진행되며 작업대를 모달로 덮지 않는다.
4. 기본 런타임이 준비되면 전체 모델 설치가 끝나기 전에도 이미지 작업대에 진입할 수 있다.
5. 한 구성요소의 설치 실패가 준비된 다른 기능을 차단하지 않는다.
6. 원본·인페인팅·번역 전환과 모든 비교 방식에서 확대·이동·선택이 유지된다.
7. 누르는 동안 원본 보기는 키를 놓거나 창 포커스를 잃으면 반드시 이전 상태로 복구된다.
8. 문제 선택 한 번으로 페이지, 중앙 위치, 선택, 오버레이, 오른쪽 편집기가 동기화된다.
9. 오른쪽 편집기를 고정하면 자동 전환이 사용자의 현재 도구를 덮지 않는다.
10. 원문 OCR 영역과 한국어 식자 영역은 별도 객체이며 시각적으로도 구분된다.
11. 한국어 식자는 기본 가로쓰기이며 세로 OCR 상자의 좁은 폭을 그대로 상속하지 않는다.
12. 오버레이는 색상 외의 선·무늬·라벨로도 구분된다.
13. 사용자 수정은 자동 저장되고 사용자 확정은 AI 재실행에서 보호된다.
14. 마지막 프로젝트, viewport, 비교, 패널, 선택, 초안이 안전하게 복원된다.
15. 1024×640 이상에서 이미지 위를 무단으로 덮는 보조 패널이 없다.
16. 설치·비교·검수의 빈 상태, 로딩, 부분 실패, 복구 상태가 모두 정의되고 테스트된다.
17. 큰 카드·그라데이션·글래스모피즘·영웅형 제목이 없다.
18. 구현 후 typecheck, test, build, Electron 수동 검증이 통과한다.
