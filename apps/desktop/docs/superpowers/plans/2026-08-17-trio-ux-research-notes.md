## 확정 전 가설

Trio는 자동 처리 파이프라인을 과장해서 표현하지 않고, 실제로 구현된 사람 중심의 OCR·화자 검토·번역 수정·인페인팅 흐름을 빠르게 반복할 수 있어야 한다. 따라서 기본 화면은 이미지 우선으로 유지하되, 선택한 말풍선의 관련 정보를 같은 작업 맥락에서 열어 주는 문맥형 인스펙터와 예외 중심의 리뷰 큐를 핵심 후보로 둔다.

## 설계 제약으로 채택할 항목

이미지 중심 선택을 우선하고, 자동 결과는 **제안**으로만 표시한다. 사용자는 같은 문맥에서 원문·화자·번역·말풍선 경계와 결과 레이어를 확인한 뒤 명시적으로 확정한다. 자동 식자·번역의 불확실성이나 처리 속도를 사실처럼 수치화하지 않으며, 실제 데이터에서 유도된 경고만 리뷰 큐에 올린다.

## 사용자 연구의 잠정 결론

전문 사용자는 “모든 모델을 한 번에 자동 실행”하는 약속보다 **실패하거나 애매한 항목을 빨리 찾아서, 이미지 문맥을 잃지 않은 채 고치고, 다음 항목으로 이동하는 흐름**에서 가치를 얻는다. Trio의 전면 리디자인은 이 점을 기준으로 진행한다.

## 디자인 결론의 근거

Trio의 기본 워크스페이스는 큰 단일 이미지 스테이지, 접히는 탐색·리뷰 표면, 선택 기반의 오른쪽 인스펙터로 구성한다. 인스펙터와 캔버스 근처의 빠른 행동은 서로 역할이 겹치지 않아야 하며, 사용자가 패널을 고정하거나 숨겨 이미지 공간을 회복할 수 있어야 한다.

## 라이트·다크 테마 판단

[Nielsen Norman Group의 다크 모드 분석](https://www.nngroup.com/articles/dark-mode/)은 정상 시력 사용자에서 일반적으로 라이트 모드가 세부 텍스트 판독 성능에 유리하다고 설명하면서도, 장시간 사용하는 앱은 사용자가 다크 모드를 선택할 수 있게 하라고 권고한다. 최근 학술 논문 원문은 현재 접속 방어로 직접 검증하지 못했으므로 해당 논문의 세부 결과를 설계 근거로 사용하지 않는다.

Trio는 **라이트 기본 테마와 완전한 다크 테마를 함께 제공**하는 방향이 타당하다. 라이트 기본은 OCR·번역문·설정처럼 장시간 읽고 수정하는 밀도 높은 텍스트에, 다크 테마는 야간 작업과 밝은 만화 이미지를 두드러지게 보는 뷰어 환경에 적합하다. 두 테마 모두 이미지 스테이지는 중성 차콜로 유지하고, 단순한 색상 반전이 아니라 각 상태·경고·선택·오버레이의 대비를 별도로 보장한다.

## 실행 화면 기준선

2026-08-17에 현재 Vite 렌더러의 초기 홈 화면을 실행해 확인했다. 현재 화면은 크림 배경, 네이비 제목, 청록 주요 버튼의 단일 카드형 진입 구조이며, 첫 방문자에게는 최근 프로젝트 빈 상태가 대부분의 화면을 차지한다. 기능적으로는 새 프로젝트, 기존 프로젝트 열기, TXT 시작, 환경 준비가 접근 가능하지만, 전문 편집 도구의 재개 중심 우선순위·프로젝트별 작업 맥락·명확한 현재 상태가 시각적으로 충분히 드러나지 않는다. 전면 재설계에서는 홈 자체의 장식보다, 최근 작업이 있는 사용자에게는 “마지막 작업 이어가기”와 실제 미해결 검토를 우선하고 신규 사용자에게는 준비·생성·불러오기 흐름을 짧고 분명하게 제시한다.

재설계 후 다시 실행한 홈 화면에서는 기존의 큰 카드가 사라지고, 명령형 헤더·신규 사용자용 시작 행·파일 작업·최근 프로젝트 목록·보조 TXT 시작 흐름이 수평 규칙으로 분리되었다. 시각 검증에서 신규 사용자의 시작 흐름이 두 개의 새 프로젝트 행동으로 보일 수 있는 점을 확인했으므로, 구현 단계에서 보조 행의 중복된 새 프로젝트 행동을 제거하고 기존 프로젝트 열기만 보조 행동으로 남긴다.

중복 제거 뒤의 최종 홈 화면에서는 한 개의 `새 번역 프로젝트` 주 행동과 `기존 프로젝트 열기` 보조 행동만 남고, 최근 프로젝트 빈 상태의 높이도 내용 밀도에 맞게 축소되었다. 브라우저 제목도 `Trio — Manga Translation Workbench`로 갱신되어 앱 표기와 일치한다.

브라우저 렌더러에서 임시 TXT 가져오기 응답으로 작업대의 시각 확인을 시도했으나, 보조 시작 방법이 접힌 상태라 해당 진입을 열지 못했다. 이 시도는 앱 소스나 저장된 프로젝트 데이터를 변경하지 않았으며, 작업대 기능 검증은 196개 렌더러 회귀 테스트로 별도로 수행한다.

보조 시작 방법을 열어 임시 TXT를 불러온 뒤, 이미지가 아직 연결되지 않은 실제 워크스페이스를 확인했다. 상단 명령 바, 차콜 스테이지, 오른쪽 선택 인스펙터, 하단 대사 큐의 역할은 구분되지만, 이미지가 없는 상태에서 결과·비교·의미 오버레이 도구가 스테이지 상단에 과도하게 노출되어 도구 밀도가 높게 보였다. 후속 조정에서는 좁은 스테이지에서 결과 레이어·비교·오버레이 제어를 한 줄의 가로 스크롤 또는 접힌 도구 그룹으로 제한해 작업 표면을 회복한다.
