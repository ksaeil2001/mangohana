# 망고하나 데스크톱 가져오기 기록

2026-10-29, 기존 웹서비스를 보존하고 독립 Electron 앱을 `apps/desktop`에 추가했습니다.

- 원본: `ksaeil2001/trio`의 `2a754df`를 기준으로 한 로컬 작업본. 망고하나 UI·UX, 문구 정리, 마우스 글자 배치와 관련 저장·초안 보호 변경을 포함합니다.
- 앱 소스·테스트·설정·브랜드 자산·라이선스·필요한 문서를 가져왔습니다. 원본 Git 이력은 병합하지 않았습니다.
- `node_modules`, 빌드·설치 산출물, 촬영 프로필, 캐시, 사용자 프로젝트와 원본 이미지는 포함하지 않았습니다. 과거 검토용 만화 이미지 1장, 이를 담은 화면 캡처 6장과 전용 검토 진입점도 제외했습니다. `public/mangohana-example`은 직접 만든 합성 예시입니다.
- 웹서비스의 패키지와 실행 명령을 유지합니다. 루트 TypeScript·ESLint는 독립 데스크톱 프로젝트를 제외하고, 데스크톱은 자신의 설정과 잠금 파일로 검사합니다.
- 데스크톱의 기존 앱 식별자·저장 경로·업데이트와 배포 대상은 호환성 검증 없이 변경하지 않았습니다.
- `apps/desktop/.github/workflows`는 기존 설정 검증에 필요한 참고 파일이며, 저장소 루트의 GitHub Actions로 등록되지 않습니다. 이번 통합으로 자동 빌드·릴리스가 시작되지는 않습니다.

## 실행

```powershell
cd apps/desktop
npm ci
npm run dev:electron
```

`npm run build`, `npm run typecheck`, `npm test -- --dir tests`를 이 폴더에서 실행합니다. 루트 웹서비스의 명령은 저장소 루트에서 실행합니다.

## 검증 범위

병합용 체크아웃에서 Node.js 24.11.1과 각 폴더의 잠금 파일로 의존성을 설치하고 확인했습니다. 설치 후 스크립트는 실행하지 않았습니다.

| 대상 | 검사 | 결과 |
|---|---|---|
| 데스크톱 | `npm run typecheck`, `npm run build` | 통과 |
| 데스크톱 | `npm test -- --dir tests --pool=threads` | 2,619개 통과, 실패·건너뜀 0개 |
| 데스크톱 | `npm run lint:jsx` | 통과 |
| 데스크톱 | `node scripts/lint-design-system.mjs --json` | 오류 0개, 경고 103개 |
| 웹서비스 | `npm run build`, `npm run lint` | 통과 |
| 웹서비스 | `npm run test:domain -- --pool=threads` | 3,031개 통과, 104개 실패, 207개 건너뜀. 전체 통과 아님 |

웹서비스 검사에서 실패한 13개 파일은 가져오기 전 `main`의 `1be384f7557b06aff2f98a8751709c8617d45f1f` 사본에서도 모든 개별 검사 상태가 일치했습니다. 이 범위에는 실패한 assertion 103개와 글꼴 카탈로그 무결성 확인 단계에서 중단된 파일이 포함됩니다. 기존 웹서비스의 소스·테스트·자산은 이번 통합에서 수정하지 않았습니다.

나머지 대용량 `windows-stage-cost-reader` 검사 1개의 30초 시간 초과는 단독 재실행에서도 발생했습니다. 같은 검사는 병합 전 코드에서도 약 33.47초 후 실패해, 실패 상태가 재현됐습니다. 이 지연의 근본 원인은 조사하지 않았습니다. 제한 시간과 검증 조건은 변경하지 않았습니다.

데이터베이스·브라우저를 포함한 웹서비스 전체 통합 검사는 수행하지 않았습니다.

이전 로컬 작업본의 실제 Electron UI에서는 격리된 프로필과 합성 프로젝트로 문구·화면 이동·글자 상자 이동 및 크기 조절·영역 적용·프로젝트 저장과 재열기를 확인했습니다. 숫자 정밀 조정의 기본 접힘 상태를 포함한 최종 가져오기 버전은 위 자동 검사로 확인했으며, 최종 버전의 실제 Electron 화면을 다시 실행하지는 않았습니다. 실제 AI 제공자와 새로운 만화의 자동 번역 품질, 새 설치 패키지·업데이트는 검증하지 않았습니다.

합성 예시의 이미지 출력은 원본 2장이 생성되고 식자 결과 2장은 `TYPESET_RENDER_NOT_PROVIDED`로 실패한 부분 완료였습니다. 마우스 배치 미리보기를 최종 식자 이미지 출력 성공으로 계산하지 않습니다.

정적 검토에서 Windows의 다른 로컬 프로세스가 경로 확인과 파일 열기 사이에 연결점을 교체하는 경쟁 조건이 지적됐습니다. 실제 공격 재현이나 네이티브 파일 핸들 경로 검증은 수행하지 않았으며, 이번 소스 통합을 보안·출시 완료로 판단하지 않습니다.
