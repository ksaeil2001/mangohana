# NotebookLM 기술 스택 선택 학습의 근거와 한계

확인일: 2026-10-03. [NotebookLM 노트북](https://notebook.google.com/notebook/edd4a227-15b0-47e8-8f08-b9481c58a7b2), 제목: 바이브코딩의 체계: 디버깅과 에이전트 활용법. 현재 선택된 소스29개를 사용했다. 이 문서는 진행 ledger가 아니라 질문·관측·원문 대조의 근거 기록이다. 진행은 [기존 플랜 8절](../../docs/superpowers/plans/2026-10-02-manga-web-workspace-contracts-and-validation-plan.md), 적용 정리는 [기술 후보 10절](../../docs/superpowers/specs/2026-10-03-manga-web-technical-options.md)에 둔다.

## 1. 실제 수행한 범위

- 기존 Chrome의 사용자 NotebookLM 탭에서 질문3회와 답변3개의 생성 완료를 UI로 확인했다. 새 노트북·소스·공유 설정을 만들거나 바꾸지 않았으며 프로젝트 파일·원본 이미지를 업로드하지 않았다.
- 첫 질문에 현재 계약의 요약과 미선택 A/B/C 후보를 제공했다. 후속 질문에는 직접 읽은 전사문과 공식 문서에서 확인한 보정 조건, 마지막에는 무료 총10장·같은 요청 재개와 기존 선택 상태를 제공했다. 이 조건을 NotebookLM이 독립적으로 확인한 사실로 취급하지 않는다.
- 관련 소스 네 개의 표시된 전사문을 각각 첫 내용부터 끝까지 읽고 보존했다. NotebookLM의 소스 가이드 요약과 전사문 본문을 구분했다. 원본 영상/음성은 재생하지 않았고 다른25개 전사문은 이번에 전량 읽지 않았다. 자동 전사에는 명칭/문장 오류가 있으며 이를 원본 음성 대조로 수정했다고 표현하지 않는다.
- 제품 코드/테스트·dependency·서비스 스키마/공개 API·실제 파일 형식을 수정하거나 확정하지 않았다. 실제 후보 runtime·AI 번역·결제·유료 인프라·계정 생성·배포는 수행하지 않았다.

DOM 기록은 당시 표시된 생성 답변·인용 버튼 이름을 보존한 연구 자료다. 인용 번호는 해당 답변에 붙은 위치이며 영구 원문 식별자가 아니다. 마지막 답변도 검증된 제품 계약이나 완벽한 강의 요약으로 취급하지 않는다. [결과 화면](notebooklm-stack-selection-result.jpg)은 실제 질문·답변 완료의 UI 근거이며 서비스 실행 증거가 아니다.

## 4. 선택적으로 확인한 공식 보정 근거

조회일은 모두2026-10-03이다. 가격·성능·처리량 우열은 이번 공식 조회에서 검증하지 않았다.

| 출처 | 직접 확인한 설명 | 현재 계약에 적용할 판단 |
| --- | --- | --- |
| [Node timers](https://nodejs.org/api/timers.html#scheduling-timers) | 정확한 callback 시각/순서를 보장하지 않음 | 정각 callback을 필수 통과 조건으로 쓰지 않고 절대 기한 이후 새 발행 차단·늦은 대조/복구를 검증 |
| [Temporal Workers](https://docs.temporal.io/workers) | Service/Cloud와 사용자 worker의 개발·운영 책임을 구분 | 자체 Temporal 클러스터 운영이 항상 필요한 것으로 분류하지 않으며 worker·DB·원장 인계 책임을 계속 비교 |
| [Temporal Retry Policies](https://docs.temporal.io/encyclopedia/retry-policies) | 기본 Activity retry의 최대 시도는 무제한이며 1로 지정하면 재시도 없음 | 비용 발생 호출에 기본 retry를 그대로 적용하지 않음. retry/history가 외부 수행불명·정산 대조를 자동 해결한다고 하지 않음 |
| [Workers KV consistency](https://developers.cloudflare.com/kv/concepts/how-kv-works/) | eventual consistency, 원자 연산/단일 transaction이 필요한 작업에 적합하지 않다고 설명 | KV를 현재 권한/정산의 원자적 잠금 근거로 쓰지 않음. 후보C의 권위 DB/DO 경계는 별도 설계·검증 |

## 5. 사용자 선택과 완료 경계

필수 계약을 만족한다는 전제에서 운영 부담/초기 비용/이전 가능성 중 무엇을 우선할지 선택지3개로 한 질문을 제시했다. 현재 응답 전이며 권장 항목을 선택으로 기록하지 않는다. Q20~Q22도 미선택이다. 다음에 Q20의 첫 상세 후보를 제시하고, 응답 뒤 해당 기술의 실제 타입/저장/실행 인계와 I-A 계획을 구체화한다.

이번에는 기술 선택 방법의 학습·직접 원문 대조와 문서 연결을 완료했다. 후보 런타임·실제 공급사·웹 UI/파일/탭, S01~S31/APV01~APV16 실행은 NOT RUN이다. 이전 SQLite 연구용 PASS는 보존하며 이번 학습의 런타임 검증으로 재사용하지 않는다.

이번 학습의 최종 architect 호출도 `agent thread limit reached`로 거절되어 **독립 검토 미완료**다. 기존 호출 한도 때문에 중단하지 말라는 사용자의 명시 지시에 따라 학습·원문 대조와 문서 검사를 진행했다. 기존 지시는 플랜7절에 보존돼 있으며 제품/기술 선택 승인으로 확대하지 않았다. [검사 결과](document-checks.json)에 L0와 독립 검토 상태를 각각 남긴다. 앞선 완료 검토나 NotebookLM 답변을 이번 architect 독립 검토로 대신하지 않는다.
