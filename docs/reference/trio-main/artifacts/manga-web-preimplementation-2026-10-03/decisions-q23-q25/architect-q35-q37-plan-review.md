# Q35~Q37 뒤 상세 초안 계획·질문의 독립 검토

일자: 2026-10-03. 담당: `/root/preimplementation_q35_q37_review`, architect 역할. 정상 호출/읽기 전용 검토. 대상은 현재 문서와 전달한 상세 초안 계획/질문이며 변경 후 최종 원문·제품 실행 검토가 아니다.

결론: Q35-A/Q36-A/Q37-A는 기존 Q32~Q34와 충돌하지 않는다. 상세 초안 작성 진행 가능. Q38/Q39는 보완 뒤 발송 가능, 당시 제안한 만료 직전 전송 질문은 추천 문구 그대로 발송하지 않는다.

| 지적 | 필요한 반영 |
| --- | --- |
| 높음: 기한 전에 받은 다운로드의 전송 마무리가 기존30일 실제 삭제와 양립하는지 미입증 | 만료 뒤 서버 원본/전송 사본을 계속 읽고 보내는 근거로 수락 시각만 사용하지 않음. 해당 질문 보류, storage/삭제 근거부터 좁힘. 이미 전달한 단말 bytes 회수 약속도 하지 않음 |
| 중간: 로그인 상한의 새 로그인 기산점이 모호 | 사용자가 명시적으로 다시 로그인하고 서비스가 새 인증 근거를 검증한 시점. 조용한 SSO/refresh/같은 callback 재처리로 상한 초기화 없음 |
| 중간: Auth 후보의 우선 검토/최종 채택 단계가 섞임 | 두 선택 모두 먼저 상세 설계/적합성 검증할 후보 순서. 제품 채택/계정 생성/유료 플랜 승인 아님. Q27-A 미충족 후보는 채택 불가 |
| Undo 인수 조건 | 수동 값·이력/cursor·새 수정 Redo 폐기·Q32 무효화 원자적 경계. 같은 context/page에 이력 유지, 명령 권한만 새 OwnerRevision 검사. 옛 owner 지연 Undo/새 owner 경합·응답 유실·AI 동시 적용 |
| ZIP 인수 조건 | revision만 기록하지 말고 불변 렌더 입력·폰트/레이아웃/필수 자산을 허용 수명 동안 확보. 전체 실패에 partial ZIP 성공 제공 없음. 같은 캡처와 항상 동일 압축 bytes 보장은 구분 |
| 보관 인수 조건 | 동일 미완료 작업의 자동/사용자 재시도 중복·시도 한도 초기화 방지, 작업/attempt/claim 세대. 객체 성공 뒤 DB/응답 유실 먼저 대조. 옛 결과의 늦은 성공이 최신 pointer/기한을 되돌리지 않음 |
| 파일/종료 인수 조건 | 필수 편집 자산과 선택 checkpoint 분리. 편집 복원과 AI 단계 재사용 판정 분리, 몰래 AI로 보충 없음. 서명 성공이 현재 접근이나 정상 종료를 대신하지 않음 |
| 현행 문구 잔재 | 준비9.3의 ZIP 처리 중/변경 뒤 미정은 Q33-A와 불일치. DS16/22/24·59, CF/OB/FX, 플랜의 선택 개수/응답 대기 갱신 |

반영: 다음 질문은 실제 Q38 인증 후보 우선 검토와 Q39 로그인 절대 상한 두 개로 보완해 발송했다. 만료 직전 전송 질문은 발송하지 않았다. Q35~Q37 본문/상태와 상세 초안의 위 인수 조건을 연결한다. 변경 후 최종 대조는 별도 수행해야 한다.

계정 생성·설치·설정 변경·메일/OAuth·DB·외부 AI/비용·파일 서명·브라우저/삭제 실행은 없었다.
