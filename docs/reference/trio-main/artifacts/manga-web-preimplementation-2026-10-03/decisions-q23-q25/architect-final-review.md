# 열두 선택과 Postgres 요청 수명 초안의 독립 검토

일자: 2026-10-03. 담당: 기존 `/root/state_contract_review`, architect. 범위는 Q20~Q31 선택 반영과 `2026-10-03-manga-web-postgres-execution-design.md` 전체의 읽기 전용 정합성 검토다.

## 최초 검토에서 받은 필수 보완

1. 이미 정한 언어/브라우저/파일별 업로드·DB 기반이 현재 미정 목록에 남아 있었다. 작성 당시 안내와 현재 상태를 구분하고 G04/PRE05의 요청 수명 초안 작성/전체 미완료를 현행화할 필요가 있었다.
2. ExecutionId PK와 페이지 단일 요청·작업 claim만으로 같은 요청/논리 단계의 두 유효 수행 준비를 막는 불변식은 충분히 명시되지 않았다.
3. 공급사 대기 회차를 끝내는 실제 시작 근거가 현재 wait round·대상 단계/수행과 연결돼야 했다. 이전 단계의 증거 재수신으로 현재 대기를 종료하지 않는 사례가 필요했다.

Q33 다음 질문의 ‘새 AI 호출 없음’은 ZIP 때문에 별도 AI 요청/재실행을 만들지 않는다는 뜻으로 한정했다. 이미 진행하는 요청의 정상 단계 수행은 기존 권한·기한에 따른다. Q34는 DS22의 실제 보관 시각을 근거로 하며 전체 묶음 성공을 추정하거나 만료 자료를 되살리는 선택이 아니다.

## 실제 반영

- Domain Story 59.3, 준비 명세 6절, 플랜 서두/9.3, 워크스페이스 계약 10절의 현재 상태를 수정했다.
- `RequestStepCurrent`의 요청/논리 단계 unique·현재 ExecutionId/세대와 같은 commit의 준비 가드를 추가했다. 준비·발행·실행·수행불명 기존 수행 중 다른 ExecutionId 생성/발행을 막고 lease 만료만으로 참조를 해제하지 않는다.
- 열린 wait round·대기 LogicalStepId·그 회차의 수행 시작 근거만 회차 종료에 쓰도록 명시했다.
- PGV16 동시 다른 ExecutionId 준비 금지와 PGV17 이전 단계 증거 재수신의 현재 대기 유지 사례를 추가했다.

architect는 지적 반영을 실제 원문에서 확인했고 이번 제한 범위의 추가 필수 수정은 없다고 회신했다. 기록 가능한 완료 범위는 **Q20~Q31 열두 선택 반영과 Postgres·TypeScript 요청 수명 초안의 독립 검토 완료, 지적 반영 확인**이다.
