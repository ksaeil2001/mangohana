# 만화 번역 웹 워크스페이스의 화면·서비스·저장 계약과 검증 명세

작성일: 2026-10-03. 상태: **문서 작성·독립 검토 완료**. 사용자 선택 Q15-A·Q16-A·Q17-A·Q18-A·Q19-A와 기존 Q1~Q14의 확정 선택을 적용한다. 식별·명령·응답·기록 이름은 논리 설계 제안이다. 코드·테스트 구현, 브라우저·실제 공급사 실행 검증은 **NOT RUN**이다.

## 1. 출처·범위·결정 상태

업무 규칙의 단일 기준은 [Domain Story](../../manga-translation-domain-story.md)이며 이번 선택은 4·15·17·21·58절에 반영했다. 입력 명세는 [웹 서비스 설계 초안](2026-10-02-manga-translation-web-service-draft.md) 11~13절, 작성 순서·완료 조건은 [계약 작성 플랜](../plans/2026-10-02-manga-web-workspace-contracts-and-validation-plan.md) T1~T6이다.

확정 정책과 기술 제안을 구분한다. 재접속 유예 5분, 공급사 연속 대기 10분, 이번 파일의 사용자 보관 확인은 확정 정책이다. 한 탭만 편집·실행하고 명시적으로 권한을 인계한다(Q15-A). 파일은 만든 계정에서만 복원한다(Q16-A). 원 모델/단계 계약 사용 불가 때 기존 재번역으로 안내한다(Q17-A). 현재 맥락의 제외는 되돌릴 수 없지만 새 복원 맥락은 파일의 저장 시점 구성을 따른다(Q18-A).

아래 계약은 단절·종료, 대기 만료, 산출물 호환성, 파일 전달과 관련된 실행·사용량·잠금·저장 경계를 구체화한다. 후속 Q20-A로 Postgres+TypeScript 실행 기반, Q21-A/Q22-A로 서비스 서명/최소 검증 근거 유지 방향을 정했다. 실제 HTTP 경로·JSON schema·나머지 제품/버전·파일 확장자·migration/서명 상세·배포 구성은 아직 미선정이다. 실제 선택과 후속 범위는 Domain Story 59절·구현 전 준비 명세 11절을 따른다. Trio 데스크톱의 IPC·`.ctp` 또는 기존 Electron 테스트를 웹 계약과 실행 증거로 사용하지 않는다.

## 2. 독립된 상태·식별·확인 근거

설계 초안 13.2의 편집 맥락, 연결, 처리 요청, 개별 실제 수행, 보류 이유, 결과/정산/잠금, snapshot/파일 확인을 각각 유지한다. 보류 이유는 동시에 존재할 수 있는 집합이며 하나가 해소됐다는 사실만으로 실행하지 않는다.

| 논리 정보 | 권한·용도 | 검사 경계 |
| --- | --- | --- |
| 현재 계정 | 인증된 서비스의 계정·프로젝트 접근 | 파일이나 화면이 주장한 계정 ID는 권한이 아니다. |
| 프로젝트/페이지 계보 | 원 프로젝트·페이지를 추적하는 서비스 참조 | 같은 계보의 현재 활성 요청을 복원 맥락에서도 대조한다. 파일명·순서로 대체하지 않는다. |
| 맥락 ID·세대 | 활성/종료 절차/종료/만료와 해당 요청의 결과 적용 대상 | 파일 복원은 새 맥락·세대. 같은 맥락의 재접속·탭 인계는 맥락 정체성을 유지한다. |
| 편집 소유권 세대 `OwnerRevision` | 현재 편집 탭을 구분하는 서비스 발급 권한 | 인계 때 변경한다. 이전 탭의 변경 명령·접속 유지 신호는 거부한다. 맥락 세대와 다르다. |
| 명령 ID·정규화된 의도 | 같은 계정의 동일 클릭 재전송 식별 | 같은 ID·같은 의도는 기존 결과 조회. 같은 ID·다른 의도는 충돌이며 새 요청을 만들지 않는다. |
| 요청/단계/실제 수행 ID | 원 설정·범위·첫 실제 시작·실제 호출과 증거의 귀속 | 명령 재전송, 내부 단계 재개, 사용자 새 재시도를 구분한다. |
| 페이지 편집·결과 버전 | 입력·선택 범위와 현재 결과 적용·수동 수정 충돌 | 실제 적용 전에 현재 맥락·페이지·범위·예상 결과 버전을 확인한다. |
| 워크스페이스 편집 버전 | 페이지 구성·현재 결과·설정 등 파일에 담는 편집 변경 | snapshot 이후 편집 변화가 있으면 과거 보관 확인으로 정상 종료하지 않는다. |
| snapshot/내보내기/확인 ID | 동일 캡처 상태·검증 파일·전달 시도·사용자 확인 연결 | 서로 다른 파일·변경 뒤 snapshot의 확인을 섞지 않는다. |
| 비용·정산·누적 출처 | 실제 수행별 비용, 현재 계정 원장, 파일 기준 누적 | 응답 유실·중복으로 차감/무료 사용/누적을 반복하지 않는다. |

`OwnerRevision`은 UI 변경 권한을 막는 구분이다. 이미 접수한 요청의 실제 수행·응답은 원 요청에 귀속한다. 탭 인계만으로 그 응답을 오래된 맥락의 응답으로 바꾸지 않으며, 결과 적용은 맥락·페이지·범위·결과 버전으로 따로 검사한다. 반대로 파일 복원 전 응답은 새 맥락에 자동 적용하지 않는다.

서비스의 시각·사건 순서가 기한 판정 권한을 가진다. 클라이언트 타이머는 안내다. 감지 확인 시각, 마지막 유효 통신, 단절 회차, 공급사 연속 대기 회차와 각 기한을 따로 기록한다. 서비스 시계의 일관성과 사건 처리 경합은 구현 검증 항목이다.

## 4. 논리 서비스 계약

### 4.1 공통 입력·응답·권한

명령은 명령 ID, 의도·대상과 해당 행동에 필요한 예상 맥락/소유권/편집·결과 버전을 받는다. 서비스가 현재 계정·접근·소유권을 검증한다. 읽기 권한과 편집 권한은 다르며 보기 전용 탭의 조회 성공은 변경·실행 권한이 아니다.

응답은 대상·현재 상태 버전·판정 근거·보류 이유·조회할 참조와 함께 다음 사실을 구분한다: **변경 확정, 접수 후 확인 중, 보류, 버전/의도 충돌, 수행 확인 불명, 기존 명령 결과**. 이 구분은 제안된 의미이며 단일 성공 flag나 특정 HTTP status를 확정한 것이 아니다. 접수만 확인한 응답에는 종결/종료 완료를 넣지 않는다.

변경 전에 동일 명령의 기존 처리 결과를 대조한다. 동일 명령·동일 의도의 재전송은 새 부작용을 만들지 않는다. 기존 응답 조회에도 현재 접근 권한을 확인하며 과거 권한의 조회 결과로 새 변경 권한을 부여하지 않는다. 서로 다른 새 명령이 같은 대상 버전을 변경하려 하면 현재 버전/단일 활성 참조를 함께 검사한다.

| C07 · 저장 시점 캡처·파일 생성 | 현재 소유권, 반영 확인된 편집 버전. 정상 저장 종료는 해당 현재 요청 종결·실행/수행불명 없음 | 동일 시점 snapshot·필수 자산을 확보한 뒤 내보내기 생성·검증. 정산 확인 중은 그 상태로 포함 | snapshot/자산/내보내기 상태 조회. 같은 캡처의 생성만 재처리. 확인 못 한 필수 자산이면 완료 파일로 인정하지 않음 |

| C09 · 다운로드 요청 사실 전달 | 살아 있는 같은 맥락·현재 소유권, 이번 검증 파일·현재 접속의 요청 사실/확인 가능한 오류 | 브라우저에 다운로드를 요청한 사실을 기록. 수신 완료·OS 저장·보관 확인으로 승격하지 않음 | 같은 내보내기 상태 조회·다운로드 재제공. 전송 실패를 정상 종료로 전환하지 않음 |

| C11 · 프로젝트 파일 열기 | 현재 계정·검증 가능한 만든 계정/접근, 지원 구조·필수 자산 | 검증한 저장 시점 구성으로 새 맥락을 생성. Q18-A로 후속 다른 맥락의 제외를 덧씌우지 않음. 요청·원장·잠금 재생 없음 | 복원 판정·현재 서비스 사실 조회. 다른 계정은 거부, 만든 계정 확인 불명은 보류. 원 파일 보존 |
| C12 · 계속/원 설정 새 재시도 | 현재 편집 권한·계보 페이지의 활성 요청 대조, 원 범위/설정·checkpoint 호환성·현재 무료/유료 조건 | 종결한 이전 요청 또는 복원 맥락에서 명시 새 요청을 접수. 성공 단계는 읽기 재사용. 첫 실제 시작만 새 무료 사용 대상 | 동일 명령 접수·현재 요청 조회. 수행불명·원 모델 불가·호환 불명은 보류하고 자동 대체/앞 단계 재실행 금지 |
| C13 · 기존 페이지/영역 재번역 | 기존 재번역 UI의 명시 의도·현재 설정·범위·현재 결과 버전·단일 활성 요청·실행 조건 | 새 설정의 별도 요청. 성공 시 지정 범위 교체, 실패 시 기존 결과 보존 | 동일 요청 조회. Q17-A 보류 안내는 이 기존 기능으로 연결하며 안내 안의 새 모델 선택을 만들지 않음 |

일반 프로젝트 파일 저장은 검증 가능한 현재 상태를 담을 수 있지만 실행 중/수행불명 상태의 과거 값이 복원 실행 권한이 되지는 않는다. 이를 Q1-A 정상 저장 종료 완료로 표현하지 않는다. 명시적 저장하지 않고 나가기는 기존 강한 경고·종료 선택 경로를 유지하며 파일 오류나 무응답이 그 의도를 대신하지 않는다.

### 4.3 서비스 사건·시계·실행·반영 경계

| ID·사건 | 확인·전이·보존 규칙 |

| E09 · 라이브러리 접근 만료 | 마지막 실제 결과 보관 성공 기준 30일의 접근/보관 경로를 적용. 상태 조회·저장 의도·비용 대조가 결과 보관 기한을 연장하지 않음 |
| E10 · 활성 요청의 원 모델/계약 사용 불가 확인 | 남은 필수 단계의 사용 불가가 확인되고 실행 중/수행불명 단계가 없으면 Q19-A로 요청 중단·활성 참조/잠금 해제를 확인. 기존 결과·수행·비용·무료 시작 보존. 실행/불명이 남으면 E06으로 대조 후 안전한 경계 확인. 일시적 제한/사용 불가 불명은 이 종결 근거가 아님 |

유효 C05/C06이 확인되면 기존 단절 회차를 끝낸다. 이후 새 E01은 새 5분 회차다. 공급사 연속 대기는 상태 조회·재접속·탭 인계·종료 시작으로 초기화하지 않는다. 만료/회복/단계 시작은 같은 현재 권한 판정을 거치며 기한 전에 이미 발행·실제 시작한 근거를 뒤늦은 만료로 미실행으로 고치지 않는다.

호출 직전 서비스 가드와 외부 공급사의 실제 실행을 한 트랜잭션으로 묶을 수 있다고 가정하지 않는다. 발행 경합의 실제 상태를 확인할 수 없으면 수행불명으로 남긴다. 공급사 조회·안전한 중복 방지 수단이 확인되지 않으면 자동 재호출하지 않는다. 실행 여력 확보·호출 의도는 무료 선사용·잔액 선차감이 아니다.

상태 종료나 30일 만료가 수행·비용 대조 기록을 자동 삭제하는 근거가 되지는 않는다. 다만 내부 대조 기록의 존재를 종료 뒤 편집 복구나 만료 이미지 재다운로드 권한으로 사용하지 않는다. 정확한 보존 기간·접근 통제·물리 정리·운영 권한은 기술/운영 결정 전 상태로 둔다.

### 5.3 snapshot·복원 자료·호환성 판정

파일에는 같은 캡처 시점의 최초 원본, 페이지 구성/순서·스킵·현재 번역/수동 수정·영역/식자 자료, 현재 설정·프로젝트 상태, 필요한 편집 자산, 원 수행/성공 checkpoint·재개 자료와 검증 가능한 출처, 파일 기준 누적/미확정 참조를 연결한다. 필수 자료의 실제 구조·지원 버전은 후속 파일 계약에서 정한다. 종료된 서버 맥락의 임시 URL만으로 편집 복원을 보장하지 않는다.

계정 secret·현재 권한·잔액/무료 사용의 복원 명령·Undo/Redo는 파일에 넣지 않는다. 과거 활성/정산 값은 당시 상태/조회 참조이며 실행·차감 재생 명령이 아니다. Q16-A의 만든 계정은 파일의 임의 ID나 자산 해시로 증명하지 않으며 검증 가능한 발행 출처와 현재 접근을 대조한다.

캡처는 서비스에 반영 확인된 편집 버전을 기준으로 한다. 화면의 미전송/미확인 초안은 포함 확인 전 파일에 저장됐다고 안내하지 않는다. 캡처 도중 다른 버전이 섞이면 실패이며, 캡처 후 편집·결과 변화는 새 snapshot을 요구한다. 캡처 후 계정 정산 확인만 바뀌는 것은 과거 파일을 갱신하거나 정상 종료를 정산 완료까지 지연하는 근거가 아니다. 그 파일은 캡처 당시의 미확정을 유지한다.

| 판정 | 확인할 내용 | 서비스·화면 결과 |
| --- | --- | --- |
| 편집 복원 불가 | 필수 구조/지원 변환 불가, 필수 원본·현재 편집 자산/내용 누락·손상 | 사유를 알리고 새 편집 맥락 생성 성공으로 표시하지 않음. 원 파일 보존 |
| 접근 거부/확인 보류 | 다른 계정이 확인됨 / 만든 계정·현재 접근 확인 불명 | 각각 거부/보류를 구분. 다른 계정 복사본이나 과거 서비스 기록 접근을 제공하지 않음 |
| 편집 복원 가능·재개 보류 | 편집 자료는 유효하지만 단계 입력/크기/방향/좌표, 영역/마스크, 소비한 설정, 산출물/단계 계약·출처가 비호환/불명 | 새 맥락의 편집 상태 복원, 해당 단계 재사용·실행 보류. 앞 단계 자동 AI 실행 없음 |
| 단계 재사용 가능 | 성공 확인·내용 검증·원 입력/범위·단계별 설정 의존성·후속 입력 모두 호환 | 새 사용자 요청이 읽기 참조. 과거 비용/무료 사용 재생·새 비용 부착 없음 |
| 현재 결과 적용 가능/충돌 | 현재 맥락·페이지·범위·예상 결과 버전·적용 ID | 호환 자산이어도 과거 맥락 응답/다른 결과 버전은 자동 적용 거부. 원 비용 대조 유지 |

단계별 설정 의존성은 그 단계가 실제 소비한 값으로 검사한다. 원 설정 스냅샷 전체가 달랐다는 이유만으로 무관한 단계의 재사용을 인정하거나 거부하지 않으며, 소비한 의존성을 모르면 보류한다. 종결 요청의 새 재시도·복원 checkpoint에서 모델 사용 불가는 Q17-A의 기존 재번역으로 안내한다. 활성 요청은 Q19-A의 E10 안전한 중단을 확인한 뒤 C13이 가능하며, 그 전에 단일 활성 요청 제한을 우회하지 않는다. 이미 끝난 모델 단계의 단순 가용성 변화만으로 요청을 중단하지 않고 남은 필수 단계에서 실제 필요한지 확인한다.

파일 기준 누적은 캡처 때 확인된 정상 완료 유료 누적과 그 출처를 유지하고 복원 맥락의 새 정상 완료·정산 확인분만 추가한다(Q8-A). 과거 실패 비용·다른 맥락의 파일 후 성공분을 합치지 않는다. 미확정 참조는 조회용으로 남기고 0/완료/면제로 바꾸지 않으며 현재 원장에 과거 차감을 재생하지 않는다.

## 6. 화면 계약

화면은 의도를 전달하고 확인 중 상태를 표시한다. 서비스 사실을 받기 전 로컬 타이머·성공 토스트·버튼 상태만으로 만료·종결·잠금 해제·종료를 확정하지 않는다. 각 U행의 명령/조회와 보존 기록은 R 추적표에 연결한다.

| ID·상황 | 표시할 사실·안내 | 허용 행동·확인 중 상태·실패 복구 |
| --- | --- | --- |
| U01 · 숨김/탭 이동 | 화면 상태와 서비스가 확인한 연결·요청 상태를 구분 | 숨김만으로 종료/취소하지 않음. 복귀 시 최신 상태 조회, 오래된 상태로 실행 승인하지 않음 |

| U06 · 취소 접수·종결/수행 확인 중 | 현재 페이지 마무리·다음 페이지 차단, 수행불명은 확인 중 | 완료/실패/안전한 중단 확인 전 잠금 해제·두 번째 요청 없음. 시간만으로 실패/비용 0/무료 복구 표시하지 않음 |

| U08 · 저장하고 나가기·계속 작업 | 종료 접수/현재 페이지 마무리/반영 확인/캡처/파일 생성 단계의 사실 | 새 시작 차단. 미전송 편집 초안 반영 확인 뒤 캡처. 살아 있는 맥락에서 계속 작업 가능하되 종결 요청은 재생하지 않음 |

인계 중 이전 탭의 미전송/미확인 초안을 서비스가 새 탭으로 옮겼다고 추정하지 않는다. 기존 탭은 초안을 조용히 삭제하거나 과거 권한으로 재전송하지 않고 저장 미확인 상태를 구분한다. 새 탭은 서비스 반영 확인 상태를 조회하며 초안·현재 값 충돌을 숨기지 않는다. 실제 초안 보존·인계 지연의 범위는 브라우저/서비스 통합 검증 대상이다.

`파일을 보관했어요`는 이번 검증 파일의 다운로드 요청 이후 별도 사용자 확인이다. 현재 소유 탭은 로컬 미전송/미확인 초안과 캡처 뒤 로컬 변경을 검사하고, 반영 확인 전에 보관 확인 명령을 보내지 않는다. 서비스는 현재 소유권·종료 절차·K09의 검증/확인된 오류·서비스 반영 편집 버전·현재 요청 종결을 다시 검사한다. 서비스가 전달받지 못한 로컬 초안의 존재·내용까지 검증한다고 약속하지 않는다. 초안 세대·반영 응답 연결은 실제 브라우저/서비스 기술 계약과 S15/S29에서 검증한다. 브라우저 수신 확인 수단 부재와 확인된 전달 실패는 구분하며, 전자는 사용자 확인 경로를 사용하지만 후자는 해결 전 정상 종료를 거부한다. 일반 다운로드 호출·서버 응답을 OS 저장 증명으로 표시하지 않는다. 파일 실패는 저장 없이 나가기의 명시 선택을 대신하지 않는다.

오류·재조회 안내는 현재 값과 사용자 초안을 보존하고 해당 행동으로 돌아갈 초점을 제공한다. 포인터와 키보드 경로, 상태 안내 접근성, 보류 이유의 전체 내용과 좁은 화면에서의 주요 행동은 7절의 실제 브라우저 검증 항목이다. 예측 크레딧·선차감·근거 없는 진행률/회복 ETA는 추가하지 않는다.

## 7. 검증 방법·사례·관측 계약

모든 사례는 **검증 설계이며 실행 상태 NOT RUN**이다. 인공 계정·프로젝트·이미지·파일과 fake credential을 사용하고 실제 사용자 자료·비밀정보는 fixture/로그에 넣지 않는다. 실제 기술·구현이 정해진 뒤 해당 실행 경로의 테스트 파일·명령을 선택한다.

## 8. 검증 결과와 증거를 기록하는 방법

현재 결과는 문서 작성·대조뿐이다. V1~V5와 S01~S31은 전부 NOT RUN이며 아직 테스트 코드·명령이 없다. 후속 실행은 구현 버전/환경, 사례 ID·인공 입력, 실제 실행한 경로·명령, 관측 기록과 기대값 대조, 결과·남은 제한을 기록한다.

- **PASS:** 기록한 환경/경로에서 해당 assertion과 부작용 관측을 통과한 범위. fixture PASS를 브라우저/실제 공급사 성공으로 확대하지 않는다.
- **FAIL:** 실행한 사례에서 기대 계약 위반·검사 실패를 확인한 결과. 테스트 환경 오류와 제품 결함을 구분한다.
- **BLOCKED:** 실제 실행을 시도했으나 필요한 자산·서비스·권한·환경 조건이 없어 중단한 근거가 있다. fake로 대체하여 통과로 기록하지 않는다.
- **NOT RUN:** 실행하지 않은 검증. 문서 검토만으로 BLOCKED/PASS를 부여하지 않는다.

브라우저 증거는 실제 입력·화면/초점·서비스 응답/버전·관련 보존 기록을 연결한다. 공급사 근거는 실제 지원 기능·참조/응답·조회/사용량 범위와 일시를 기록하되 credential·프로젝트 원문은 로그에서 제외한다. 실제 파일 검증은 원 파일 보존·지원 구조/자산의 전체 검사와 적용 판정을 남긴다.

문서 검사는 [검증 참조](../../agent-validation.md)의 L0 범위인 내용·참조·표·UTF-8·최종 diff/공백·확정 정책/추적 ID 대조다. 이 결과는 웹 서비스 동작·배포·릴리스 증거가 아니다.

## 10. 작성 완료 조건과 범위

R01~R24가 U/C/E/K/S와 출처를 연결하고, 각 명령의 확인/재조회·각 저장 인계의 재처리·각 사례의 허용/금지 부작용을 갖는지 교차 대조했다. Q15-A~Q19-A의 실제 선택과 기존 5분/10분·수행불명·정산·파일 확인 경계를 독립 검토하고 필요한 보완을 반영했다. 작성 결과와 문서 검사 범위는 계약 작성 플랜 5절에 기록했다.

문서 작성 완료는 이 논리 계약·검증 설계 검토안의 범위다. 9절의 기술 선택·구현·실행 검증이 끝난 상태나 기술 상세/배포 승인을 뜻하지 않는다. 후속 기술에서 계약 위반 또는 새로운 제품 분기가 드러나면 출처와 영향에 따라 계약/질문을 갱신한다.

## 11. 후속 기술 조사와 증거 연결

2026-10-03 [기술 요구·후보 비교·격리 실험](2026-10-03-manga-web-technical-options.md)에 TR01~TR12와 기존 R/C/E/K/S의 연결, 세 후보의 공식 보장·한계, P01~P06의 로컬 모형 실행과 미실행 범위, 첫 구현 흐름·선택 질문을 기록했다. 이 조사에서 기존 논리 계약·Q1~Q19는 변경하지 않았다. P의 연구용 PASS를 V1~V5/S01~S31 제품 PASS로 옮기지 않으며 해당 제품 검증은 **NOT RUN**이다. 후속 기술 선택·실제 타입/저장/파일·runtime 검증은 별도 범위다.
