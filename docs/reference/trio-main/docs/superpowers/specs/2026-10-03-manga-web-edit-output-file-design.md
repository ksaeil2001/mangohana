업무 원본은 [Domain Story](../../manga-translation-domain-story.md)다. 이 문서는 [워크스페이스 계약](2026-10-02-manga-web-workspace-contracts.md)의 C/K/S와 [준비 명세](2026-10-03-manga-web-preimplementation-readiness.md)의 CF/OB/FX를 [Postgres 실행 설계](2026-10-03-manga-web-postgres-execution-design.md)에 연결한다. 정책을 별도로 복제하거나 Electron의 `.ctp`/IPC로 구현한 문서가 아니다. 진행은 [기존 플랜](../plans/2026-10-02-manga-web-workspace-contracts-and-validation-plan.md)에 둔다.

## 1. 공식 설명과 적용의 범위

| 확인한 공식 설명 | 이 초안에 적용하는 판단 |
| --- | --- |
| PostgreSQL Read Committed의 연속 SELECT는 같은 transaction 안에서도 서로 다른 확정 상태를 읽을 수 있다. Repeatable Read는 transaction snapshot을 사용한다. [공식 transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html) | 결과/구성/폰트의 순차 조회만으로 시점 캡처를 보장하지 않는다. 캡처 transaction의 일관성·자산 pin/GC 순서를 설계하고 동시 변경으로 검증한다 |
| Node의 `crypto.sign`/`crypto.verify`는 byte 입력을 다루며 Ed25519에는 algorithm을 null/undefined로 지정한다. ## 2. 최소 기록과 명령 결과의 후보

기존 `CommandReceipt`, `WorkspaceContext`, `PageResultApplication`, `CheckpointAssets`의 의미를 유지한다. 각 결과 조회는 현재 인증/계정 접근을 다시 확인한다. 동일 명령 ID의 응답 조회가 오래된 권한·이미 만료된 자산을 제공하는 허가가 아니다.

| 후보 기록 | identity/보존할 사실 | 중복·경합 검사 |
| --- | --- | --- |
| ManualPageHistory | ContextId+PageLineage, HistoryRevision/cursor, 항목의 수정 범위·before/after 값·결과/공유 설정/자산 의존성·유효성 | 같은 살아 있는 맥락의 페이지별 이력. OwnerRevision은 명령 권한이며 이력 자체의 소유 context/page를 인계 때 바꾸지 않음 |
| ManualEditApplication | CommandId+정규화 의도, 현재 편집/결과 revision, 실제 적용/거부와 HistoryRevision | 값·이력·cursor 변경을 같은 DB 경계로 한 번 반영 |
| ExportCapture | ExportRef+purpose, 캡처 Context/구성 revision·시각·페이지 순서/결과 revision·불변 렌더 입력/자산 pin | 최종 ZIP과 정상 종료 프로젝트 파일의 purpose/gate를 구분. 응답 유실에 새 캡처를 몰래 만들지 않음 |
| ExportArtifact | ExportRef+생성 계약, 필수 entry 목록/상태·검증 산출물 참조/hash·전달 사실 | 같은 입력의 렌더/압축 재시도와 같은 검증 파일 재전달 구분. 부분 성공을 전체 완료로 전환하지 않음 |
| LibraryStoreOperation | AccountId+Project/PageLineage+ResultRevision+보관 의도, 객체 참조/digest·attempt·claim generation·보관/인계 사실 | 동일 미완료 작업의 자동/사용자 재시도 중복 방지. 성공한 같은 작업은 최초 실제 성공 시각 유지 |
| LibraryPageHead | 페이지의 현재 제공 버전/보관 작업·실제 보관 성공 시각·30일 기한·접근/삭제 상태 | 옛 보관 작업의 늦은 성공이 새 head/version/기한을 되돌리거나 갱신하지 않음 |
| TrustedIssuerKey | 서비스가 신뢰하는 key ID/algorithm/public verifier·사용 목적/형식·발행/검증 허용 상태 | 파일의 key ID는 제한된 선택자. 파일의 공개키/URL을 믿는 키로 등록하지 않음 |
| ProjectRestoreAssessment | 원 파일/manifest 검증 근거, 만든 내부 계정/현재 접근, 필수 편집/선택 checkpoint 각 판정·새 맥락 참조 | 편집 복원과 AI 단계 재사용/현재 요청·원장 조회를 각각 판정 |

형식/validation·정확한 SQL 타입·HTTP/error code는 후속 인계 대상이다. 이미지와 원문을 일반 명령 로그에 복사하거나 이 표를 대용량 DB blob 저장의 승인으로 사용하지 않는다. 최소 근거의 구체적 기간/운영 접근은 미정이며 라이브러리30일을 요청/정산/파일 verifier 수명으로 전용하지 않는다.

## 3. 페이지별 수동 수정과 Undo/Redo

허용 수동 항목은 대사·줄바꿈·글자 크기·폰트다. 색/좌표/이동/회전/지우기나 AI 결과 자체의 Undo를 새로 추가하지 않는다. 현재 owner·살아 있는 context·현재 페이지/결과 revision·활성 요청/편집 잠금·수정 값 validation을 서비스가 검사한다. 잠금 중 Undo/Redo도 수동 변경 명령이므로 거부하며 보기/원본 비교·다른 페이지 탐색은 기존 정책을 유지한다.

1. 현재 계정/context/page와 예상 OwnerRevision·EditRevision·HistoryRevision을 검사하고 동일 CommandId 의도를 대조한다. 동일 의도 이미 확정이면 적용 결과를 조회하고 현재 projection과 분리해 반환한다.
2. 새 수동 수정은 현재 값의 before/after와 의존성을 기록하면서 결과/편집 revision을 올리고 이력을 추가한다. Undo 뒤 새 수정이면 이전 Redo branch를 같은 transaction에서 폐기한다.
3. Undo는 현재 cursor 앞의 적용된 항목을, Redo는 cursor 뒤의 되돌린 항목을 이력 순서에 따라 선택하고 해당 항목의 유효성·현재 의존성을 검사한다. 항목이 무효/불명이면 이유를 표시하고 새 AI 결과를 복원하지 않는다. cursor 이동·값 적용·revision·receipt를 같은 경계로 확정한다. 무효 항목의 탐색 표시/다음 유효 항목 선택 UI는 남은 화면 상세이며 건너뛴 경우에도 현재 값·의존성을 확인한다.
4. 성공 AI 재번역의 결과 적용과 Q32 영향 이력 무효화를 같은 DB 적용 경계에서 수행한다. 겹침 항목은 무효화하고 비겹침도 실제 의존성 변화가 있으면 유효로 가정하지 않는다. 단순히 페이지의 전체 revision이 올랐다는 사실로 모든 비겹침 이력을 무조건 지우거나 유지하지 않는다.
5. 명시적 탭 인계는 context/page 이력을 유지하면서 owner 세대만 바꾼다. 옛 owner의 늦은 수정/Undo는 현재 세대로 거부한다. 인계 직전 이미 서비스가 확정한 수정/Undo는 조회 후 새 owner가 이어간다. 미전송 로컬 초안은 확정 이력이라고 취급하지 않는다.

일관된 잠금 순서와 원자적 조건부 쓰기 범위를 정해 수동 명령·AI 적용·인계가 경합해도 한 순서로 확정한다. DB-only 재시도 안에 렌더/객체 쓰기/외부 AI 호출을 넣지 않는다. 새 프로젝트 파일 복원·정상 종료·5분 맥락 만료는 이력을 이어 쓰는 경로가 아니며 history 접근을 끝내고 이력 삭제를 처리한다. 정확한 물리 정리 방식/기한은 별도 운영 상세로 남기되 종료 후 다시 제공하지 않는다.

화면은 현재 페이지 기준 Undo/Redo 가능 여부·잠금/무효 사유·명령 반영 중/충돌을 표시한다. 응답 유실을 무조건 실패로 취급해 다른 명령을 자동 발행하지 않고 동일 receipt/현재 값·history를 대조한다. 조회 응답이 사용자의 새 로컬 초안을 덮지 않는다.

## 4. 최종 ZIP의 캡처·생성·전달

Q33-A로 현재 확정 구성/순서/결과를 즉시 캡처한다. 진행 중 새 AI 결과가 아직 없으면 이전 확정 결과, 그것도 없으면 원본을 사용한다. 제외 페이지는 빼고 스킵 페이지도 현재 확정 결과를 넣는다. 미전송 편집 초안·미확정 AI 응답은 캡처한 확정 결과로 표시하지 않는다. 화면에는 저장 시점과 새 결과를 받으려면 다시 생성해야 함을 알린다.

### 4.1 시점 캡처와 자산 확보

후보 방식은 캡처 시 DB의 구성/순서·페이지별 결과·렌더 조건을 같은 일관된 transaction snapshot으로 읽고 불변 asset 참조에 pin을 확정하는 것이다. 별도 조회의 revision만 모아 시점이 일치했다고 주장하지 않는다. 모든 쓰기/GC가 이 참조와 잠금·retry 조건을 지켜야 하며 Repeatable Read의 serialization 충돌도 캡처를 다시 판정하는 DB-only 경계에서 처리한다.

캡처의 완전한 입력에는 원본/확정 결과의 불변 자산, 최종 대사/줄바꿈/식자 값, 폰트 파일 버전/사용 조건, layout/렌더 계약 버전이 필요하다. 자산 내용/존재가 확인되지 않은 캡처를 준비 완료로 표시하지 않는다. 후속 편집으로 현재 pointer가 바뀌어도 기존 pin을 최신 이미지로 바꾸지 않는다. DB pin 이전의 GC와 객체 존재 확인 틈은 storage 선정 뒤 장애 실험으로 해결할 항목이다.

D08로 같은 캡처 재시도창은 생성부터30분과 현재 live 맥락/권한 유효기간의 교집합으로 선정했다. 실제 자원 한도와 pin/GC/삭제 적합성은 후속이다. pin이 워크스페이스의5분 유예·정상 종료/접근 철회를 늘리거나 라이브러리 삭제를 막는 근거가 되지 않는다. 살아 있는 맥락의 유효 입력과 라이브러리 전용 사본의 출처/수명을 구분한다. 더 이상 유효한 입력을 확보하지 못하면 같은 캡처 재시도 가능으로 표시하지 않고 이유를 알린다. 몰래 AI를 재실행하거나 만료 라이브러리에서 자산을 보충하지 않는다.

### 4.2 전체 성공과 재시도

entry는 내부 페이지 ID/순서와 명시 출력 이름의 대응으로 만든다. 이름 중복·대소문자/정규화 충돌·경로 탈출을 차단하며 후속 위임 D08로 확정 순번/max(4,개수 자릿수) 이름·PNG압축6을 첫 기준으로 선정했다. 실제 렌더 품질/자원 적합성은 후속이다. Q46-A로 모든 페이지 entry는 PNG이며 원본만 있는 페이지도 캡처 원본에서 PNG를 출력하고 원본 bytes는 보존한다. PNG로 저장해 JPEG 원래 손실이 복구되거나 캡처와 다른 결과가 생겼다고 주장하지 않는다. 렌더와 압축은 AI 처리와 분리한다.

Q36-A로 필수 페이지 렌더가 하나라도 실패하면 전체 ZIP 실패/실패 목록을 반환한다. 성공한 부분 산출물을 내부 작업 결과로 보존할 수 있어도 부분 ZIP을 성공 다운로드로 제공하지 않는다. 모든 필수 entry의 개수/순서/자산 대응·형식/내용과 압축 산출물 검증 뒤에만 전체 다운로드 가능으로 전환한다.

확인된 실패는 같은 ExportRef/불변 입력의 필요한 렌더·압축만 재시도한다. 객체 생성 성공 뒤 DB/응답 유실이면 동일 산출물의 검증/인계 상태부터 대조한다. 이미 검증된 파일의 전송 실패는 같은 파일을 다시 전달한다. 같은 캡처의 재렌더가 언제나 동일 ZIP bytes를 만든다는 새 결정론적 압축 약속은 하지 않는다. 새 편집/AI 결과를 포함하려는 요청은 새 ExportRef다.

조회/렌더/압축/재전달 때문에 별도 AI 요청·무료 추가 사용·같은 비용 중복 차감을 만들지 않는다. 이미 승인된 기존 요청의 정상 수행 및 최초 미정산 비용 정산은 독립적으로 진행할 수 있다. ZIP이 기존 request 권한/기한/holds를 바꾸거나 정상 저장 종료의 프로젝트 파일 조건을 대신하지 않는다.

## 5. 페이지별 결과 보관과 실패 복구

### 5.1 실제 성공·기준 시각·버전

검증된 결과 이미지의 보관 의도를 PageLineage+ResultRevision+작업 ID에 연결한다. 실제 객체 보관/내용 검증의 확실한 성공 근거를 확보한 시각과 DB 반영/응답 시각은 구분한다. 원 성공 시각을 확인할 수 없으면 그 사실을 보류하며 DB 재처리 시각으로30일을 새로 시작하지 않는다. 정확한 성공시각 근거의 획득은 선택 storage의 조건을 확인해야 한다.

같은 작업의 성공을 receipt로 대조할 때 최초 실제 성공 시각과 원30일 기한을 반환한다. 실패/조회/다운로드/정산 대조가 기한을 갱신하지 않는다. 한 페이지 새 결과의 실제 보관 성공만 그 페이지 기준을 바꾸며 다른 페이지 기한은 그대로다. 옛 결과의 늦은 성공은 그 원 보관 사실을 대조하더라도 최신 페이지 제공 pointer/기한을 덮지 않는다. 이를 과거 이미지 버전 다운로드 기능의 추가 승인으로 사용하지 않는다.

### 5.2 제한 자동 재시도와 사용자 요청

Q37-A로 저장 공정만 제한 자동 재시도한다. 객체/검증/DB 인계 각 상태와 attempt·claim generation을 보존한다. 작업 claim 만료는 이전 저장의 성공/실패를 확정하지 않는다. 객체 성공 뒤 DB/응답 유실은 먼저 같은 참조/digest/성공 근거를 대조해 저장 반복/시각 갱신을 막는다.

자동 재시도와 사용자 보관 요청이 같은 미완료 작업에 겹치면 같은 작업을 조회/조정하며 새 worker 세대만으로 attempts를 초기화하지 않는다. 계속 실패하면 보관 실패·유효 결과 존재 여부·재요청 가능/불가 이유를 보여준다. 완료한 자동 시도 묶음 뒤 명시적 사용자 재요청의 작업/attempt 연결·한도/간격·오류별 retry 조건은 아직 미정이며 동일 명령 재전송과 구분한다. 후속 위임 D09의 초기값은 저장-only 최초1회+5초/30초 뒤 각1회 총3회다. 성공한 같은 보관 작업은 원시각 조회로 유지한다.

현재 접근/결과 자산이 유효할 때만 재요청을 받는다. 맥락/자산 만료·접근 철회 뒤 자료가 없으면 미저장 상태를 복구한다고 약속하거나 재시도 가능으로 표시하지 않는다. 저장 실패를 AI 실패로 바꿔 AI/무료 사용을 다시 만들지 않는다. 기존 비용의 최초 정산은 보관 성공과 별개다.

### 5.3 만료와 실제 삭제

서비스 시각이 페이지의30일 기한 이상이면 새 라이브러리 조회/다운로드 권한을 주지 않는다. 결과 객체·복제본/버전·library 캐시·백업·전송용 사본·내부 이미지 사본까지 실제 삭제 대상/제공 경로를 목록화한다. 출처가 다른 유효 맥락/사용자 파일의 자산 참조를 라이브러리 삭제와 혼동하지 않는다. 내부 원가/정산 기록으로 이미지 재제공을 우회하지 않는다.

LibraryPageHead와 별개로 모든 실제 보관 작업·객체의 원 성공 시각과 삭제 대상을 추적한다. 비현행·고아 객체를 최신 head의 갱신된 기한으로 연장하지 않는다. 원 기한이 지난 뒤 성공 사실을 발견하면 제공/head 반영 없이 삭제 대조 대상으로 처리한다. 원 성공 시각이 불명인 객체는 접근을 차단하고 유한한 정리 기준을 storage 선정 시 반드시 확정하며 무기한 보관하지 않는다.

삭제 요청/queued/한 URL의403을 실제 삭제 완료로 표시하지 않는다. 실패/지연은 미완료와 운영 대조로 남긴다. 만료 직전 이미 진행 중인 전송의 취소/마무리는 미선택이며 기존 실제 삭제와 양립하는 근거부터 검증한다. 기한 전 수락 사실만으로 만료 뒤 원본/전송용 사본을 계속 읽어 보내는 권한을 확정하지 않는다. 이미 단말에 전달된 bytes를 서버가 회수한다고 약속하지 않는다.

## 6. 프로젝트 파일의 후보 발행/검증 형식

Q21-A는 서비스의 믿는 키로 발행 서명을 확인하고 만든 계정의 현재 접근을 확인한다는 방향이다. 후속 추천 위임 D06으로 **ZIP container+정확한 UTF-8 manifest bytes+detached Ed25519 서명+자산 digest**를 첫 v1 상세 기준으로 선정했다. `.manga-project.zip`/필수manifest 입력은 추천 인계5절을 따른다. 실제 key host/migration·parser/수치 적합성과 공개지원은 후속이다. 기존 Electron `.ctp` 호환 약속을 만들지 않는다. 서명은 파일 내용의 암호화를 뜻하지 않으며 로컬 파일 기밀성/잠금 방식은 별도 미정이다.

### 6.1 서명 범위와 신뢰 경계

후보 서명 payload는 고정된 앱/형식 목적 prefix와 manifest의 원 UTF-8 bytes를 연결한다. 이는 Node Ed25519의 context 옵션 채택이 아니라 우리가 검증할 입력 bytes를 구분하는 설계다. JSON을 파싱/재직렬화한 bytes로 서명을 검증하지 않는다. manifest에는 format/schemaVersion·issuer/key ID/algorithm·ExportRef/시각·만든 내부 AccountId·프로젝트/페이지 계보·구성/순서/결과·필수 자산 목록/길이/digest·수동 값/설정·누적 기준/미확정 정산 참조·선택 checkpoint의 계약/의존성을 포함한다.

자산별 SHA-256 digest와 길이를 signed manifest에 연결하는 후보로 전체 필수 자산의 내용 대응을 확인한다. 파일 전체 hash는 추적/전달 무결성의 보조 근거이며 서명/현재 접근을 대신하지 않는다. signature envelope의 key ID/algorithm과 signed manifest 값이 일치하고 서비스 allowlist의 같은 목적/형식 key여야 한다. file의 공개키나 키 URL·알고리즘 요구를 서비스 신뢰 설정으로 승격하지 않는다.

manifest 자체·container directory/entry 수/길이/확장 크기의 제한된 검사부터 수행한다. 중복 JSON key·중복/case/정규화 entry·절대/상위 경로·symlink/외부 링크·미등록 entry·과도한 확장/압축 비율을 제한/거부하는 후보를 둔다. 파일의 entry 이름을 서버 파일 경로로 사용하거나 외부 URL 자산을 자동 fetch하지 않는다. 실제 수치·parser/ZIP 라이브러리·streaming 메모리 조건은 후속 검증 전에는 운영 활성화하지 않는다.

### 6.2 필수 편집 복원과 선택 AI 단계 재사용

필수 자산은 저장 시점 페이지의 원본·현재 편집/출력 재현에 필요한 자산·지원 폰트/레이아웃 근거다. 그 실제 범위를 누락하지 않게 manifest/schema에서 작성한다. 필수 자산 누락/손상·지원하지 않는 필수 구조이면 편집 복원 성공/새 맥락 성공으로 인정하지 않고 원 파일을 보존한다. 다른 계정이면 거부, 출처나 만든 계정의 현재 접근 확인이 불명이면 보류한다.

서명/필수 구조/자산 검증과 현재 접근이 유효하면 저장 시점 구성으로 새 맥락을 만든다. 다른 맥락에서 이후 제외한 페이지를 파일의 저장 시점 구성에 덧씌우지 않는다. Undo 이력·활성 요청/잠금·과거 잔액/무료 원장을 새 맥락에 재생하지 않는다. Q8-A의 파일 기준 정상 완료 누적과 이후 새 맥락의 정상 완료분은 출처를 유지하고 현재 계정 원장과 분리한다.

선택 checkpoint 자산의 누락/손상/입력·범위·설정·모델/단계 계약 불일치는 그 checkpoint의 재사용 불가/불명으로 반환한다. 필수 편집 검증이 유효하면 편집 복원 가능 여부와 구분하고 새 AI로 선택 자산을 몰래 보충하지 않는다. container 전체/서명/필수 구조를 검증할 수 없는 상태까지 선택 checkpoint 실패로 축소하지 않는다.

원 파일 검증 뒤에도 현재 서비스의 계보 페이지 활성 요청·수행불명·정산/무료/잔액·실행 조건을 따로 대조한다. 조회 실패/불명은 실행 확인 보류이며 과거 파일의 완료/잠금 없음으로 해제하지 않는다. 사용자가 계속/원 설정 재시도를 선택할 때 성공 단계의 현재 호환성을 다시 검사하며 필요한 원 모델/계약 불가는 기존 재번역 기능으로 안내한다. 서명이 유효한 파일을 열었다는 사실만으로 새 AI 요청이나 단계 재사용 권한이 생기지 않는다.

### 6.3 키 수명과 미해결 운영 조건

서비스만 발행 개인키를 소유하며 프로젝트 파일/브라우저/일반 로그에 넣지 않는다. 믿는 verifier catalog·형식별 허용 algorithm·key ID·회전/발행 종료/검증 허용 상태를 별도 관리한다. Q22-A로 정상 회전 시 과거 지원 파일의 검증에 필요한 공개키/최소 근거를 현재 계정 접근/지원 형식 동안 유지한다. 새 발행 개인키와 과거 verifier 보존은 다른 목적이다.

발행 키 유출/폐기/신뢰 근거 불명은 해당 파일의 복원 보류/거부 사유다. 유출 키의 서명만으로 과거 정상 발행과 위조를 구별할 수 있다고 약속하지 않는다. 별도 신뢰 근거를 활용한 사고 복구·키 보관/백업·접근 소멸/지원 종료 절차는 후속 운영 결정이다. 이를 Q21-B 발행 등록부가 이미 선택됐다고 기록하거나 모든 구형 파일의 영구 복원을 보장하는 근거로 삼지 않는다.

## 7. 정상 저장 종료와 사용자 보관 확인

정상 저장 종료는 첫 실제 시작 전 요청·다음 페이지·새 요청을 차단한다. 이미 실제 시작한 현재 페이지 요청은 현재 권한·실행 조건·보류 및 공급사 대기 규칙 안에서 마무리하고, 정상 완료/안전한 중단 및 실행 중·수행불명 없음 확인 뒤 파일 캡처로 진행한다. 단절이 확인되면 별도의 새 비용 단계 차단 규칙을 적용한다. 공급사10분 만료는 안전한 요청 중단을 확인한 상태를 저장한다. 단절5분/접근/owner 조건과 기존 결과·무료/실제 비용·미정산 상태를 보존한다.

같은 시점 snapshot/필수 자산 확보→파일 생성/서명·검증→다운로드 요청→사용자의 `파일을 보관했어요` 확인→조건부 context 종료 순서다. 파일 검증/전달 실패가 남아 있거나 캡처 뒤 서비스 반영 편집 버전이 바뀌면 과거 확인으로 종료하지 않는다. 로컬 미전송 초안은 소유 탭이 먼저 확인해 반영/새 캡처를 준비하며 서버가 보지 못한 초안을 안다고 가정하지 않는다.

사용자 확인은 보관했다고 진술한 사실이며 OS/local 파일 저장을 입증한 사실은 아니다. 확인 명령은 이번 ExportRef·현재 OwnerRevision·캡처/편집 버전·종료 intent를 묶는다. 동일 확인/종료 receipt 유실은 원 결과 조회로 대조하고 새 다운로드/중복 종료/AI를 자동 발생시키지 않는다. 미해결 정산은 현재 계정의 독립 사실로 유지한다.

## 10. 업로드 후보의 검증·선택·수용·반영

Q31-B/Q40-A/Q41-A/Q42-A의 기술 연결이며 정책 원본은 Domain Story3.1절이다. 파일 전송의 성공과 파일 validation·페이지 반영 성공을 구분한다. 모든 단계에서 현재 인증/owner/context를 검사하고 원본 bytes를 보존한다. 업로드/중복 확인/순서 수정만으로 AI 요청·무료 사용을 만들지 않는다.

후보 `UploadCandidateManifest`는 업로드 의도·파일별 immutable source 참조/실제 길이/서비스가 검증한 digest·decode 판정/실패 이유·원 입력 순서·표시 이름·제안 순서·중복 관계·선택한 중복 항목·현재 구성 revision을 연결한다. 브라우저 선언 MIME/bytes/hash/목록 순서를 검증된 내용/사용자 의도로 가정하지 않는다. Q45-A의 정지 PNG/JPEG만 첫 입력으로 검증하고 실제 내용/decode를 확인한다. WebP/애니메이션을 한 프레임으로 몰래 변환해 인정하지 않는다. decode/확장/메모리/전송 안전 한도의 수치는 후속이다.

1. 전송/검증의 안전 한도를 먼저 적용하고 실제 불변 원본/내용을 검증한다. 무효 파일은 실패 목록, 유효분은 후보로 구분한다. Q31-B는 이 유효 후보의 부분 허용이며 전체 수용 초과를 앞부분 수용으로 바꾸는 계약이 아니다.
2. Q40-A로 파일명을 숫자 고려 순서로 정렬해 미리 보여 주고 명시적 순서 수정을 반영한다. 동일 이름/숫자·문자 정규화의 tie 규칙/정렬 계약 버전을 기술 상세로 고정해 UI/서비스/재전송의 순서를 일치시킨다. 실패분 새 업로드는 새 묶음의 선택 순서로 현재 맨뒤에 추가하고 옛 실패 슬롯을 자동 복구하지 않는다.
3. Q41-A의 같은 bytes 중복을 현재 맥락 기존 페이지/새 묶음 앞선 이미지와 대조해 중복분의 추가 항목을 확인한다. 사용자가 중복을 추가하지 않아도 비중복 유효분은 기존 정책에 따라 처리한다. 내용 digest/길이와 원본 검증 근거를 사용하며 시각적 유사도·표시 이름을 동일 내용의 증거로 사용하지 않는다. 명시 추가한 중복도 별도 PageLineage로 처리하고 같은 명령 재전송과 구분한다.
4. 페이지 반영 명령은 선택한 후보/순서·중복 선택 근거·예상 구성/OwnerRevision·정규화 의도를 포함한다. 현재 구성이 바뀌어 중복/순서/수용 근거가 낡으면 충돌/새 확인을 반환하고 예전 미리보기를 조용히 새 구성에 적용하지 않는다.
5. 원자적 DB 경계에서 현재 구성/수용 사실과 후보 전체를 재검사한다. Q42-A로 초과면 이번 후보 전체를 미반영하고 줄여 재선택 안내한다. 통과면 이번 후보의 페이지/계보·순서 append와 receipt를 함께 확정한다. 같은 의도 응답 유실은 원 receipt/페이지 참조를 조회한다. 반영 중 예외를 파일별 실패로 축소해 의도하지 않은 앞부분만 남기지 않는다.

업로드 자산 저장과 DB는 별도 인계다. 자산 성공 후 DB 실패/유실은 같은 업로드/자산/반영 의도를 대조하고 같은 이미지를 다시 올려야만 해결된다고 안내하지 않는다. 이미 페이지로 반영된 성공분은 같은 명령 조회로 반환한다. 후보 미반영/실패 임시 자산은 현재 접근/유한한 정리 정책으로 관리하며 정리 기간/방식은 미정이다. 명시 재선택과 동일 명령 재전송, 전체 사용자 취소와 중복분만 미추가를 각각 구분한다.

수용량 계산의 대상(논리 원본 bytes/자산 등)·수치/현재 project 비용은 아직 확정하지 않았다. 새 업로드의 처리 중 행동은 Q49-A 선택 완료이며11절의 활성 요청 종결 확인 뒤 허용/현재 guard를 따른다. 선택되지 않은 수치로 수용 권한을 활성화하지 않는다. 페이지 후보를 전부 commit했다는 사실만으로 원본 외부 전송이나 AI 권한을 부여하지 않는다. EOV17~19도 실제 실행 NOT RUN이다.

## 11. 처리 중 업로드·구성 잠금과 미래 요청 설정

Q49-A/Q51-A로 새 업로드/페이지 반영 및 제외·스킵·순서는 현재 활성 AI 작업이 완료/중단/실패로 종결 확인된 뒤 허용한다. 이 일괄/요청의 진행·대기·수행불명 상태를 DB에서 확인하고 일괄 페이지 교대 중 짧은 공백을 종결로 취급하지 않는다. 종료/만료·계정/탭 편집 권한 등 기존 거부 이유는 종결 확인 뒤에도 재검사한다. 다른 페이지의 허용된 수동 편집·보기/비교·ZIP은 구성 잠금 때문에 막지 않는다. 서비스의 조회 projection은 해당 행동의 가능 여부/거부 이유·근거 버전을 표시하며 브라우저 표시만으로 명령을 허용하지 않는다.

새 업로드 의도 접수/반영은 현재 guard를 재검사하고 AI 접수·구성 변경과 같은 맥락의 DB-only 경계에서 판정한다. 업로드 시작 뒤 AI가 먼저 접수된 race에서는 새 후보 반영을 허용하지 않고 기존 페이지/원본과 조회 가능한 업로드 결과를 보존한다. 같은 명령의 이미 성공한 결과는 현재 접근을 확인해 원 결과 조회이며 busy 때문에 새 실패/중복 페이지로 바꾸지 않는다. 임시 bytes의 안전 한도/정리 기간은 별도다.

Q50-B로 현재 설정 변경은 허용한다. 후보 SettingsRevision은 설정 변경/새 요청·일괄 접수의 서비스 확정 순서에 따라 캡처한다. 먼저 접수된 기존 일괄의 아직 실행 안 한 페이지도 원 캡처 설정을 유지하고, 변경 뒤의 별도 새 요청은 새 설정을 쓴다. 재접속/10분 대기 재개/실패 재시도·명시 인계로 원 설정을 다시 캡처하지 않는다. 수동 수정 값/기존 결과 자동 교체·AI 재실행/무료/원장/기한 변경을 만들지 않는다. 진행 페이지의 수동 잠금과 명시 재번역 성공의 교체 범위는 별개다.

실제 row/transaction 순서·DDL/HTTP 거부/충돌 code·화면 문구/갱신/기기 경합은 구현 인계에서 좁힌다. 이 설계 후보로 비용 실행이나 실제 구현을 시작하지 않는다.
