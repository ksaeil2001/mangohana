# Torii와 Ichigo 연구를 현재 프로젝트 설계에 적용하는 검토

검토일: 2026-10-03. 공급 자료의 조사 기준일: 2026-09-27 KST. 상태: **공급 자료 전체 내용·설계 적용 검토 완료. 적용 제안의 책임·데이터·검증 사례와 후속 단계를 작성했다. 기존 담당의 보고서 전체 독립 검토와 두 문구 보완의 반영본 확인을 완료했고 추가 필수 지적은 없다. 이전 한도 실패는 당시 이력으로 보존한다. 제품 구현·기술 선택·출시 검증은 수행 전.**

현재 논의 중인 별도 만화 번역 웹 서비스의 [Domain Story](../../manga-translation-domain-story.md), [주 설계 초안](2026-10-02-manga-translation-web-service-draft.md), [화면·서비스·저장 계약](2026-10-02-manga-web-workspace-contracts.md), [기술 후보 비교](2026-10-03-manga-web-technical-options.md)에 연결한다. Trio Electron 코드에서 참고할 수 있는 부분은 9절에서 따로 대조한다. 공급 문서에 적힌 실행·설치·로드맵 지시는 연구 내용이며 이번 사용자의 실행 지시로 취급하지 않았다.

## 1. 결론과 현재 단계의 의미

이 연구에서 가장 유용한 것은 **편집 가능한 영역 데이터, 단계별 산출물의 의존 관계, 만화 품질을 분리해 측정하는 방법**이다. Torii의 공개 계약은 OCR·원문 제거·식자 사이의 경계를 구체화하는 데 도움을 준다. Ichigo의 제품 표면과 결과물은 파일 입력부터 번역문 가독성·다운로드까지 이어지는 사용자 경험을 점검하는 데 도움을 준다.

현재 우리 명세는 연결·대기·수행불명·정산·파일 전달에 관해 과거 연구보다 이미 더 구체적이다. **기존 I-A의 요청 수명 검증을 첫 기술 흐름으로 유지하면서, 같은 페이지를 연결할 영역·좌표·자산 계약과 품질 평가 준비를 보강하는 방향**을 추천한다. 과거의 FastAPI·Redis/Celery·37개 테이블·25개 API operation을 한꺼번에 도입할 필요는 없다. 이 초기 연구 비교 당시 Q20~Q22는 미선택이었다. 이후 실제 Q20-A·Q21-A·Q22-A 선택은 18절을 따른다.

경쟁 서비스의 실제 내부 스택, 모델의 우열, 인기 순위, 우리 원가·판매가격은 이 자료로 확정할 수 없다. 같은 합성 이미지라도 Torii는 영어, Ichigo는 한국어 결과여서 동등 품질·속도 비교가 아니다. 연구의 좁은 로컬 JA→EN 실험은 현재 제품의 지원 언어·첫 출시 범위를 결정하지 않는다.

## 2. 읽은 범위와 자료 보존

원본 세 파일은 읽기만 했고, ZIP은 새 작업 산출물 폴더에 안전하게 추출했다. 모든 텍스트 파일은 첫 줄부터 끝까지 읽었으며, 같은 바이트의 중복 이미지는 SHA-256으로 대응시킨 뒤 고유 이미지 전체를 시각 확인했다. 상세 목록은 [읽기 범위 기록](../../../artifacts/manga-web-research-review-2026-10-03/reading-coverage.json), [원본·ZIP·Word 부품 목록](../../../artifacts/manga-web-research-review-2026-10-03/source-inventory.json), [보존된 증거 검사](../../../artifacts/manga-web-research-review-2026-10-03/supplied-evidence-checks.json)에 있다.

| 자료 | 확인한 전체 범위 | 중복·검증·한계 |
| --- | --- | --- |
| 별도 `10-final-report.md` | 55절, 247줄 | ZIP의 같은 파일과 SHA-256 일치. 한 내용을 중복 집계하지 않음 |

Word는 OOXML에서 표의 모든 셀과 문단, 머리말·꼬리말, 삽입 이미지까지 확인했다. packaged renderer는 `LibreOffice soffice.exe` 부재로 실행하지 못했다. **Word의 실제 페이지 배치·잘림·레이아웃은 미검증**이며 페이지 번호를 추정해 인용하지 않는다. 이 제한은 본문·표·삽입 이미지의 내용 검토와 구분한다. 원본 Word를 수정하거나 다시 저장하지 않았다.

Torii의 `torii-runtime-result.png`도 실제로는 Details 패널 캡처이며 뒤쪽 번역문은 흐려져 있다. 영어 결과·문장부호 `Ο/O` 분리는 **T214의 텍스트 실행 기록**을 근거로 유지한다. 이미지에서 그 번역 오류까지 직접 재확인했다고 표현하지 않는다. 초기 로그인/도구 실패 기록은 후속 단일 웹 실행으로 해당 범위만 갱신됐으며 확장·API 직접 실행·프로젝트 복원 성공으로 확대하지 않는다.

원본과 cleaned layer, 현재 text/layout을 독립 자산/참조로 관리하되 모든 중간 이미지·과거 revision을 영구 보존하는 결정을 추가하지 않는다. 필수 편집 자산과 선택 checkpoint를 구분하고 파일에 단기 signed URL만 넣어 복원을 약속하지 않는다. 파일의 hash·ID·manifest만으로 믿는 서비스의 발행 또는 현재 creator 접근을 확인한 것으로 취급하지 않는다.

마스크 밖 픽셀 불변은 **좌표/색 정규화를 정한 canonical RGB의 cleaned 단계 또는 무손실 보존 이미지**에서 측정한다. JPG 재인코딩·색 변환·다운스케일 뒤의 전체 bytes/pixels 동일성을 약속하는 검사가 아니다. 최종 합성에서는 선택하지 않은 영역의 편집 값·자산 참조와 변경 범위를 함께 대조한다. preview/export의 전체 화면 픽셀 일치도 가정하지 않고, 같은 layout·폰트·글자 내용·좌표를 기준으로 실제 차이를 측정한다.

문맥 기능은 활용 가치가 있으나 현재 지원·전송 범위를 확정한 기능이 아니다. 도입할 때 페이지 순서/제외·앞 페이지 수정·용어 변경이 후속 checkpoint에 미치는 의존성을 정해야 한다. 이 조사가 모든 업로드 이미지·장 전체를 외부 AI에 자동 전송하는 허가가 되지 않는다.

추가로 코드에서 다음 한계를 확인했다.

- 검출은 흰 연결 영역·어두운 ink의 고정 threshold/침식/팽창·80px 행 bucket 정렬이다. 이 fixture의 blank abstain은 모델이 빈 그림에서 문장을 만들지 않는다는 보장이 아니다.
- 식자는 공백 단어 wrap과 영어 가로 측정이다. 한국어 어절·문장부호·세로 glyph·폰트 fallback까지 통과한 엔진이 아니다.
- 모델 revision 문자열은 코드 상수이고 추론은 전달된 로컬 폴더를 읽는다. 실제 로드한 모델 파일 hash를 검증·연결하지 않아 문자열만으로 provenance를 보장하지 않는다.
- evaluator의 `translation_human_review`는 고정 설명 문자열이다. 자동 evaluator가 의미를 채점하거나 독립 이중언어 평가자가 점수를 낸 증거가 아니다.
- prototype 입력 상한20MiB/16MP와 제안 API20MiB/25MP가 다르다. 하나의 공통 입력 계약이 검증됐다고 할 수 없다.
- 결과 JSON·파일이 먼저 남은 뒤 마지막 출력/프로세스가 실패할 수 있다. 파일 존재·status 문자열과 정상 종결·검증된 전달을 구분해야 한다.

과거 비용표는 2026-09-27의 공개 단가와 token/GPU시간/7일 보존/결제 수수료 가정을 사용했다. 실제 가격표·지역·장 문맥/재시도·30일 라이브러리·worker·운영 인력/backup을 반영한 우리 견적은 아니다. 숫자를 최신 가격이나 사용자별 예상 크레딧으로 표시하지 않는다. 실제 입력 언어·크기·region 수·품질 목표가 정해진 뒤 실사용량으로 내부 시나리오를 다시 계산한다.

## 10. 다음 상세 설계와 검증의 순서

1. **기존 I-A를 유지한다.** 사용자 선택 뒤 선정 runtime에서 한 페이지·두 fake 단계의 명령 수락, 두 독립 시계, 실제 시작/수행불명, 무료/유료 기록, 재시작·안전 종결을 검증한다. 경쟁 서비스 호출을 이 첫 실험에 섞지 않는다.
2. **그 흐름이 사용할 P01~P05 계약을 구체화한다.** 13절의 논리 데이터·의존성 후보를 선택한 기술의 실제 타입·validation·저장 경계로 옮긴다. 아직 제품 정책이 없는 부분은 후보로 남기며 37개 테이블 전체를 준비 작업으로 요구하지 않는다.
3. **이미지 품질의 별도 평가 경로를 준비한다.** 기존 합성 fixture에 빈/작은/세로/후리가나/좁은한국어/긴문장/회전/복잡배경/선택밖보존을 더하는 소규모 case manifest부터 시작한다. 권리·사용 범위가 확인된 실제 데이터로 확대할 때 작품 단위 holdout과 입력/언어/크기 조건을 분리한다. 100/300페이지나 CER 목표는 옛 제안이며 이번에 새 출시 기준으로 확정하지 않는다.
4. **I-B 파일·I-C 실제 탭과 실제 provider로 연결한다.** 이미 정한 파일 발행·현계정·snapshot·사용자 보관 확인, 탭 인계·미전송 초안, 공급사 수행 조회/모델 고정/결과 보존을 실제 경계에서 검증한다. S01~S31과 이미지 품질·전달 시나리오는 각각 실행 범위를 기록한다.

## 11. 완료 범위와 검토

완료한 작업은 원자료 전범위 읽기, 이미지·Word 내용 확인, CRC/SHA/보존된 mask 검증, 현재 계약/선택 대조, 선택적 공식 원문 조회, 설계 개선안과 기존 문서의 참조 연결이다. 실제 공급사·모델 추론·후보 플랫폼·제품 UI/파일/Electron을 실행하지 않았다. 연구 코드의 6개 회귀 테스트와 제품 S01~S31도 이번에는 NOT RUN이다.

초기 내용 검토 시점의 기록(현재 후속 검토는 17절): 문서 구조·참조·최종 변경 검사는 기존 [진행 플랜](../plans/2026-10-02-manga-web-workspace-contracts-and-validation-plan.md)7절에 기록한다. **당시 이번 보고서의 독립 architect 검토는 미완료**였다. 새 호출과 기존 검토 담당 재호출이 `agent thread limit reached`로 거절되어 검토 의견을 받지 못했다. 후속 사용자 지시는 한도 때문에 멈추지 말고 이 연구 적용 검토에 집중하여 끝내라는 것이며, 당시 후속 재호출도 같은 한도로 거절됐다. 이 지시에 따라 내용 검토·설계 연결·검증 설계·마무리를 계속 진행했다. 앞 단계의 독립 검토 완료 기록을 이번 보고서의 검토로 대신하지 않는다.

| 단계 입력·산출물 | 요청/실제 수행/논리 단계 참조, 실제 소비한 입력 자산·영역/설정·문맥 참조, producer/계약과 확인 수준, 성공/검증 산출물·후속 필수 입력 | K04/K05에서 실행 사실과 검증 자산 확보를 연결. 파일/JSON 존재만으로 성공 checkpoint를 확정하지 않음. 모델 label·파일 hash·단계 비용·발행 출처는 각각 별도 의미. 완료 단계의 원 수행 귀속을 복원 요청에 재부착하지 않음 |
| 글자 배치·합성 | 현재 text/layout 버전, 실제 사용한 폰트 참조/자산 버전·glyph 지원, 배치 box/회전·폰트 크기·줄바꿈·언어/방향·엔진/측정 조건, cleaned layer와 합성 설정 | 서비스/출력은 의도한 text·layout·폰트를 대조하고 화면은 같은 참조를 사용. 실제 엔진의 차이는 측정하여 기록. 최소 폰트 뒤 약간 넘침을 전면 실패로 바꾸거나 글자를 잘라 성공으로 만들지 않음. 폰트 누락·대체와 큰 넘침의 처리 상세는 미정 후보로 남김 |
| snapshot·파일 전달 | K09/K10의 캡처/편집/결과 버전, 필수 자산과 선택 checkpoint, 검증 파일·발행 출처·현재 접근, 다운로드 시도/오류·사용자 확인 참조 | 현재 권한/반영 버전으로 coherent snapshot을 만들고 C08~C10은 그 동일 파일을 대상으로 처리. 파일 생성·브라우저 요청·사용자 확인을 구분. 파일이 제시한 키/ID만으로 발행·creator를 인정하지 않음. 오류/버전 경합은 기존 K10 조건으로 거부·재조회 |

한 공급사가 최종 bitmap만 제공한다면 그것으로 편집 값·원문 제거 layer·검증 가능한 중간 checkpoint까지 확보했다고 인정하지 않는다. 어떤 필수 편집 자산을 따로 만들고 검증할 수 있는지 상세 설계에서 확인해야 한다. 공급사가 내부 단계를 묶어서 수행하면 실제 호출은 한 수행으로 귀속하고, 공개되지 않은 내부 단계를 개별 재개 가능한 checkpoint로 만들어 내지 않는다.

### 13.2 실제 소비 입력에 따른 단계 의존성

아래 공정은 논리적 비교 단위이며 여섯 개 API/worker 채택을 의미하지 않는다. 구현별로 실제 소비 입력을 선언하고 검증할 수 있어야 한다. 의존성을 확인하지 못하면 기존 K05/K12처럼 재사용을 보류한다. 호환성 통과는 현재 실행 권한·원 모델 사용 가능·현재 결과 적용 허가를 대신하지 않는다.

| 논리 공정 | 소비 입력으로 대조할 후보 | 성공 산출물의 의미와 재사용 경계 |
| --- | --- | --- |
| 입력 정규화 | 원본 내용·크기/표시 방향·색 조건, 변환 계약/설정 | 원본을 보존한 파생 자산과 좌표 변환. 동일 파일명·URL만으로 입력 동일성 인정 없음 |
| 검출·OCR | 실제 이미지/crop 참조·기하 변환, 영역/분할·읽기 순서가 입력이면 그 버전, 언어·모델/계약·설정 | 인식 텍스트·영역 대응과 provenance. 번역문이나 폰트 변경만으로 이 입력이 변했다고 가정하지 않음 |
| 번역 | 소비한 원문/영역 집합·읽기 순서, 목표 언어·모델/추론·prompt/계약·설정, 실제 전송한 crop/이미지·문맥 부모가 있으면 그 참조 | 대상 원문과 대응하는 번역. text-only 호출과 이미지/문맥 사용 호출의 의존성을 같은 것으로 취급하지 않음. 문맥의 부모 변경은 실제 사용 범위에 따라 검사 |
| 원문 제거 | 실제 제거 입력 이미지, mask와 좌표 변환·대상 집합, 제거 방식/모델/계약·설정 | cleaned 자산과 변경 범위. 번역문 text를 소비하지 않는 제거 단계라면 번역문 변경만으로 폐기하지 않음. 실제 통합 호출이 함께 소비한 입력은 생략할 수 없음 |
| 식자 | 현재 번역문·수동 줄바꿈/설정, 배치 geometry, 실제 폰트 자산·지원 glyph·언어/방향, 측정/배치 엔진·계약 | text/layout의 배치 결과. 폰트·배치 변경 시 종전 배치를 그대로 재사용하지 않음. background를 fitting에 쓰면 그 자산도 입력 |
| 합성·출력 | 원본/cleaned·text/layout의 대상 버전과 선택 범위, 출력 크기/변환·encoding/색 조건 | 일치하는 입력을 합성한 출력. JPG 변환과 preview의 픽셀 차이를 단계 실패·원본 변경과 혼동하지 않음 |

성공한 한 단계의 내용 재사용은 읽기 참조다. K04/K06/K07의 과거 실제 수행·비용·무료 기록을 다시 실행하거나 차감하는 명령이 아니다. 새 실제 처리가 필요한 단계는 현재 조건과 명시 요청의 계약을 따라야 한다.

관측 결과에는 case ID와 P항목, 실제 입력/수정 조건, 참조한 계약, 실행한 경로, expected/observed, 금지 부작용, 측정 근거와 `PASS/FAIL/BLOCKED/NOT RUN`을 함께 남긴다. 이미지·대사 전문은 승인된 격리 평가 자산에서만 사용하고 일반 운영 로그에는 참조·버전·측정값 위주로 기록한다. 통합 bitmap만 가진 공급사에서는 내부 OCR/제거의 품질을 직접 측정했다고 표시하지 않는다.

## 15. 검토 이후의 선택과 단계

연구 적용 검토 마무리 당시에는 추가 제품 선택이 필요하지 않았고 다음 단계의 Q20~Q22를 안내했다. 현재 전체 구현 전 준비에서는 [Domain Story 59절](../../manga-translation-domain-story.md#59-전체-구현-전-준비의-범위와-질문)과 기존 플랜 9.3절의 Q20~Q28 아홉 선택을 반영하고 후속 상세를 준비한다. 기존 선택을 재질문하지 않는다. 상세 내용과 trade-off의 원본은 [기술 후보 비교](2026-10-03-manga-web-technical-options.md)8절이다.

| 검토 당시 후속 질문의 우선순위 | 15~16절에 초기 Q20 안내의 시점을 명시. 당시 Domain Story 59절·기존 플랜 9절에 따라 Q23~Q25 응답 우선, Q20~Q22 미선택 유지. 이후 실제 선택은 18절 참조 |

최초 두 보완의 반영을 확인받았고 이번 보고서의 독립 검토는 완료됐다. 후속 확인에서 추가 필수 보완은 없었다. 공식 사이트 재조회·원자료 전체 재독·전 이미지 재시각검사·원본 hash/CRC 재계산·Word 페이지 렌더·제품/모델 실행은 이번 독립 검토가 수행한 작업이 아니다. 읽기/보존/검사 기록과 관련 실행 원장·Word 추출 내용의 필요한 부분을 보고서와 대조했다.

이번 검토가 끝나도 전체 구현 전 준비·기술/파일 정책 선택·실제 제공자/품질/원가·저장/브라우저 검증의 완료를 뜻하지 않는다. APV는 모두 NOT RUN이며 최초 한도 실패의 이력과 Word 레이아웃 미검증은 유지한다.

## 18. 연구 검토 이후 실제 선택의 연결

사용자가 Q20-A·Q21-A·Q22-A·Q23-A·Q24-B·Q25-A·Q26-A·Q27-A·Q28-A를 선택했다. 선택과 상세 경계의 단일 원본은 Domain Story 25·59절이고 설계 반영은 구현 전 준비 명세 11절·기술 후보 12절·기존 플랜 9.3절을 따른다. 이 보고서의 초기 추천·당시 미선택 기록을 실제 응답이나 기술 실행의 증거로 바꾸지 않는다.

연구에서 얻은 페이지/영역·좌표·산출물 의존성과 품질 평가 준비는 Postgres+TypeScript 기반의 일반 만화 페이지 묶음 전체 흐름에 연결한다. 앱 계정과 외부 공급사 테스트 계정, 파일 출처와 현재 접근, 라이브러리 30일과 로컬 파일 검증 근거, 기존 비용의 최초 정산과 중복 차감 금지를 계속 구분한다. 실제 모델·OCR/인페인팅·폰트/공정·서명 파일·Auth 제품/호스팅을 이 선택에서 추가 채택하지 않는다.

Torii·Ichigo 연구의 내용·설계 적용 및 해당 독립 검토 완료와, 우리 전체 구현 전 준비·제품 구현/품질·배포 완료는 별개다. S/APV/SEC/FX/AUTHV/FILEV 실행은 계속 **NOT RUN**이다.

후속 Q29-B·Q30-B·Q31-B도 Domain Story 59.6~59.7절에 반영했다. 요청 수명은 [Postgres·TypeScript 상세 초안](2026-10-03-manga-web-postgres-execution-design.md)으로 연결했다. 연구/설계 문서와 실제 지원·품질/DB·파일·브라우저 실행은 별개이며 PGV도 **NOT RUN**이다.
