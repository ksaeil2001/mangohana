# 만화 번역 웹 서비스의 구현 전 준비 명세

작성일: 2026-10-03. 상태: **구현 전 준비 문서 작성 완료 — Q20~Q57의38답·위임 D01~D20의20선정/계약·검증·인계 연결 / 제품 실행 NOT RUN / 신규 범위 독립 검토 미완료**. 최신 판정은12절이다.

**목표:** 사용자가 요청한 구현 전 준비를 서비스 전체에 대해 마친다. 이미 끝낸 Torii·Ichigo 적용 검토와 상태 전이 계약을 보존하고, NotebookLM 강의의 준비 방법을 전체 화면·서비스·저장·운영·검증 명세와 연결한다.

**아키텍처:** 화면의 의도·표시, 업무 규칙과 요청 조정, 권위 저장과 외부 제공자의 책임을 분리하는 설계 제안이다. 논리 책임 분리가 여러 배포 서비스의 강제 분리를 뜻하지 않는다. 기존 Electron의 IPC·`.ctp`·단계별 사용자 승인 흐름을 새 웹 서비스에 그대로 전용하지 않는다.

**기술 스택:** Q20/Q54/Q57와 D01~D20으로 React/Vite/TypeScript·Node24/Fastify5/pg·권위PG18/별도TSworker, Render Singapore 첫상세기준·privateR2/Auth0 우선검증 후보와v1파일/서명·운영정책·별도root의예정인계를정했다. 실제회사계정/사양/월예산·auth/모델/이미지공정/키/파일/PG/삭제의적합성과지원은RSG gate에서확인한다. 정확patch/lockfile·실측한도/가격은활성화전에고정하며현재설치/지출/제품구현승인이아니다.

**기준:** 업무 정책의 단일 원본은 [Domain Story](../../manga-translation-domain-story.md)다. 설계 입력은 [주 설계 초안](2026-10-02-manga-translation-web-service-draft.md), [상태 계약·검증](2026-10-02-manga-web-workspace-contracts.md), [Torii·Ichigo 적용 검토](2026-10-03-torii-ichigo-project-application-review.md)다. 진행 상태는 [기존 플랜 9절](../plans/2026-10-02-manga-web-workspace-contracts-and-validation-plan.md)에 둔다. 이 문서는 정책·진행 원본을 새로 만드는 문서가 아니다.

**작업 경계:** 제품 구현 전까지 조사·질문·설계·구현 인계를 준비한다. 계정 생성, 유료 인프라 구매, 실제 AI/결제 실행, 사용자 자료 업로드, 새 의존성 설치, 배포는 현재 준비 작업의 완료를 위해 실행하지 않는다. 실제답/명시추천위임의설계선정은기록하되계정/지출/제품실행승인으로확대하지않는다.

**검토 초점:** 기존 선택 보존, 수행불명·정산·무료 사용의 독립성, 파일의 편집/재개/현재 접근 분리, 전체 서비스의 빠진 결정, 명세와 실행 증거의 구분. 이전 전체 준비의 architect 신규 호출은 한도로 불가했다. 이후 기존 architect 담당을 다시 호출해 업로드·편집/Undo·ZIP·라이브러리의 공통 계약과 미결정 분기를 독립 검토했다. 그 범위와 반영은 10절을 따른다. G01~G08 전체 상세 설계의 독립 검토는 **미완료**다.

## 1. NotebookLM에서 배운 준비 방법과 근거

기존 노트북의 표시된 전사문 **29개/163,888자**를 모두 직접 확인했다. 정석 7개, 로드맵 6개, 구조 10개, 체계 6개다. 이전에 읽은 네 전사문도 이번 전체 캡처와 대조했다. [읽기·근거 기록](../../../artifacts/manga-web-preimplementation-2026-10-03/learning-evidence.md)과 [검증된 전사문 목록](../../../artifacts/manga-web-preimplementation-2026-10-03/transcript-manifest-verified.json)을 참조한다. 원본 MP4 재생·음성 대조는 수행하지 않았다.

| 직접 확인한 강의 설명 | 원문 | 우리 준비에 적용할 제안 |
| --- | --- | --- |
| 불편함과 목적을 설명하고 AI의 인터뷰로 중요한 미정을 좁힌다. 사용자가 전문 설계서를 직접 쓸 필요는 없다 | 로드맵 part002/005, 체계 part003 | 확정 정책을 다시 묻지 않고, 범위와 행동이 달라지는 결정을 1~3개씩·각 2~3개 선택지로 질문한다 |
| 화면·업무 정책·데이터 접근을 책임별로 나누면 변경 영향과 검증 위치를 이해하기 쉽다 | 정석 Part001/002/003 | 화면의 임시 상태와 서비스 확정 상태, 순수 정책 판정과 부수 효과 조정을 구분한다. 모든 유스케이스를 순수 함수로 강제하지 않는다 |

| 외부 서비스 대역을 쓰면 비용과 외부 한도의 영향을 줄일 수 있지만 대역도 실제 계약과 맞아야 한다 | 구조 part003/004 | fake 제공자 수명주기 검증과 실제 제공자 응답/품질 검증을 분리한다. fake PASS를 번역 품질로 확대하지 않는다 |
| 타입 검사·린트 등의 장치를 두고, 코드에 드러나지 않는 목적과 결정 근거를 남긴다 | 체계 part005, 정석 Part004/005 | 변경에 맞는 검증 명령과 구현 인계 문서를 준비한다. 모든 코드를 다시 문서화하거나 작업마다 새 ledger를 만들지 않는다 |

API와 DB 사이의 반복 왕복은 배포 지역과 응답 시간을 함께 검토할 이유다(체계 part005/006). 정확한 지역·지연 목표는 사용자 대상과 후보 지원을 확인한 뒤 정하며 강의만으로 숫자를 확정하지 않는다.

다음은 채택하지 않는다: Mac 구매/환경 변경, 특정 월요금이면 손실이 없다는 원가 가정, 자동 브라우저 권한으로 민감 접근·약관·결제를 승인하는 해석, 컨텍스트 70%에서의 강제 종료, 통합 테스트 불필요 일반화, 모든 업무 로직의 순수 함수화, 기존 정책을 새 PRD/Glossary로 복제하는 제안. 강사의 도구 취향·사례·직업 조언과 이 서비스의 기술 보장은 다르다.

## 2. 구현 전 완료와 구현 후 검증을 나누는 기준

구현 전 준비 완료는 **선택한 첫 제품 범위에 필요한 정책, 책임, 데이터/API/파일 계약, 검증 기대값, 구현 순서와 미검증 활성화 조건을 연결한 상태**다. 실제 구현이 없는 단계에서 빌드·서비스·AI 품질·파일 복구 PASS를 요구하거나 기록하지 않는다.

남겨도 되는 것은 측정으로 정해야 하는 성능·품질·원가 값과 뒤 단계의 출시 결정이다. 각각 측정 입력, 담당 시점, 통과 기준 결정 방법, 실패 시 행동을 지정해야 한다. 새 비용 실행이나 유료 출시를 좌우하는 상한·가격·권한을 미정인 채 활성화하지 않는다.

## 4. 공통 기술 계약 작성의 입력과 완료 조건

### 4.1 화면과 명령/조회

첫 제품 범위를 선택하면 각 행동에 `의도 → 요청 식별 → service 확인 → 확정 기록 → 화면 갱신`을 작성한다. 로딩은 아직 확정되지 않은 상태이며 timeout을 서비스의 실패 확정으로 표시하지 않는다. 중복 제출 후에는 같은 의도를 조회·대조한다. 이미 C01~C13으로 정한 수명 명령과 새 로그인/업로드/편집/ZIP/라이브러리/구매 행동의 관계를 표로 연결한다.

처리 중 제외·스킵·순서·모델/식자 설정 변경은 Q4의 대사·식자 편집 잠금에서 자동 유추하지 않는다. 허용 범위의 제품 선택을 받은 뒤 캡처된 대상과 이후 요청의 입력을 구분한다. 기본 프로젝트 상태와 `실제 수정`이 되는 행동도 목록으로 명시한다.

### 4.2 권위 저장·실행·시계

선택한 저장소에서 Account/Project/Page/WorkspaceContext/ProcessingRequest/Execution/Checkpoint/Settlement/Snapshot의 실제 schema, uniqueness, CAS/transaction, worker 발행·대조 경계를 작성한다. 이름은 논리 설계 입력이며 모두 별도 microservice나 table이어야 한다는 뜻은 아니다.

서비스가 확정한 시각과 절대 기한을 저장하며 브라우저 clock/timer는 안내·wake-up에만 사용한다. worker 재시작·중복 전달·늦은 응답과 lease/fencing을 실제 런타임에 연결한다. 일시 공급사 제한, 원 계약 불가, 수행불명, 정산 확인 중을 별도 사유로 표현한다. 외부 호출은 DB transaction만으로 정확히 한 번을 보장할 수 없으며 제공자 계약과 확인 경로를 함께 설계한다.

### 4.3 이미지·공정·파일

[연구 적용 P01~P08](2026-10-03-torii-ichigo-project-application-review.md)의 안정된 region ID, 좌표/각도/색의 정규화, 마스크·원본·파생 자산 hash, 단계별 실제 입력 의존성, 폰트/layout와 preview/export 일치를 물리 타입에 연결한다. 모든 변경이 전 단계를 무효화한다는 가정과 자동 앞 단계 재실행을 피한다.

파일은 container·manifest·필수 자산·선택 checkpoint·schema/contract version·원본 순서·설정·누적 출처를 구체화한다. `편집 복원 가능`, `checkpoint 재사용 가능`, `현재 결과에 적용 가능`, `현재 계정 접근 가능`의 판단을 분리한다. 원 파일을 보존하며 파일의 AccountId나 digest만으로 믿는 발행자/현재 권한을 인정하지 않는다. Q21-A/Q22-A에 따라 서비스 서명과 최소 검증 근거 유지의 상세를 작성한다. 키 회전·유출·폐기/접근 소멸의 검증 불명 행동과 지원 범위는 남은 준비 항목이다.

### 4.4 AI·품질·비용

지원 공급사·정확한 모델 ID·Low/Medium/High 대응·필수/선택 단계와 호출 상한을 표로 작성한다. 지원되지 않는 조합을 실행 가능으로 표시하거나 모델을 조용히 대체하지 않는다. 실제 provider 계약이 원 모델 유지/조회/과금 근거를 제공하지 않으면 제한과 보류 경로를 작성한다.

대표 평가 자료의 사용 권한·언어·페이지 형태·해상도·대사량·효과음·읽기 순서·긴 번역문을 정의한다. OCR 인식/누락, 번역 의미/일관성, 배경 손상, 식자/허용 넘침, 결과 파일 일치, 시간·메모리·원가를 별도 평가한다. 현재 연구 fixture 보존 검사를 새 inference 품질로 취급하지 않는다. 수치 목표는 사용자 품질 기대와 첫 실험 결과로 정한다.

C안의 실제 AI 원가, 다른 공정의 측정량 단가, 공통비·수익·PG 실수령 기준을 단위와 근거까지 작성한다. 소수 크레딧의 내부 정밀도와 사용자 표시/차감 반올림, 원가 갱신·예외·새 단계 적용을 분리한다. 유료 단계 전 내부 실행 여력은 사용자 예상치·선차감이 아니다. 무료 운영 비용은 유료 사용자 원가로 이전하지 않는다. 실측 상한·손실 방지 근거 없이 유료 활성화를 허용하지 않는다.

### 9.3 내보내기·원본·라이브러리의 자산 경계

내보내기 manifest는 `ExportRef + 구성/순서 + 각 PageLineage/ResultRevision + 자산/폰트/layout + 렌더 계약 + 검증 산출물`의 대응을 설명해야 한다. 표시 이름/중복 파일명은 내부 참조가 아니며 ZIP entry 이름의 충돌·경로 탈출을 막는다. Q33-A로 처리 중 현재 확정 결과/순서를 한 시점에 캡처하고 후속 변경은 새 캡처로 생성한다. Q36-A로 필수 렌더 실패는 전체 실패/같은 캡처 재시도다. 출력 형식/품질과 캡처 자산의 허용 수명은 미정이다.

원본 불변은 최초 업로드 내용에 수정을 덧씌우지 않는다는 계약이다. 서비스 전체에 원본을 무기한 보관하는 신규 정책이나 계정 라이브러리의 이미지 수명 연장으로 해석하지 않는다. 파일 복원의 필수 자산, 살아 있는 맥락 자산, 라이브러리 보관 버전은 출처·수명·접근 경로를 구분한다.

라이브러리는 **30일 뒤 삭제와 서비스 재다운로드 불가 모두**를 요구한다. 기한부터 권한을 차단하는 것만으로 삭제가 끝났다고 표시하지 않는다. 선택 storage의 결과 객체·버전/복제본·library용 캐시·다운로드 grant·backups·내부 대조 기록 속 이미지 사본까지 삭제/차단 범위를 명세하고 검증한다. 공유 물리 자산이 다른 유효 맥락/사용자 파일에서 온 자산과 혼재하는 경우 출처/참조·삭제 범위를 별도로 확인한다. 라이브러리 만료 자료를 내부 경로로 읽어 새 편집 맥락이나 파일을 만들어 주는 우회는 금지한다.

물리 삭제 지연/실패는 남은 처리·운영 문제로 기록한다. 삭제 요청 접수·queued 상태·일반 URL 거부를 실제 모든 사본 삭제의 증거로 쓰지 않는다. 선택한 서비스가 해당 삭제/접근 계약을 만족할 근거를 확보하지 못하면 이 항목은 미완료다. 내부 수행/비용 기록을 보존하더라도 만료 이미지 제공을 유지하지 않는다. 사용자가 이미 보관한 로컬 파일의 포함 자산은 현재 접근/지원 형식으로 별도 검증하며 서비스가 로컬 복사본을 삭제한다고 약속하지 않는다.

## 10. 공통 계약의 architect 독립 검토와 반영 범위

## 11. 첫 범위·실행 기반·파일·인증 선택의 반영

이 절은 Domain Story 25·59절 선택을 설계에 연결한다. 첫 제품 완료는 지정된 내 내부 테스트 계정의 전체 업로드→자동 처리→수동 수정→ZIP→프로젝트 파일→복원 흐름이다. 라이브러리 등 기존 포함 기능을 유지한다. 실제 크레딧 판매/일반 이용자와 스마트폰 전체 편집, 긴 세로 웹툰 지원은 후속이다. PC·태블릿의 첫 OS/브라우저와 일반 페이지의 첫 언어 조합은 Q29-B/Q30-B로 정했다. Q43-A/Q44-A/Q45-A/Q46-A로 간체·다른 언어7방향·정지 PNG/JPEG 입력·PNG 출력을 정했다. 버전·실기기 확보·수치 한도/실제 적합성은 후속 상세다.

| 선택 | 상세 설계에 연결할 계약 | 남은 구현 전 준비 |
| --- | --- | --- |
| Q20-A Postgres+TypeScript | 요청·실행·무료 사용·정산·계정/권한의 권위 사실은 DB, 별도 실행서버는 발행·대조·재시작 복구 | 물리 schema·조건부 쓰기/트랜잭션·기한 재검사·외부 호출 수행불명 대조. TS/DB 선정이 실제 실행 성공은 아님 |

인증 제공자의 user/identity ID와 앱의 안정된 내부 AccountId를 구분한다. 단순히 같은 이메일 주소이거나 제공자가 identity를 연결했다는 사실만으로 앱 계정·잔액·무료 사용·파일 소유권을 합치는 근거로 사용하지 않는다. 앱 내부 테스트 계정은 외부 AI 공급사 무료 테스트 계정과 다르다. 실제 세션 만료 시간과 워크스페이스의 5분 단절 유예·10분 공급사 대기는 별개다.

Supabase는 조사 후보다. 공식 문서의 같은 이메일 자동 identity 연결 동작과 Q27-A의 명시적 앱 계정 연결이 일치하는지 확인해야 한다. 자동 연결 비활성화 가능 여부, Google로 시작한 계정에 이메일 수단을 추가하는 방향까지 포함한 실제 적합성은 아직 검증하지 않았다. Q20-A는 Supabase Auth 채택이 아니다. 근거는 기술 후보 12절과 [이번 선택의 공식 문서 기록](../../../artifacts/manga-web-preimplementation-2026-10-03/decisions-q23-q25/official-auth-evidence.md)에 둔다.

Q29-B·Q30-B·Q31-B를 실제 응답으로 반영했다. 정확한 선택지와 적용 범위는 Domain Story 59.6~59.7절을 따른다. Q31은 OB01의 파일별 검증 실패이며 OB02의 초기 순서·삽입·명시적 중복과 묶음 전체 한도 초과는 별도다. 추천값을 답으로 취급하지 않는다.

Q40~Q42 반영/업로드 상세와 다음 질문의 architect 재호출은 `agent thread limit reached`로 불가했다. 이전 사용자 지시대로 메인 검증을 이어가며 그 시점 이 추가 범위의 독립 검토를 미완료로 기록했다. 이후 새 architect의 Q40~Q51 검토/지적 재확인 종결은11.18절을 따른다. 앞선20선택/편집·출력·파일 초안의 지적 반영 후 독립 검토 종결과 구분하고 다른 모델로 조용히 대체하지 않는다.

Q43-A/Q44-A/Q45-A를 실제 답변으로 반영했다. 간체부터·같은 언어 자동 처리 제외·정지 PNG/JPEG 입력이며 원본은 Domain Story3.1·7·59.16절이다. 첫 자료별 공정/모델·파일/브라우저 적합성과 수치/품질 PASS는 후속 검증이다.

### 11.14 첫 지원·출력·복구/해제와 인증 상세 연결

Q48 반영 당시 Q20~Q48 스물아홉 선택을 반영했다. Q46-A로 PNG ZIP, Q47-A로 모든 수단/앱 로그인 상실 시 원 provider 계정 복구, Q48-A로 남길 수단 재인증 뒤 명시 제거·마지막 수단 보호·관련 앱 세션 철회를 연결했다. 파일 소지/동일 email로 계정 이전·무료 원장 재생을 허용하지 않는다. PNG 출력은 JPEG 원본 bytes를 덮어쓰거나 원래 손실을 복구했다는 뜻이 아니다.

[인증·세션 상세 초안](2026-10-03-manga-web-auth-session-design.md)에 AuthAttempt/VerifiedAuthEvidence/LoginBinding/AppSession 후보, Google의 auth_time/nonce와 OTP 직접 교환의 다른 근거, 목적별 한 번 소비·앱7일 상한·명시 연결·동시 제거/철회와 ASV01~ASV10을 작성했다. Auth0 fresh 교환이 Google 비밀번호 재입력을 보장하지 않고 Sessions API/refresh 철회가 앱 접근 차단을 대신하지 않는 공식 한계를 반영했다. 새 초안/업로드·처리 중 설계의 독립 문서 검토는 이후 Q40~Q51 지적 재확인으로 종결했다(11.18절). 실제 인증/파일/제품·전체 준비 검증과 구분한다.

SOV01 첫 언어7방향은 언어별 OCR/이름·말투/뜻/폰트·줄바꿈/글자 넘침·원문 제거와 페이지/영역 재번역까지 같은 평가 자료에 연결한다. SOV02 같은 언어/번체/미지원 조합의 안내와 AI 요청 차단은 UI와 서비스 둘 다 검증하고 거부 단계에서 호출/무료 사용을 만들지 않는다. EOV20/21은 정지 PNG/JPEG의 실제 내용·애니메이션/손상/위장 파일과 모든 ZIP entry의 PNG·캡처/원본 대응을 확인한다. fixture 분포/기준 수치·데이터 사용/처리 범위는 후속이며 모두 NOT RUN이다.

Q52-B로 선택한 모든 앱 session logout의 파일/종료/proof 상세·외부 철회 감지·코드 제한/현 계정 proof 강도·내부 계정 bootstrap·Q49~Q51 처리 중 행동의 DB/HTTP/화면 검증·공정/모델/품질/원가·host/storage/파일/키·운영 수치·전체 상세 인계가 남았다. 제품 구현/계정 생성/설정/지출 없이 준비를 이어간다.

### 11.15 실제 처리 중 행동 질문과 미선택 경계

Q49-A·Q50-B·Q51-A를 선택했다. 새 업로드/제외·스킵·순서는 활성 요청 종결 확인까지 잠그고 미래 요청 설정은 변경한다. CF01/05/06과 상세 초안11절/EOV22~24에 현재 권한/서비스 사실·동시 요청 접수/설정 변경/구성 확정·같은 명령 재전송을 연결했다. 기존 페이지 수동 잠금과 다른 페이지 허용 편집/보기/ZIP, 원 캡처/비용/수명 보호를 유지한다. 제품 실행은 NOT RUN이다.

### 11.16 처리 중 명령의 현재 검사와 검증 경계

Q51 반영 당시 Q20~Q51 서른두 선택을 반영했다. 같은 맥락의 request/batch 접수·종결, 업로드 반영/구성 명령·설정 변경을 동시 DB-only 검증 경계로 연결한다. 일괄의 페이지 교대 중 잠깐 비어 보이는 투영이나 오래된 busy boolean을 종결 근거로 쓰지 않는다. 같은 성공 명령의 조회와 새 의도의 mutation을 구분한다. 상태 확인/거부/설정 변경이 비용·무료·workspace/provider clock을 초기화하지 않는다. 실제 DB schema/HTTP/화면·기기/worker 경합 검증은 후속이다.

### 11.17 화면/API 기반과 첫 검증 흐름의 선정 상세 기준

[기술 후보16절](2026-10-03-manga-web-technical-options.md#16-첫-화면api-기반의-비교와-선정-상세-기준)의 React/Vite 별도 API 또는 Next Node web/API를 상세 설계 기준으로 비교했다. Q54-A로 React/Vite/TypeScript 화면+Node API를 첫 상세 설계 기준으로 선택했고 PG/별도 worker·Auth/원 수행/기한/수행불명·정산 guard는 같은 전제다. 로그인→원본 업로드→한 페이지 자동 처리/편집·ZIP/library→서명 파일/보관 확인→새 맥락 복원의 기준 흐름으로 FAV01~04를 잇는다. 실제 첫 구현/기기/배포·세션/자산/cache 적합성은 NOT RUN이다. Q53-A의 계정 전체 한 live context·Q52-B의 현재/모든 앱 logout은 별도 실제 선택으로 반영하며 화면 framework로 조용히 정한 정책이 아니다.

### 11.18 Q40~Q51 최신 독립 문서 검토의 종결과 다음 질문

새 architect가 Q40~Q51 반영·신규 인증·세션 및 업로드/처리 중 명령 설계를 읽기 전용으로 확인했다. 이미 선택된 행동/복구를 미정으로 읽게 한 표현과 과거29선택의 현재 표기 두 정합성 항목을 수정했고 후속 원문 재확인에서 종결 가능/추가 필수 수정 없음으로 확인했다. [검토 기록](../../../artifacts/manga-web-preimplementation-2026-10-03/decisions-q23-q25/architect-q40-q51-review.md)에 지정 범위와 공식 출처 재조회/제품 실행의 한계를 남긴다. 이전 호출 실패는 그 당시 기록이며 이번 실제 종결과 구분한다.

Q52-B/Q53-A/Q54-A를 실제 응답으로 반영했다. Q54 반영 당시35선택이며 새 범위 반영의 독립 확인은 후속이다. 검토 종결 자체를 사용자 채택으로 처리한 것이 아니다. logout의 진행 요청/파일/종료 절차 결합, 단일 맥락에서 기존 작업 자동 폐기 금지와 종료/파일 확인, 선택 기반 적합성·환경/수치·전체 G01~G08 인계는 후속이다. 실제 제품/ASV/EOV/FAV 실행은 NOT RUN이다.

### 11.19 현재/모든 앱 세션·계정 전체 한 맥락·선정 화면/API 기준

Q52-B의 두 logout 범위는 AppSession/내부 AccountId로 판정한다. Q48 제거 binding 관련 철회와 일반 모든 앱 세션 철회를 구분하며 provider logout/refresh 철회와 같은 성공 의미로 합치지 않는다. Q55-A의 정상 저장/보관 확인 뒤 현재logout, Q56-B의 연결 수단 접근 재증명/손실 명시 확인 뒤 파일 대기 없는 전체 session·현재 맥락 종료를 선택했다. proof/철회·발행 경합의 실제 기술/인수는 후속이다.

Q53-A의 첫 제약은 기기/로그인 수단별이 아니라 안정된 내부 AccountId 전체에서 한 live context다. 같은 맥락 여러 탭의 Q15 explicit owner 인계는 허용한다. 현재 alive/exit/disconnect grace와 종료/만료 확정·원 수행/정산 hold는 별개이며 기존 맥락을 파일 확인 없이 자동 폐기하거나 새 맥락으로 원 요청을 옮기지 않는다. 후보 AccountLiveContextSlot/current state의 동시 새 프로젝트/파일 열기·종결/5분 만료 대조를 PG8.4·ASV12로 검증한다. actual schema/TTL/host/worker 실험은 NOT RUN이다.

Q54-A의 상세 기준은 browser React/Vite/TypeScript→Node API→Postgres/별도 TSworker다. browser는 상태/명령·이미지 편집/파일 전달을 소유하고 API는 secret/auth/현재 계정·owner/명령 validation/DB를, worker는 기존 실행·수행불명/정산/기한 guard를 소유한다. 같은 app origin의 static/API/auth 경로는 배포 후보이며 특정 host/설치·CORS/CSRF/cookie/버전을 확정하지 않았다. FAV01~04와 API가 현재 권한을 재검사하는 first full flow를 구현 인계로 연결한다. 기존 Electron `.ctp`/IPC/제품 코드의 변경 승인은 아니다.

### 11.20 문서 기록 지시·추가 검토 한계·호스팅 근거

사용자 지시에 따라 새 결정/근거·진행/미검증·실제 질문/응답은 프로젝트 문서에 기록하고 별도 메모리에 저장하지 않는다. 기록 주체/원본은 기존 플랜9.9절을 따른다. Q52~Q54 추가 범위는 기존/새 architect 모두 호출 한도로 접수되지 않아 독립 검토 미완료이며, Q40~Q51의 완료된 지정 범위와 구분한다. 메인의 선택 원문/서비스·저장 대조와 문서 검사는 독립 검토를 대신한 PASS가 아니다.

[호스팅 공식 후보/책임 비교](../../../artifacts/manga-web-preimplementation-2026-10-03/decisions-q23-q25/hosting-primary-comparison.md)를 G02/G05/G07의 근거로 연결한다. Render 작은 compute 합계·Railway 최소 구독/실사용과 unmanaged PG·직접 VPS의 OS/앱/데이터 책임을 구분한다. HOV01~04는 재가동 뒤 원 시계·외부 수행불명/중복 방지·객체/복구 보존의 실제 삭제·자료별 자원/전체 견적의 검증 설계이며 모두 NOT RUN이다. Q57-A로 운영 플랫폼을 먼저 비교하며 회사·지역/사양·월예산·계정/지출은 별도다. logout의 파일/현재 맥락/새 proof 방향은 Q55-A/Q56-B로 선택하고 실제 계약/인수에 연결한다.

### 11.21 Q55~Q57 추천안 수락과 이후 설계 위임

사용자가 남은 질문은 추천대로 진행하고 어떤 답을 했는지 모두 문서화하라고 명시했다. 실제 질문 Q55-A/Q56-B/Q57-A를 반영해 현재38선택/실제 미응답 없음이다. 직접 응답 원본과 선택/위임 경계는 Domain Story59.20~21이며 [질문 전문/추천 대응](../../../artifacts/manga-web-preimplementation-2026-10-03/decisions-q23-q25/questions-q55-q57.json)을 보존했다. 이후 설계 선정은 추천 이유·대안/영향·미검증/활성화 조건을 문서에 남기며 매번 같은 승인을 다시 묻지 않는다.

Q55-A의 current session logout은 해당 session이 owner인 맥락의 C02~C04 저장 종료/최신 file·보관 확인 뒤 app revocation이다. 다른 session owner의 작업은 current-only logout으로 폐기하지 않으며 동일 session 보기 탭은 owner 탭/명시 인계를 안내한다. Q56-B는 목적별 CONFIRM_ALL_LOGOUT/현재 active binding 증명과 손실 명시 확인 후 file을 기다리지 않는 별도 보안 종료다. 전체 session 철회/live 맥락 종료와 원 요청·불명·정산 사실을 분리하고 새 비용 단계 허가를 막는다. PGV18~20/ASV13~16은 실제 DB/외부 발행/종결/접근 race를 검증할 설계이며 NOT RUN이다.

Q57-A의 운영 플랫폼 비교에서 관리형 PG 책임·공유 객체 저장과 데이터 보존/실제 삭제 적합성을 따로 확인한다. HOV01~04와 전체 자원/예산·AI 품질/원가·실제 host/키/파일/인증 상세 인계는 계속 준비한다. Q52 이후 독립 architect 호출 한도·검토 미완료와 모든 제품 실행 NOT RUN을 유지한다. 추천안 수락은 계정 생성/지출/제품 구현·배포 승인이 아니다.

### 11.22 남은 추천 선정과 구체 인계의 연결

[추천 선정/구현 인계 상세](2026-10-03-manga-web-recommended-selections-and-handoff.md) D01~D15에 이후 위임으로 고른답/이유·대안/조건을 기록했다. 직접 사용자 답의38선택과 후속15상세선정을 분리한다. Node24/Fastify/pg·Render/PG18 상세기준·privateR2 검증후보, 목적별proof·파일형식/서명·평문/키, 캡처/저장재시도/만료전달/운영기록, 모델·공정/폰트·21자료계획과 유료활성화 경계를 연결했다. 숫자초기정책과 실측한도/전체원가/기기지원PASS는 구분한다.
