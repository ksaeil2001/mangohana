# Trio 현재 코드와 기존 실행 근거

**현재 Trio 웹에는 입력·검수·저장·복구·계정 관리 코드와 부분적인 실제 이미지 처리 구현이 있지만, 일반 운영 진입점은 차단되어 있습니다.** Electron의 문맥 번역·Production OCR·인페인팅·`.ctp` 기능은 별도 제품의 기존 기능이며, 웹에 연결된 기능으로 합산할 수 없습니다.

이번 작업은 **읽기 전용 원인 분석**입니다. 파일 수정, 테스트·앱·모델·제품 API 실행, 설치, commit/push는 하지 않았습니다. 두 저장소와 아래 기존 실행 기록을 읽는 데 권한 오류는 없었습니다.

상태 표시는 다음 의미로 사용했습니다.

| 표시 | 판단 기준 |
|---|---|
| 구현존재 | 실제 처리 본문과 관련 검증 코드가 존재함 |
| 일부연결 | 합성 환경, 주입한 adapter, 제한된 실행 또는 특정 단계에서 연결됨 |
| 일반운영미연결 | 일반 API/worker 시작 경로에서 조립·활성화되지 않음 |
| 기존실행 | 저장된 과거 실행 결과를 이번 조사에서 읽어 확인함 |
| 미검증 | 현재 환경의 실행 성공, 전체 자동 처리 또는 새로운 이미지 품질을 확인하지 않음 |

**일반 운영 차단은 다음 순서로 구분해야 합니다.**

1. **현재 첫 차단은 API·worker 공통 활성화 검사입니다.** `inspectRuntimeConfig()`는 구현·비용·호스트 검증 누락 조건을 항상 추가하고 `ready:false`를 반환합니다. `requireRuntimeActivation()`이 `RUNTIME_ACTIVATION_UNCONFIRMED`로 중단하므로 설정의 검증 플래그만 켜서 운영할 수 없습니다.  
   근거: [runtime-config.ts:69](C:/Users/ksaei/Documents/Codex/trio-manga-web/packages/operations/src/runtime-config.ts:69) — `inspectRuntimeConfig`, `requireRuntimeActivation`; [runtime-config.test.ts:41](C:/Users/ksaei/Documents/Codex/trio-manga-web/tests/domain/runtime-config.test.ts:41).

2. **worker에는 활성화 검사 이후에도 운영 조립이 없습니다.** `startOperationalWorker()`는 검사 뒤 `RUNTIME_PIPELINE_UNIMPLEMENTED`를 던집니다. 한편 `OperationalPipelineProvider.dispatch()`에는 OCR·번역·LaMa 복원·식자 분기가 실제 존재합니다. 따라서 현재 상태는 **처리 클래스 구현 존재 / 일반 worker 조립 미연결**입니다.

3. **API에도 다음 연결 누락이 있습니다.** `startOperationalApi()`가 만드는 options에는 `apiNative`가 없지만, `FileService`는 `MEASURED` profile에서 native 처리 경계를 요구합니다. worker 실행도 `executionLimit`, native gateway, 입력·결과 검증, `beforeValidateInput` hook을 요구하는데 일반 시작 정책에는 실행 한도 주입이 없습니다. 이는 **코드상 후속 차단**이며 이번에 실행해 관찰한 오류는 아닙니다.
