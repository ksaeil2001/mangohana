# Trio 웹 검증 하네스

상태: 승인된 하네스 실행기 보강과 후속 수정의 선정 검사가 통과했다. 직접 회귀 20개와 실제 Chrome 흐름 1개는 관련 소스가 바뀌지 않아 기존 유효 증거를 재사용한다. PG 날짜 fixture 수정 후 17개와 한국어 평가 계획 회귀 9개, 최종 타입 검사가 통과했다. 번역 제품의 품질은 별도 미검증이다. 작업 흐름은 제공되는 Superpowers 스킬과 프로젝트의 기존 검사를 재사용한다.

이 문서는 성공 기준을 먼저 정하고, 그 기준을 확인하는 검사를 선택하기 위한 기준이다. 현재 진행 상태와 승인 기록은 [source-reference.json](source-reference.json)이 가리키는 기존 플랜에만 남긴다. 제품 계약과 기존 완료·중단 조건은 이 문서로 바꾸지 않는다.

## 하네스의 공통 성공 기준

| 기준 | 확인 방법 | 합격 조건 |
| --- | --- | --- |
| 다음 작업이 하나로 정해짐 | 아래 다음 작업과 완료 조건을 사람이 읽어 확인 | 기존 진행 기록과 연결되고, 조사·변경 범위와 산출물이 명확함 |
| 완료 조건마다 확인 방법이 있음 | 아래 증거 수준·검증 선택표 확인 | 자동 검사, 실제 웹 실행, 사람의 이미지 검토를 구분함 |
| 실패와 증거 부족을 성공으로 처리하지 않음 | 변경별 실패 재현·회귀 검사와 완료 전 근거 대조 | 실패·미실행·필수 증거 누락이면 완료 보류, 관련 소스 변경 후 기존 통과를 재사용하지 않음 |
| 합성 성공을 제품 완료로 올리지 않음 | 실행 기록과 제품 인수 조건 대조 | 선택 검사 통과만 기록하고 제품 품질은 별도 미검증으로 남김 |
| 기존 작업과 근거를 보존함 | 변경 전후 파일 비교와 독립 검토 | 명시한 변경 파일·범위 외 기존 코드와 데이터·과거 검증 기록 보존, 영상의 확인·미확인 범위 표시 |

작업을 시작할 때 목표, 입력과 기대 결과, 허용 변경 파일, 완료 조건, 각 조건의 확인 방법을 먼저 짧게 적는다. 작은 작업은 대화에 적어도 된다. 긴 작업은 기존 플랜을 재사용한다. 선택한 검사 목록과 선택 이유는 작업 기록에 명시한다. 검사 범위를 줄여 기존 인수 조건을 우회하지 않는다.

| H03 | 실패가 성공으로 처리되지 않음 | 폴더 준비 실패·child 시작 오류·child exit 7·실제 임시 파일 쓰기 실패/충돌·정리 실패를 직접 주입. exit 0이나 성공 판정으로 바꾸지 않고 종료 코드와 실패 이유를 보존 |
| H04 | 이번 실행기가 소유한 임시 PG의 정리 경계가 확인됨 | 폴더 준비 실패는 PG 시작 전 중단. PG helper 정상 반환 직후부터 child·검사 실패에도 stop 실행. stop 성공 뒤에만 기록하며 정리 실패는 예외로 실패. 준비된 격리 runtime의 정상 종료도 별도 확인 |
| H05 | 검증 범위와 기존 작업을 보존함 | 허용 범위 외 bytes·설정 보존. 합성 제공자 검사·실제 제품 웹 처리·새 이미지 무보정·사람 품질 검토를 구분. 미실행 필수 확인은 `NOT RUN`/`BLOCKED`로 남기고 전체 완료로 올리지 않음 |

### 두 실행기의 구현 동작

1. PG와 browser 모두 매 실행 OS 임시 폴더에 새 증거 디렉터리를 PG 시작 전에 준비한다. 준비 실패는 PG 시작 전에 실패한다. Browser build도 PG 시작 전에 실행하며 실패하면 PG를 시작하지 않는다.
2. `startIsolatedPostgres`가 정상 반환하면 즉시 `try/finally` 정리 경계에 들어간다. 반환 후의 준비·로그·자식 검사 실행은 이 경계 안에서 수행한다.
3. 자식 실행이 종료하면 `finally`에서 이번 실행기가 소유한 PG의 stop을 실행한다. child 오류·정리 오류는 예외로 실패하며 기록 단계로 진행하지 않는다.
4. PG stop이 성공한 다음 새 증거 디렉터리의 `environment.json`을 `flag: 'wx'`로 저장한다. 기존 파일 충돌·쓰기 오류는 예외로 실패하며 성공한 `environment.json` 기록을 만들지 않는다. 기존 `docs/validation/postgres-environment.json`은 전혀 수정하지 않는다.
5. 기록까지 성공한 마지막 단계에서 자식의 종료 코드를 `process.exitCode`에 설정한다. child exit 7은 정리 성공 뒤 `exitCode: 7`로 기록하고 그대로 exit 7로 끝난다. 이를 검사 성공으로 처리하지 않는다.

정리 보장의 시작점은 PG helper가 **정상 반환한 직후**다. helper 내부의 부분 startup failure와 OS 강제종료는 이번 보장 범위 밖이다. 직접 회귀의 합성 PG/child fixture는 실제 PG 정리 확인을 대신하지 않는다.

## 번역 제품의 완료 조건

**새 만화를 수동 보정 없이 실제 웹에서 업로드부터 최종 다운로드까지 처리하고, 최종 이미지의 품질 검토를 통과해야 제품 완료다.** 자동 테스트 통과는 그중 일부 증거다.

| 조건 | 필요한 증거 | 합성 검사만으로 합격 가능한가? |
| --- | --- | --- |
| OCR 텍스트·좌표·읽기 순서 | 원본과 기대 결과, 실제 인식 결과의 대조 | 아니요. fixture는 계약과 오류 검출 범위만 확인 |
| 번역 의미·문맥·누락 | 원문/번역 대조, 호칭·어투·용어의 사람 검토 | 아니요 |
| 원문 제거·그림과 프레임 보존 | 원본/마스크/제거 결과의 전체 페이지와 확대 비교 | 아니요. 한 영역의 성공과 전체 합격을 분리 |
| 식자 가독성 | 글자 넘침·겹침 검사와 크기·줄바꿈의 사람 검토 | 아니요 |
| 웹 처리·저장·취소·복구·다운로드 | 실제 제품 경로의 실행, 저장 파일 재열기, 원본 보존 | 합성 UI 회귀는 가능하지만 운영 제공자 연결은 별도 |
| 새로운 이미지 적용 | 기존 평가 세트와 별도 새 이미지, 동일 설정, 무보정 결과 | 아니요 |

원본 SHA-256, 코드와 모델/폰트/설정 버전, 수동 수정 여부, 단계별 산출물, 시간·비용의 실측/미측정, 검토자와 판정을 남긴다. 평가 전에 OCR 허용 오차·그림 보존 영역·글자 넘침과 가독성 기준을 정한다. 기존 평가 계획과 계약을 재사용하며, 결과를 본 다음 합격 기준을 낮추지 않는다. 미측정 값은 0으로 바꾸지 않는다.

## 전체 비교의 목표와 사용자 선택 전 완료 조건

**당근망가 번역기의 고정 커밋에 공개된 저장소 전체를 조사하고 현재 Trio와 비교하여, 사용자가 유지하거나 바꿀 부분을 선택할 수 있는 근거와 보고서를 제공한다. 사용자 선택을 반영해 단계별 구현·검증으로 제품을 완성하는 것이 최종 목표다.**

이번 단계는 원인 분석·비교·설계 자료 작성까지다. 작은 말풍선의 줄바꿈 등 기존 문제는 전체 비교의 개별 항목으로 포함하며 다음 구현 대상으로 미리 확정하지 않는다. 기존 REA 기록과 플랜은 재사용하고, 공개 코드로 확인할 수 있는 부분은 소스 분석을 우선한다. 과거 플랜 10.121의 좁은 다음 작업보다 현재 사용자의 전체 비교 요청이 우선한다.

| ID | 사용자 선택 전 완료 조건 | 확인 방법과 필요한 산출물 |
| --- | --- | --- |
| C01 | 분석 기준과 전체 범위를 고정함 | Carrot의 커밋 SHA·라이선스·추적 파일 목록과 분류, 파일별 검토 상태·보고서 연결을 남긴다. 목록 작성만으로 전체 검토 완료를 선언하지 않고 미검토 이유와 비교 한계를 적는다. 구현·테스트·설정·문서·빌드·외부 모델 및 자산을 구분하고 제외·미확인 범위와 이유를 적는다. Trio는 웹과 Electron을 구분해 현재 파일 해시와 관련 테스트를 기록한다. |
| C02 | 모든 제품 단계와 주요 기능을 현재 코드로 비교함 | 입력·전처리·탐지·OCR·읽기 순서·문맥·번역·마스크·원문 제거·식자·검수·저장·출력·취소·실패·재개·복구와 설정·모델 관리·보안·성능·비용을 빠짐없이 매핑한다. 실제 코드 경로·입출력·처리 방식·관련 테스트와 연결 여부를 적고 공개되지 않은 모델/API 내부는 미확인으로 남긴다. |
| C03 | 사용자가 기능별 유지·변경을 선택할 수 있음 | 두 제품의 현재 동작·차이·장단점, 유지/개선/교체/신규/보류 선택지, 추천 이유, 변경 영향·위험·선행 조건·검증 방법을 쉬운 한국어로 제시한다. 추천과 사용자 확정 선택은 별도 칸에 기록하고 모든 선택은 사용자 결정 전까지 미선택이다. |
| C04 | 품질 주장과 재사용 조건의 근거·한계를 표시함 | 코드 확인·기존 실행 근거·이번 실행·추정·미검증을 구분한다. 동일 입력·설정의 전후 비교와 별도 새 이미지 무보정 검증 계획을 제시하며 미실행은 NOT RUN, 실측하지 않은 비용·속도는 미측정으로 적는다. GPL·개별 모델/폰트/의존성 조건과 직접 재사용/독립 구현 판단에 필요한 결정을 분리한다. |
| C05 | 선택 전 변경 경계와 독립 검토를 충족함 | 제품 코드·테스트·스키마·의존성·설정·모델·원본 및 과거 증거를 변경하지 않는다. architect 검토 결과를 반영하고 분석 전후 소스 무변경을 확인한다. 비교 자료가 준비되면 사용자 선택을 기다리며 선택되지 않은 후보를 구현하지 않는다. |

허용 변경은 이 하네스 문서, 웹의 `docs/validation/` 비교·근거 보고서, 기존 활성 플랜의 추가 기록이다. 별도 진행 원장을 만들지 않는다. 이번 문서 검증은 내용·로컬 참조·범위·수정 전후 보존 확인으로 수행한다. 제품·모델·테스트 실행, OCR·번역 등 제품 처리용 외부 API 호출(무료·유료 포함), 설치·commit/push/배포는 이번 분석에 포함하지 않는다. 테스트는 소스와 기존 실행 기록만 검토하며 이번 실행 결과로 표현하지 않는다. 공개 소스와 공식 라이선스 자료 조회는 분석 범위에 포함한다.

## 실행·증거의 보호 경계

- 문서와 스킬은 에이전트의 작업 규칙이며 모든 우회 경로를 막는 실행 장치가 아니다. 기존 검사 실패는 종료 코드로 확인한다. 필수 검사·실제 품질 증거가 없으면 완료로 보고하지 않는다. Git/CI가 없는 현재 상태에서 커밋·병합·배포 차단을 주장하지 않는다.
- 같은 소스와 유효한 환경의 검사 결과를 재사용할 때 검사 범위를 함께 확인한다. 관련 소스·설정·환경이 바뀌었거나 근거가 부족하면 다시 검증한다. 이전 검사와 현재 소스를 연결하지 못하면 통과 근거로 쓰지 않는다.
- 로컬 검사도 쓰기 위치·실제 서비스 접근 여부를 먼저 확인한다. 이번 보강의 구현 동작은 위 실행 순서와 같으며, 두 실행기의 기록은 매 실행 새 OS 임시 폴더의 `environment.json`에 분리한다. 기존 `docs/validation/postgres-environment.json`은 읽기 전용 보존 대상이다. 브라우저의 `dist/web` build는 PG 시작 전에 수행한다. 위 회귀와 실제 격리 실행으로 확인한 범위만 완료 근거로 사용한다.
- 실제 키·운영 DB/설정·외부 모델을 합성 테스트에 섞지 않는다. 기존 실행기의 환경 상속과 자료 접근 범위를 확인한다. 고정 `realProviderCalls: 0`·`actualProviderCalls: 0`은 선언이며 외부 호출을 관측한 값이 아니다. 스킬 적용이나 이번 실행기 보강을 네트워크 차단·실제 credential 접근 차단·외부 호출 0회의 증명으로 표현하지 않는다.
- 실패·취소·중단·프로세스 정리 미확인은 그대로 기록한다. 강제 종료된 실행이나 출력이 없는 검사를 성공으로 바꾸지 않는다.
